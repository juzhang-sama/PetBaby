## 2. 产品方向与不可降级原则

### 2.1 主线优先级

严格优先级保持不变：

1. 真实宠物照片生成与身份还原；
2. 真实宠物体型保真和角色级动作适配；
3. 呼吸、眨眼、耳动、尾动、伸展和用户打断的自然程度；
4. 身体完全离屏、只保留独立动态尾巴的边缘藏身；
5. 领养猫与内容扩展。

标准猫只是公共技术基准，不代表真实宠物照片生成已经成立。至少一只真实照片分身和第二种体型完成交叉回归以前，不得宣称“已支持真实宠物生成”或开始六只领养猫批量制作。

### 2.2 照片分身方向校准

- 继续采用 **A：动画电影软萌风**，不改为写实照片风格。
- 上传入口允许一次提交一张或多张照片，最低一张；上传前一次性告知第三方 AI 和资料不足补全规则。
- 用户开始生成后不插入中途确认；完整动态角色和自动质量检查完成后统一预览。
- 最终预览允许接受安装、重新生成或输入简短局部修改；局部修改必须锁定未要求改变的身份特征。
- 身份外观只允许来自用户资料和 AI 补全，并记录 `user` / `ai-completed`；标准模块负责动作结构和非身份性视觉规则，不能把标准猫身份外观带入用户宠物。
- 资料不足时由 AI 补全身体、尾巴、遮挡区域和动作所需素材；不得静默把所有宠物套成均衡型。
- 每个可重试生成步骤最多尝试三次总计；最终失败直接报错，不得用标准猫或静态图片替代。
- 原始照片在用户接受、放弃、取消或会话终止后删除；正式产品只使用有明确保存期限和删除能力的供应商。
- 关闭主界面后销毁创建 WebView，宠物和托盘继续运行；云端任务可继续，重新打开主界面后轻量恢复，不发送系统通知。
- 常驻内存目标 `<= 120 MB`；release 实测超过 `180 MB` 不得放行。

### 2.3 质量工作方式

- 不允许“鲁莽地一直向前走”。每个视觉阶段都要回看中性、峰值和回退状态是否合格。
- 自动化测试通过不等于视觉通过；Cubism 编辑器、真实 Live2D renderer 和证据截图都属于验收面。
- 发现切片偏移、白线、透明破洞、错误形变或脸部错位时必须停下修正，不能在错误基础上继续绑定。
- 不为赶进度复制同一 `.moc3` 伪造不同体型，不用整只猫等比缩放冒充独立形体模块。
- 当前闭眼美术只达到“功能门槛暂时通过”，不能在文档中写成最终美术完成。

### 2.4 Krita 与 Cubism 同步原则

本轮已确认一个关键问题：Cubism 曾继续使用旧的、错位的素材，而 Krita 中已有较健康的版本。用户明确要求：

- Krita 的健康分层稿是视觉内容依据；
- Cubism 必须同步到该健康稿，不能让两边长期分叉；
- 不仅眼睛，身体、胸腹、前腿和尾根切片也必须同步检查；
- Cubism 中出现的明显白色分割线不是“正常现象”，必须区分编辑器选区线和真实透明接缝，并用运行时证据验证。

Task 3 已基于同步后的健康源完成三体型导出。未来若再次改美术，必须从下文列出的可逆源文件继续，并重新导出、更新哈希和重录受影响证据。

## 4. 本轮视觉返工的关键结论

### 4.1 闭眼素材

- 为改善原先生硬闭眼，曾生成和导入新的闭眼眼部素材，并在 Krita 中反复处理。
- 用户指出“闭眼缝”和“闭眼上方灰黑残留”是两个不同区域；后续严禁把上方阴影问题误当成闭眼缝并继续擦改。
- 当前闭眼已经通过 Task 8 功能门槛，但上方灰黑阴影仍不够自然。
- 用户决定暂时接受并推进，后续再做美术优化。
- 后续优化必须从可逆 Krita 工作稿继续，绝不能破坏当前闭眼缝和已经通过的开闭眼绑定。

### 4.2 胸腹切片与白线

- Cubism 中胸腹、身体和腿部曾有明显错位与白色切片线。
- 这些问题被判定为真实素材/切片问题，不能当作正常编辑器显示忽略。
- 已从 Krita 健康稿重新同步并返工胸腹遮挡保护。
- 圆润型中性状态、呼吸峰值和伸展峰值曾暴露外侧白线；已分别修正中性关键形和伸展关键形并重新导出。
- Task 3 最终运行时证据中，圆润型胸腹外缘已连续。

### 4.3 耳动安全幅度

- 早期较大耳动幅度会在眼睛上方暴露白色弧线，根因是耳部切片下缘在较大形变下露出。
- 当前三体型耳动批准幅度统一收敛为 `-0.15…0.15`，运行时证据无白弧。
- 这不是永久宣称“大幅耳动已解决”。未来若要扩大耳动幅度，必须重新制作更完整的耳根/头部遮挡切片并重录证据，不能直接调大参数。

### 4.4 可复用性判断

本轮三体型工作具有复用性，但复用边界必须准确：

- 可复用的是三份已绑定形体模板、统一动作语义、动作空间档案、批准幅度、哈希合同和验证脚本；
- 正式产品中不应要求每位用户手工经历本轮 Krita/Cubism 流程；
- 未来照片分析器应选择白名单体型模块，builder 只读复制已绑定模板并生成角色级外观/纹理与 v5 档案；
- 体型不确定时不得静默回退均衡型，应要求补图或返回低置信状态；
- 上述自动照片分析与 builder 尚未实现，属于新计划 Task 6–8。
