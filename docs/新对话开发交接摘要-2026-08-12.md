# PetBaby 新对话开发交接摘要（2026-08-12）

> 用途：把本轮长对话的开发背景、当前代码事实、动态效果设计与后续边界带入新的 Codex 对话。新对话应先读本文件，再按“重要文档与代码入口”读取对应文件。本文以 `main` 当前代码为准；旧计划中的已废止需求不能覆盖本文结论。

## 1. 一句话结论

PetBaby 已走过技术探针和初级功能搭建阶段，形成了一个 Windows 优先、可真实运行的桌面宠物 MVP：三种创建方式、多宠物管理、资料编辑、尺寸调节、按宠物校准、生成抠图安全闸门、一键开发启动、持久化与热切换均已实现。当前宠物动态只正式交付呼吸、整体轻摆及基础点击/拖拽反馈；自动眨眼、眼球/头部跟随、嘴部动作和自动口型已经明确冻结。

本轮最后根据真人测试反馈完成四项修复：停用错误的整图眨眼、修复正式宠物会话被误判为草稿、认领成功后返回上一级、把双窗口模式收敛为唯一常驻陪伴模式并加入 Win+D 非侵入式恢复。

最新自动化全部通过，但这四项修复仍需要用户在真实 Tauri 程序中进行下一轮手工复测。

## 3. 技术栈与运行形态

- 桌面框架：Tauri 2.11
- 后端/常驻核心：Rust
- 前端：TypeScript、Vite、PixiJS 8、Canvas、WebView2
- 本地数据：SQLite（`rusqlite bundled`）和版本化 JSON preferences
- Live2D：Cubism Web SDK，官方 SDK 文件保持本地 ignored，不提交仓库
- 图片生成：lk888.ai / `gpt-image-2` 异步任务（submit、poll、download）
- 生成实验工具：Python，位于 `services/appearance-generation`
- 目标平台：当前只考虑 Windows；本轮不扩展其他操作系统

开发阶段使用 `npm run tauri -- dev` 启动 Rust 后端与前端。公开发布时会生成 Windows `.exe`/安装包，但安装、升级、卸载、fresh machine 和 release 性能尚未完成正式发布验收，因此不能把当前状态描述为“可公开发布”。

## 4. 本次对话完成的主要工作

### 4.1 Windows 一键开发启动

- 仓库根目录已有 `一键启动桌宠开发环境.cmd`。
- 实际逻辑位于 `scripts/start-desktop-pet-dev.ps1`。
- 会检查 Node/npm/Cargo、必要依赖和 Cubism 准备状态；依赖缺失时可自动执行 `npm install`，该操作可能访问 npm registry。
- 启动器静态 AST、ASCII CMD、路径、退出码和 fake-command 合同已经验证；真实联网安装仍未作为正式验收完成。

### 4.2 数据库启动崩溃

曾出现 `no such table: creation_sessions` 导致 Tauri setup panic。迁移和启动顺序已修复并通过完整迁移测试；当前 Rust 全量测试可从临时数据库完整建立最新 schema。真实用户安装的首启仍需要 release/fresh-machine 验证，但正常迁移机制已存在。

### 4.3 图片生成与抠图安全

- 生成过程保存 raw 与 cutout 双图及结构化质量报告。
- 过度抠图、空结果、内部洞等不安全结果不会直接成为正式宠物；会进入可复核候选。
- 设置页复核能查看原图、抠图和质量提示。
- finalization 会阻止不安全候选进入正式资产。
- 资源路径有数据库所有权、canonical containment、junction/reparse 防护。
- 真实 provider 请求可能收费；未经用户动作发生前明确确认，不得再次调用。

### 4.4 宠物资料编辑

- 每只用户宠物有编辑入口。
- 可修改名称、性别、出生日期；有严格 Gregorian 日期和未来日期校验。
- 内置宠物不可编辑。
- 更新使用 mutation gate 与数据库事务，失败保留输入，切宠/删除竞争有互斥保护。

### 4.5 桌宠尺寸

- 设置页支持 50%～150%，0.05 步长和常用预设。
- 通过 Tauri 前后端 ACK 协议修改真实逻辑窗口矩形，并读取 OS 实际值作为 canonical 结果。
- 几何、显示比例、renderer 和 hit region 使用事务与回滚协调。
- 跨 DPI、负坐标副屏、拖动/缩放并发、保存乱序等已有大量自动化覆盖。
- 仍需真实多显示器、100%/125%/150% DPI 手工复测。

### 4.6 真实按宠物校准

- 校准按 pet ID 持久化，不是全局演示页。
- 设置页当前公开两个有效控件：`呼吸幅度 0%～5%`、`点击反馈 0～100%`。
- 预览、保存、取消、切宠、关闭窗口、保存中关闭和 runtime commit/reconcile 均有事务式状态机。
- `blinkIntervalScale` 仍留在 schema 中，范围 0.5～2，仅为旧数据 round-trip 的休眠字段；设置页不显示，运行时不消费。

### 4.7 创建与多宠物闭环

- 三条创建链路：上传图片生成、引导组合、直接认领。
- 创建候选完成后可热切换为当前宠物；SQLite 的 active pet 是权威事实。
- 支持重启恢复、精确删除、候选/任务 ownership、安全路径与失败回滚。
- 本轮修复：只有 upload/composer、pet lifecycle 为 draft、`completed_at IS NULL` 且不是当前宠物，才算可恢复长期草稿。
- ready 且已有 `completed_at` 的正式宠物若残留非终态 creation session，会被幂等收敛为 completed，不会再弹出错误的“处理上次创建”。
- 认领已有宠物或新认领成功并切换后，会返回创建入口上一级；失败、迟到或已离页时不导航。

### 4.8 单一常驻窗口模式

- 用户最终确认只保留一种公开模式：默认显示的常驻陪伴窗口。
- 设置页与托盘都不再提供 companion/desktop 选择。
- 托盘仍保留“显示或隐藏”。
- 同一显示器存在独占全屏前台窗口时自动隐藏；全屏结束后仅在用户没有手动隐藏时恢复。
- 旧 `mode=desktop` preference 在读取和写回时都归一为 companion；兼容命令收到 legacy desktop 请求也只执行 companion。
- 启动流程不再进入 WorkerW/BottomFallback。原双模式底层代码暂时保留为不可达兼容实现和测试资产，不是当前产品能力。
- Win+D 不修改 `userVisible`。程序通过 `IsWindowVisible`、`DWMWA_CLOAKED` 与 topmost 状态判断；只在 canonical 状态明确“应显示”时执行一次 `ShowWindow(SW_SHOWNA)` 和 `SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE)`。
- 同一次 Shell cloak 最多重申一次；不抢焦点、不 `SetParent`、不查找/重挂 WorkerW、不发送 Explorer 消息、不重启 Shell。若当前 Shell 持续 cloak，必须接受平台限制，不能用侵入式技巧强解。

## 5. 宠物动态效果设计：当前真实进度

这一节是下一对话最重要的动态设计事实。需要区分“运行时抽象里有接口”和“当前产品实际产生画面”。

### 5.1 动态架构

当前动态链路大致为：

```text
用户/窗口事件
  → behavior/decision.ts 生成 BehaviorIntent
  → PetPresentationController
  → renderer motion/expression + EffectOverlay + WindowMotionController
  → RenderScheduler 控制 active/companion/paused 档位
```

主要事件包括身体单击、双击、拖拽开始/结束、显示/隐藏和 idle tick。表现层支持 happy、curious、carried、landed、sleep、awake 等意图，但不同 renderer 的可见实现程度不同。

渲染档位：

- active：60 FPS，用于交互反馈。
- companion：24 FPS，用于常驻呼吸/微动。
- paused：停止帧循环；隐藏、全屏 suppression 和窗口事务暂停时不继续推进动画，也不会恢复时补跑大量旧帧。

### 5.2 三类 renderer 的动态实现

#### A. Static PNG

- 当前有底部中心锚定的整体呼吸缩放。
- 周期约 2.8 秒。
- 缩放幅度由 `breathAmplitudePercent` 控制，范围 0%～5%。
- 锚点在宠物底部中心，因此脚底位置尽量稳定。
- 不实现表情、look、carried/landed motion 或口型；这些调用目前为 no-op。
- 已删除眨眼的整图纵向压缩。现在的整体呼吸是平滑周期缩放，不是突然闭眼替代效果。

#### B. Animated image（当前用户创建宠物的主路径）

- 使用 `life-v1` motion profile。
- 呼吸周期约 2.8 秒；只对 profile 指定的中央胸腹区域做 24 条切片局部形变。
- 有 `faceSafetyLine`，脸部上方保持不变；切片边缘有 raster-safe bleed，降低缝隙。
- 整体轻摆周期约 5.2 秒；最大约 0.7°，水平位移约视口宽度 0.45%。
- 摆动围绕 profile 的 `swayPivot`，hit envelope 预计算覆盖整个摆动范围。
- 当前仅 idle motion 真正驱动连续微动；expression、look、lip sync 和其他 motion 仍是 no-op。
- 呼吸幅度由校准值缩放，0 可关闭，5 为当前最大值。

#### C. Live2D 内置宠物

- 正式生产只驱动两项：`bodyBreath → ParamBreath`、`bodySway → ParamBodyAngleX`。
- 呼吸基础值为 0.5，正弦周期约 4 秒，校准幅度按 0%～5%叠加。
- 整体轻摆由 7.5 秒与 11.3 秒两条正弦混合，最终限制在 `-6..6`。
- carried 状态下轻摆归零，呼吸降低到正常的 25%；landed/idle/wake 恢复普通微动。
- Live2D motion/expression 映射存在时可以播放对应动作或表情；缺失时只记录诊断并安全 no-op。
- `setLookTarget` 当前是 no-op。`setLipSync` 和 parameter mixer 的口型兼容接口仍存在，但当前没有自动口型来源，不能宣称嘴部动作已经实现。

### 5.3 点击、拖拽和视觉反馈

- 身体单击：`react-curious`，优先触发 curious 表情/motion，并播放 sparkles。
- 双击：`react-happy`，优先触发 happy 表情/motion、hearts，并按反馈强度摇晃窗口。
- 拖拽开始：`carried`；拖拽结束：`landed`，播放落地粒子并按反馈强度弹跳窗口。
- 点击反馈强度只缩放粒子透明度/位移/旋转/缩放及窗口 shake/bounce 幅度，不改变行为选择。
- 反馈强度为 0 时不播放视觉粒子或窗口反馈，但行为层仍可选择相同 intent。
- Static PNG 与 animated-image 对 motion/expression 的支持有限，所以跨 renderer 最稳定的可见反馈是 overlay 粒子和窗口 shake/bounce；不能假设每类宠物都有相同表情动画。

### 5.4 已冻结的动态能力

以下能力明确不进入当前版本：

- 自动眨眼
- 整图压缩模拟闭眼
- 眼球跟随
- 头部跟随/转头
- 嘴巴开闭
- 自动口型/lip sync

原因不是缺少调用接口，而是缺少合格的眼睑、闭眼、口腔、多角度遮挡和补图素材。此前的 v7 眨眼、v9 头部跟随等研究文件继续作为研发归档保留，不能直接恢复到生产。

代码中的 `BehaviorIntent` 仍包含 `blink`，manifest 语义仍允许 `eyeOpen`/`mouthOpen`，parameter mixer 也保留相应兼容层；但 `PetPresentationController` 当前对 blink 直接 return，三类 renderer 已无 `setBlink`，设置页也没有眨眼控件。这是有意的冻结兼容设计，不是遗漏修复。

### 5.5 动态效果下一步的正确方向

短期不应继续增加“假眨眼”或全图形变。推荐先做：

1. 真实运行复测呼吸、轻摆、点击、双击、拖拽和隐藏恢复在三类 renderer 上的视觉一致性。
2. 优化 static PNG 整体呼吸的自然度，避免和“整体突然缩小”的旧眨眼问题产生视觉混淆。
3. 为 animated-image 的呼吸区、脸部安全线和 sway pivot 增加用户素材质量诊断。
4. 统一三类 renderer 对 carried/landed/react motion 的最小可见反馈，仍以 overlay/window motion 为跨格式保底。
5. 只有完成眼睑/闭眼/口腔/转头素材专项后，才重新设计眼睛和嘴部状态机。
