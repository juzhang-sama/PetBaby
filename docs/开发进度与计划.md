# 桌面宠物项目——开发进度与计划交接文档

> 用途：跨会话开发交接。新会话先阅读本文件，再阅读对应阶段计划、设计和验证记录。

## 1. 项目概览

**目标**：Windows 优先的轻量桌面宠物（Tauri 2 + Rust + PixiJS 8），支持上传宠物照片 → 云端生成形象 → 桌面陪伴、多宠管理与离线可用。首只原创 Live2D 宠物仅交付已达标的胸部呼吸和整体轻摆；头部跟随、眼球、眨眼和嘴部动作留待具备合格拆图与补图素材后的迭代版本。

**产品定位**：先做好“有生命感、不碍事”的桌面宠物；AI 助手、声音和主动养成为后续迭代。云端负责创造，本地负责陪伴。

**里程碑**：M0（技术探针）→ M1（P0 运行时）→ M2（P1-A 生命感）→ M3（生成链路实验）→ M4（P1-B 创建闭环）→ L1（首只原创 Live2D 宠物）。M0～M3 已通过；M4 三条创建链路的核心创建、热切换和重启恢复已经真实 Tauri 验收，生成失败/编译失败等破坏性 GUI 边界仍有明确未执行项；L1 的模型、运行包、浏览器预览和正式 Tauri 桌面接入已通过验收。

## 2. 技术栈与架构

- 桌面端：Tauri 2.11 + Rust + TypeScript + Vite + PixiJS 8 + SQLite（rusqlite bundled）
- 生成服务：聚合平台 lk888.ai / gpt-image-2（异步任务：submit → poll → download）
- 实验工具：`services/appearance-generation/`（Python，M3 验证用，含 rembg 抠图）
- 目录结构：`apps/desktop`（主应用）、`services/appearance-generation`（生成实验）、`scripts`、`docs`（计划/验证记录）

## 4. L1 当前状态（重要）

**已完成**：Cubism v11 生产源、单张 2048 纹理图集、脸部/眼睛/胸前缝隙修复、只驱动 `ParamBreath` 与 `ParamBodyAngleX` 的确定性微动控制器、manifest v2 内置包、`?live2dPreview=1` 真实模型预览，以及普通 Tauri 桌宠启动路径。

**验收结果**：用户已确认呼吸幅度；呼吸端点不改变脸部，整体轻摆落地点稳定。浏览器深色背景连续运行 60 秒，模型资源全部加载成功、WebGL 上下文丢失为 0。普通 Tauri 透明窗口中也已确认模型显示、持续运动、拖拽放下、全屏隐藏和恢复，未发现脸部或胸部透明穿孔。详见 `docs/验证记录/首只宠物呼吸与整体微动验收记录.md` 和 `docs/验证记录/首只Live2D宠物正式桌面接入验收记录.md`。

**明确不进入当前版本**：头部跟随、眼球跟随、自动眨眼、嘴巴开闭和自动口型。相关 v7/v9 研究文件继续保留，不丢弃有效数据。

## 6. 关键业务逻辑（M4 定稿）

```text
上传 + Key → 创建一个 pet 与一个 job → 生成中（可续接）→ 唯一候选预览
  ├─ 接受 → 编译 → 两阶段热切换 → 持久化当前选择与接受状态 → 桌面
  ├─ 生成失败 → 同一 pet 重新上传并生成新 job
  ├─ 编译/切换失败 → 保留候选与 job，在可重试阶段继续
  └─ 放弃 → 精确删除目标 pet、关联 job 与资产
```

- 当前选择的权威来源是 SQLite；设置页、桌面窗口和重启恢复必须以该记录为准。
- API Key 本地配置仅为开发期方案；发布前须服务化，不能将 Key 写入仓库。
- 单候选创建不持久化未提交表单草稿；一旦创建 pet/job，即应可跨设置窗口和应用重启续接。
