# 桌面宠物项目——开发进度与计划交接文档

> 用途：跨会话开发交接。新会话先读本文件，再读各阶段计划与技术结论。

## 1. 项目概览

**目标**：Windows 优先的轻量桌面宠物（Tauri 2 + Rust + PixiJS 8），支持上传宠物照片 → 云端生成卡通形象 → 桌面陪伴（呼吸/眨眼/互动），多宠管理与离线可用。当前为**小范围测试版**阶段。

**产品定位**（已确认）：先做好"有生命感、不碍事"的桌面宠物，AI 助手/声音/主动养成为后续迭代；云端负责创造、本地负责陪伴。

**里程碑**：M0（技术探针）→ M1（P0 运行时）→ M2（P1-A 生命感）→ M3（生成链路实验）→ M4（P1-B 创建闭环）。**M0~M3 已通过，M4 自动化通过、人工闭环测试进行中**。

## 2. 技术栈与架构

- 桌面端：Tauri 2.11 + Rust + TypeScript + Vite + PixiJS 8 + SQLite（rusqlite bundled）
- 生成服务：聚合平台 lk888.ai / gpt-image-2（异步任务：submit → poll → download）
- 实验工具：`services/appearance-generation/`（Python，M3 验证用，含 rembg 抠图）
- 目录结构：`apps/desktop`（主应用）、`services/appearance-generation`（生成实验）、`scripts`、`docs`（计划/验证记录）

## 4. M4 当前状态（重要）

**已实现**：创建向导（上传照片→填 Key→生成 1 个候选→预览→编译→桌面）、任务进度轮询、单候选流程（满意/重新生成/放弃）、资产编译（manifest + 降级）、多宠切换（pet-asset 协议）、API Key 应用内配置、隐私提示。

**M4 修复链（按时间）**：
1. WebView2 硬件加速问题 → 所有窗口 `--disable-gpu`
2. 设置/校准窗口懒创建（state 注入前不预加载）
3. 全屏检测排除桌面窗口（Win+D/点桌面不再隐藏宠物）
4. 双击弹跳不再翻转、偏移自动复位
5. 创建向导：identityMode 序列化（realPet）、任务数字 task_id 解析、轮询线程 tokio 嵌套 panic、错误可见、切页状态保持、单候选流程

**待用户实测**：M4 人工清单 C-01~C-08（见 `docs/验证记录/M4手工验证清单.md`），当前用户正在测创建闭环。

## 5. 关键业务逻辑（M4 创建流程定稿）

```
上传+Key → 生成 1 个（进度卡片）→ 预览
  ├─ 满意，出现在桌面 → 编译（自动清理 jobs 中间产物）→ 设为当前 → 桌面
  ├─ 不满意，重新生成 → 同一宠物再生成（不重复建宠物）
  └─ 放弃 → 删除宠物记录 + 清理任务产物
```
- 切页（我的宠物/创建宠物）保持生成状态
- API Key 本地配置为**开发期方案**；SaaS 化（密钥放服务端）已记录为发布前迭代项
