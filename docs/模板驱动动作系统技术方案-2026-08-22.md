# 模板驱动动作系统 技术方案（路线 C）

> 状态：待评审
> 日期：2026-08-22
> 前置文档：`docs/项目开发交接文档-动作库路线-2026-08-20.md`（逐帧重绘路线）、`docs/项目开发交接文档-2026-08-19.md`（项目总览）
> 结论一句话：把「每只猫手工标注动作区域」换成「一套标准猫体模板 + 每个形象自动适配」，让呼吸/眨眼/摇尾巴对所有形象通用。

---

## 1. 背景与目标

### 1.1 问题

当前动作库（`scripts/中等简约动作.py` + `像素动作库.py`）的工作方式是：**每只宠物单独手工标注一套 160 网格像素坐标**（`eyes` / `breathZone` / `groundAnchors` / `tail.root + tail.mask`），动作算法针对这套坐标重绘帧。

这套方式在三只内置猫上能跑通，但**无法扩展到「用户上传照片 → 生成像素形象」的主链路**：每来一个新形象，就要手工标一遍。这违背项目「面向所有用户」的目标。

### 1.2 已暴露的具体症状

- **尾巴分割「粘连」**：`tail.mask` 是 6~7 个顶点的粗凸多边形，`owned = mask ∩ 可见像素` 会把「身体右侧 + 尾巴根」一起圈进蒙版，动尾巴时连带身体一起抖（01/02 号最严重，卷曲尾巴尖回到身体下方）。根因是「多边形切一刀」在低分辨率像素画里切不干净，而这是**每个形象都要单独面对**的问题——不是改三只猫的 mask 能根治的。

### 1.3 目标

建立一套**模板驱动的动作系统**：

1. 动作算法只认「标准猫体模板」定义的分区与锚点，**与具体形象无关**。
2. 任意新形象只需提供母版 PNG，系统**自动**生成动作分区并驱动动作，**无需逐形象手工标注**。
3. 保留每个形象的身份特征（体型、尾巴姿态、毛色花纹完全自由）。

---

## 2. 现状与根本结论

### 2.1 项目里已有「标准猫体模板」，但动作库没接上

`services/appearance-generation/src/photo_avatar_backend/assets/pixel-style-v1/标准猫体模板.json`（`pixel-style-v2-animation-ready` 也有一份）已经定义了一套归一化坐标（0..1）的身体结构：

| 模块 | 内容 |
|---|---|
| `proportions` | 体型比例：头高 55%、身高 45%、头宽 62%、四肢高 20% |
| `parts` | 四层部件 `head` / `body` / `tail` / `paws`（各带归一化 bounds） |
| `space` | `alphaBounds`、`faceSafeZone`、`eyes`（左右眼 center+bounds）、`earRoots`、`breathZone`、`tailRoot`、`edgeTailBounds`、`stretchAxis`、`swayPivot` |
| `amplitude` | `breath` / `blink` / `ear` / `tailAngle` / `tailCurl` / `tailTip` / `bodyStretch` |

配套代码 `standard_cat_template.py` 的 docstring 明确写：**「标准猫体模板是『生成规整 + 动作库 + 未来 Live2D 绑定』的公共基础设施」**。同时还有三套体型变体（`body-slender-v1` / `body-balanced-v1` / `body-rounded-v1`）与身份中立的 `uv-guides`。

**结论**：模板资产齐备，缺的是「模板 → 动作库」的衔接层（自动适配），以及动作库从「手工标注」向「模板驱动」的改造。

### 2.2 网格与尺寸关系（必须统一口径）

| 层 | 尺寸 | 用途 |
|---|---|---|
| 母版 PNG | 1024×1024 | 生成产物原始分辨率 |
| 逻辑网格 | 160×160 | 动作库合成帧的像素工作层（`load_logical_rgba` 用 NEAREST 缩到 160） |
| 模板 canvas | 256×256 | 模板归一化坐标的参考画布（实际坐标是 0..1，与 canvas 尺寸无关） |

模板坐标一律归一化，因此**映射时直接用 0..1 比例**，与 160 / 256 / 1024 无关。

## 3. 核心架构

```
                     ┌─────────────────────────────────────────┐
                     │  标准猫体模板（归一化，不可变，已入库）   │
                     │  space: eyes / breathZone / tailRoot / … │
                     └──────────────────┬──────────────────────┘
                                        │ 归一化坐标
                                        ▼
母版 PNG(1024) ──► alphaBounds 自动计算 ──► 模板仿射对齐（映射到 160 网格）
                                        │
                                        ├─► breathZone / groundAnchors（模板映射，够用）
                                        ├─► eyes（模板先验 + 局部检测）
                                        └─► tail（模板 tailRoot 先验 + 骨架提取精确切）
                                        │
                                        ▼
                          MotionAnnotation（自动生成，动作算法的输入契约不变）
                                        │
                                        ▼
                动作算法（make_breath / make_tail_wag / make_blink，逐帧重绘）
                                        │
                                        ▼
                          帧序列 → 打包 manifest → 桌面运行时
```

核心设计原则：**动作算法的输入契约（`MotionAnnotation`）保持不变**，只把它的「来源」从手工标注换成「模板 + 自动适配」。已验证的呼吸/尾巴/眨眼算法完全复用，不重写。

## 4. 关键设计

### 4.1 模板归一化坐标 → 实际形象的仿射对齐

模板锚点不能简单「×160」，因为每个形象的实际轮廓（alphaBounds）大小、偏移都不同。正确做法是**以 alphaBounds 为锚做仿射对齐**：

```python
# 模板空间（归一化）的 alphaBounds（模板 JSON 固定值）
T = dict(left=0.19, top=0.06, right=0.85, bottom=0.94)
TW, TH = T["right"] - T["left"], T["bottom"] - T["top"]

# 实际形象的 alphaBounds（160 网格，从母版 alpha 通道自动算）
A = dict(left=..., top=..., right=..., bottom=...)
AW, AH = A["right"] - A["left"], A["bottom"] - A["top"]

def map_x(x_norm): return A["left"] + (x_norm - T["left"]) / TW * AW
def map_y(y_norm): return A["top"]  + (y_norm - T["top"])  / TH * AH
# 矩形同理：四个角分别映射
```

- `breathZone`、`groundAnchors`、`eyes` 中心点、`tailRoot` 都用这个映射定位到 160 网格。
- 这个映射的前提是「形象拓扑与模板一致」——即正视坐姿、头在上、尾巴在右下。**生成 prompt 已保证这一点**（`front view, sitting upright, full body visible`）。

### 4.2 尾巴：模板 tailRoot 先验 + 骨架提取精确切（解决「粘连」的关键）

尾巴是「位置会漂移、形态差异大」的部位，模板映射只能给「尾巴大概在右下」的先验，不能给精确蒙版。精确蒙版用**骨架提取**得到（已在本轮实测验证可行）：

1. **起点**：模板 `tailRoot` 映射到实际形象后，找该点附近最近的「可见像素」作为 BFS 起点。
2. **测地距离**：沿可见像素做 BFS 测地距离（只在「tailRoot 邻域」内扩散，不进身体主体）。
3. **尾巴尖**：测地距离最远的像素。
4. **骨架**：从尾巴尖回溯到起点，得到 1px 中心线。
5. **精确蒙版**：沿骨架按「局部粗细」向两侧扩展，得到像素级尾巴蒙版。

实测结果（三只猫）：BFS 覆盖率 99~100%，尾巴尖定位准确，骨架长度 53~57px。骨架天然处理卷曲尾巴（01/02 号尾巴尖回到身体下方）。

**为什么它根治「粘连」**：骨架提取产出的蒙版只含「贴着骨架的尾巴肉」，身体像素不在蒙版里 → 动尾巴时身体像素**永远不动**。替代现在「粗多边形把身体右侧一起圈进去」的做法。

### 4.3 眼睛：模板先验 + 局部深色检测

眼睛位置相对稳定（头部中线附近），但颜色因猫而异（黑猫眼睛深色、浅色猫眼睛可能偏蓝绿）。策略：

1. 模板 `eyes.left.center / right.center` 映射 → 得到「眼睛大概中心」。
2. 以该点为中心，在模板 `eyes.bounds` 映射出的局部窗口内，搜索「深色像素连通簇」。
3. 取最靠近模板中心、且大小符合眼睛特征的簇作为眼睛 Rect。

**风险与兜底**：黑猫（03 号）眼睛与毛色接近，深色检测可能不稳 → 兜底用「模板映射的眼睛 bounds 原样套用」（不精确但可用，眨眼是覆盖局部小区域，容错高）。

### 4.4 呼吸区 / 地面锚点：纯模板映射（够用）

- `breathZone`（身体中段，大范围、位置稳定）→ 模板映射直接用。
- `groundAnchors`（脚掌贴地区域）→ 模板 `paws` bounds 底部 + alphaBounds 底部推断。作用是审计时校验「脚掌 0 变化」，从轮廓底部自动取脚掌接触带即可。

### 4.5 体型变体（可选项，增强贴合）

模板已备三套体型（slender / balanced / rounded）。生成环节可根据宠物体型选择对应变体，使形象更贴合模板拓扑，降低自动适配的漂移。第一版可先用 balanced 一套跑通，变体作为后续增强。

### 4.6 自动适配失败的分层兜底

自动适配是主路径，失败时**分级降级**，把「手工成本」从「标全套」降到「标 2~3 个点」：

| 级别 | 触发 | 兜底 |
|---|---|---|
| L0 全自动 | 默认 | 全部模板映射 + 自动检测 |
| L1 尾巴失败 | 骨架提取找不到尾巴尖 | 用模板映射的 tailRoot + 默认尾巴方向，退化为一小段刚性摆 |
| L2 眼睛失败 | 深色检测置信度低 | 用模板映射的眼睛 bounds 原样套用 |
| L3 关键点校准 | 用户对某个部位不满意 | 人工只标眼睛中心 / 尾巴根等 2~3 个点，其余仍模板映射 |

## 6. 分阶段实施计划

| 阶段 | 内容 | 验收 |
|---|---|---|
| **S1 模板适配器（分区映射）** | 实现 alphaBounds 计算 + 仿射对齐，自动产出 breathZone / groundAnchors / eyes / tailRoot | 三只猫自动映射出的分区与手工标注误差在合理范围（呼吸区/锚点 100% 一致，眼睛中心 ±3px） |
| **S2 尾巴骨架提取接入** | 把已验证的骨架提取收敛为正式模块，接入模板适配器 | 三只猫自动切出的尾巴蒙版，动尾巴时身体区变化 = 0（解决粘连） |
| **S3 眼睛自动定位** | 模板先验 + 局部深色检测 + L2 兜底 | 三只猫眨眼帧闭眼覆盖正确，黑猫不误判 |
| **S4 动作库改造为模板驱动** | 像素动作库入口改为「母版 → 自动标注 → 动作」，去掉手工 json 依赖 | 三只猫全自动跑通 breath/blink/tail-wag，审计全绿 |
| **S5 回归与打包** | 重新打包 builtin-pets，跑 `npm test` + Rust 测试 | 无回归，manifest 正确 |
| **S6 新形象验证** | 用第 4 只新形象（或用户照片）验证「零手工标注」跑通 | 只给母版，自动生成标注 + 动作，无需人工干预 |

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| AI 生成形象不贴合模板（尾巴位置漂移大） | 模板映射偏差 | 骨架提取用「tailRoot 邻域 + 最远点」自动纠偏，不依赖模板精确 |
| 黑猫眼睛检测失败 | 眨眼错位 | L2 兜底套模板 bounds；眼睛区域小，容错高 |
| 尾巴与身体严重粘连（极端形象） | 骨架提取切不开 | L1 兜底退化为短段摆；标记该形象为「需人工校准」 |
| 模板强约束伤身份 | 体型个性丢失 | 模板只锁「拓扑」不锁「形状」，体型/尾巴姿态完全自由（路线 B 而非 A 的核心） |

---

## 8. 验收标准（统一）

1. **零手工标注**：新形象只提供母版 PNG，系统自动生成 `MotionAnnotation` 并跑通三个动作。
2. **动作审计全绿**（沿用现有 `audit_action`）：循环闭合、地面锚点 0 变化、≤24 色、峰值变化量正常。
3. **尾巴不粘连**：动尾巴时，身体区（骨架蒙版外）像素变化 = 0。
4. **身份保留**：不同体型/毛色/尾巴姿态的形象，动作仍各自动作（不套同一个形状）。
5. **无回归**：`npm test` 全量通过（当前基线 1073 passed / 17 skipped），Rust 测试通过。

---

## 9. 与既有资产的关系（不冲突、不删除）

- 标准猫体模板 + 体型变体 + uv-guides：**复用**，成为本方案的输入。
- 逐帧重绘路线（`像素逐帧重绘demo_v6.py` 及 `中等简约动作.py` 算法）：**保留**，算法不变，只换标注来源。
- 三只猫现有手工 annotation json：**保留为回归夹具**（用来验证自动适配与手工标注的一致性）。
- Live2D 休眠资产：**不动**（本方案不涉及其恢复）。
