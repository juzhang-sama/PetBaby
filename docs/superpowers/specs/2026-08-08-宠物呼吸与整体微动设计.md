# 宠物呼吸与整体微动设计

## 1. 结论

第一版停止继续制作眨眼和嘴巴开闭，保留已经形成的模型文件、设计记录和失败结论。下一阶段以不产生新画面的动作建立生命感：呼吸、身体轻摆、上半身渐变式头部跟随和受限视线。

模型采用多个职责单一的嵌套弯曲变形器，运行时分别驱动对应参数。现有眼睛、虹膜、鼻子、嘴线和嘴部变形器全部保留，不重新拆图，不生成新的眼睑或口腔素材。

## 2. 目标与非目标

### 2.1 第一轮目标

- 呼吸可感知但不夸张，胸肩区域变化大于底部，整体轮廓保持稳定。
- 身体产生缓慢、低幅度的左右轻摆，底部基本固定。
- 通过上半身渐变形变表现轻微头部跟随，不单独移动五官。
- 继续使用现有眼球 X/Y 参数，但把运行范围限制在安全区间。
- 呼吸、轻摆、头部跟随和视线能够同时叠加，不互相覆盖。
- 模型缺少眨眼或嘴部运行能力时静默降级，不报错、不出现异常画面。

### 2.2 第一轮非目标

- 不制作眨眼、眼睑、闭眼纹理或闭眼 Motion。
- 不制作嘴巴开闭、口腔内部、牙齿、舌头或自动口型。
- 不制作耳朵和尾巴的独立物理。
- 不重新拆分头部、身体或毛发底图。
- 不制作主动行走、复杂全身动作或多角度转身。
- 不为了增加动作幅度接受白边、透明洞、五官漂移或明显纹理拉伸。

## 4. Cubism 模型设计

### 4.1 选择方案

采用“嵌套整体变形器 + 运行时程序驱动”。不采用以下方案：

- 只制作一个循环 Motion：制作更快，但呼吸、视线和交互难以独立混合，循环感明显。
- 重新拆分头部和身体：动作上限更高，但需要补图和处理遮挡，不符合首版加速目标。

### 4.2 变形器结构

目标结构如下：

```text
整体轻摆变形器
└─ 呼吸变形器
   └─ 头部跟随变形器
      └─ 现有全部 ArtMesh、旋转变形器和局部弯曲变形器
```

三个新变形器只负责各自的参数。现有眼球 X/Y、嘴线和其他局部关键形继续保留在内层，不删除、不重建。

### 4.3 参数职责

| 产品语义 | Cubism 参数 | 建议范围 | 职责 |
|---|---|---:|---|
| `bodyBreath` | `ParamBreath` | `0..1` | 胸肩轻微扩张和头部极小升降 |
| `bodySway` | `ParamBodyAngleX` | `-10..10` | 下部固定、上半身左右缓慢轻摆 |
| `angleX` | `ParamAngleX` | `-30..30` | 上半部分轻微左右跟随 |
| `angleY` | `ParamAngleY` | `-30..30` | 上半部分轻微上下跟随 |
| `eyeBallX` | 现有眼球 X | 运行时 `-0.35..0.35` | 安全范围内的水平视线 |
| `eyeBallY` | 现有眼球 Y | 运行时 `-0.35..0.35` | 安全范围内的垂直视线 |

参数的 Cubism 声明范围保持标准值，实际可见幅度由关键形控制。运行时不使用标准参数的极限画面作为日常动作幅度。

### 4.4 视觉幅度

- 呼吸周期初值为约 4 秒。胸肩轮廓变化控制在局部尺寸的约 `1%` 到 `2%`，底部变化接近 `0`。
- 身体轻摆周期在 6 到 9 秒间缓慢变化。上半身横向位移不超过模型可见宽度的约 `1%`。
- 头部跟随的日常输入约为标准角度参数的 `±2°` 可见效果；参数极值只用于校准，不用于运行时持续驱动。
- 眼球运行范围初值为 `±0.35`。如果组合动作仍出现白边，继续缩小到 `±0.25`，不修改眼球纹理扩大范围。
- 所有动作使用平滑曲线；禁止瞬间跳到关键形端点。

“头部跟随”不是把眼睛、鼻子和嘴单独移动。它通过覆盖整个模型、但让上部控制点移动更多的渐变形变实现，避免五官与脸部毛发分离。

## 5. 运行时设计

### 5.1 能力映射

在 `Live2DParameterSemantic` 中增加 `bodySway`，映射到 `ParamBodyAngleX`。继续复用已有的 `bodyBreath`、`angleX`、`angleY`、`eyeBallX` 和 `eyeBallY`。

第一版模型的 manifest 不声明 `eyeOpen` 和 `mouthOpen` 运行能力。参数混合器遇到缺失映射时跳过写入；不得把缺失能力视为模型加载失败。

### 5.2 驱动层

运行时使用相互独立的自动化通道：

```text
时间源
├─ 呼吸波形 -> bodyBreath
├─ 慢速轻摆波形 -> bodySway
└─ 低频头部漂移 -> angleX / angleY

鼠标目标
├─ 受限平滑 -> eyeBallX / eyeBallY
└─ 更弱的受限平滑 -> angleX / angleY
```

自动漂移与鼠标跟随在进入参数混合器前相加并限幅。眼球响应快于头部；头部只跟随一小部分鼠标位移，从而产生先看、再轻微跟随的层次。

### 5.3 状态与中断

- `idle` 和 `companion`：运行呼吸、轻摆和低频头部漂移。
- 用户移动指针：眼球平滑跟随，头部以更低权重跟随。
- `carried`：暂停自动轻摆，保留极弱呼吸；拖拽结束后平滑恢复。
- `hidden`、`paused` 或 WebGL context lost：停止自动化时间推进。
- 点击和窗口抖动继续由展示控制器与窗口运动控制器负责，不写入 Cubism 基准参数。

### 5.4 降级

- 缺少 `bodySway`：保留呼吸、头部跟随和视线。
- 缺少 `bodyBreath`：保留轻摆、头部跟随和视线。
- 缺少角度参数：保留呼吸、轻摆和视线。
- 缺少眼球参数：眼睛保持正视。
- Live2D 模型加载失败：继续使用静态预览图回退。

任何单项能力缺失都不能阻止合法模型加载。

## 6. 验收标准

### 6.1 Cubism Editor 验收

- 分别往返检查呼吸、轻摆、角度 X/Y 和眼球 X/Y，各执行至少两次。
- 再检查所有参数在安全运行范围内的组合状态。
- 眼睛保持睁开、嘴保持闭合，鼻子和嘴线不随呼吸错误漂移。
- 毛发轮廓无新增白边、透明洞、断裂或明显拉伸。
- 下半身和落地点保持稳定，不产生整只宠物在画布中滑动的感觉。
- 用户能够感知呼吸和微动，但第一注意力仍是宠物身份而不是动画。

### 6.2 运行时验收

- 空闲观察 60 秒时，动作不呈现明显机械重复。
- 鼠标从中心移动到四个方向时，眼球先响应，上半身随后轻微跟随。
- 视线不进入已有白边位置。
- 拖拽期间动作不与窗口移动争抢，放下后平滑恢复。
- 禁用眨眼和嘴部能力后无重复诊断刷屏、无异常参数写入。
- 静止、隐藏和暂停档位仍能停止不必要的连续更新。

## 7. 测试策略

- 为 `bodySway` 语义、参数混合顺序和限幅增加 TypeScript 单元测试。
- 为自动化波形的周期、连续性、暂停恢复和组合限幅增加确定性测试。
- 为缺少眨眼、嘴部、呼吸或轻摆参数的模型增加能力降级测试。
- 运行 `runtime-live2d`、展示控制器和渲染调度器相关测试，再运行前端类型检查和构建。
- Cubism 变形质量和运行时自然度采用人工视觉验收，不用单元测试替代。

## 8. 停止条件

出现以下任一情况时停止增加幅度并回到上一个安全版本：

- 白边、透明洞或毛发轮廓断裂无法通过缩小幅度消除。
- 五官相对脸部明显漂移。
- 呼吸导致身体像整体缩放或橡胶拉伸。
- 轻摆导致落地点明显移动。
- 头部效果必须依赖重新拆图才能成立。

停止某个局部动作时，其他已通过验收的动作继续保留，不把单项失败升级为整个模型失败。
