# 固定帧动作资源协议与桌面运行时设计

设计日期：2026-08-21
状态：用户已确认
适用范围：`animated-image-v1` 固定帧资源、三只中等简约宠物、Windows/Tauri 桌面运行时

## 1. 结论

本次采用已确认的方案一：保留 `renderer=animated-image-v1`，新增独立的 `schemaVersion=6` 固定帧资源清单。历史 `schemaVersion=3` 的“单张 PNG + motion-profile + Canvas 程序形变”继续兼容，但新生成的中等简约宠物统一使用 v6 的透明 PNG 帧序列。

桌面运行时不再根据宠物身体结构实时制造呼吸、眨眼或摇尾。它只读取清单、预加载帧、按资源声明的时长播放，并在呼吸、眨眼和摇尾之间切换。这借鉴 Petdex 的运行时边界，但不照搬 Petdex 的低分辨率画风、固定网格尺寸或固定帧数。

三只当前动作虽然视觉质量不合格，仍作为占位资源接入真实桌面运行时并自动播放。`qualityStatus=placeholder` 只记录资源质量，不隐藏动作、不降低播放频率，也不引入“验收模式”。以后项目重新生成或第三方制作合格动作，只需替换同一状态下的 PNG 帧并重编译清单，不修改播放器代码。

## 2. 目标与非目标

### 2.1 本次目标

1. 定义可复用、严格校验、可版本演进的固定帧动作资源协议。
2. 让每个资源包自行决定帧数和逐帧时长，不把当前的 8/5/9 帧写死在运行时。
3. 桌面默认持续循环呼吸，并随机插入眨眼和摇尾；动作结束后返回呼吸。
4. 三只中等简约宠物进入现有真实桌面窗口、渲染循环、点击区域和宠物切换链路。
5. 保留 v3 历史资源兼容，冻结 Live2D v4/v5 路线，不让 Live2D 进入新路径。
6. 为未来第三方“代工”动作建立明确交付标准：透明 PNG 帧序列 + v6 清单。

### 2.2 本次不做

- 不继续精修三只宠物的动作美术。
- 不重新调用 lk888。
- 不直接播放 GIF，也不把 GIF 作为运行时权威资源。
- 不实现通用 GIF/APNG/视频导入器；第三方素材先离线转换为 PNG 帧。
- 不新增骨骼、网格、部件拆分或 Live2D 绑定。
- 不扩展跑、跳、睡眠、行走等新动作。
- 不建立单独的验收页面、验收开关或占位资源屏蔽逻辑。

## 3. 总体架构

```text
动作生产端或第三方软件
  -> 透明 PNG 帧序列
  -> 固定帧资源编译器
  -> manifest.json + previewImage + states/*/*.png
  -> Rust 清单/路径/哈希校验
  -> TypeScript 清单严格解析与图片预加载
  -> FixedFramePlayer 逐帧播放
  -> AnimatedImageRenderer 负责 Canvas、缩放、命中面和生命周期
  -> PetRuntimeSlot 原子切宠物
  -> PetStage 使用真实桌面帧循环驱动 update(deltaMs)
```

职责边界如下：

- 生成端负责“宠物长什么样”和“每个动作包含哪些帧”。
- 资源编译器负责复制规范化 PNG、计算 SHA-256、生成 v6 清单。
- Rust 负责不可信资源边界：清单结构、相对路径、声明文件和哈希完整性。
- TypeScript 负责浏览器边界：再次解析清单、解码图片、验证画布一致性。
- `FixedFramePlayer` 只负责时间、状态、优先级和帧索引。
- `AnimatedImageRenderer` 只负责把当前帧画到 Canvas，并继续提供 resize、visibility、hitTest、destroy 等既有运行时接口。
- `PetStage` 继续提供唯一桌面帧循环，不为固定帧新增第二套 `requestAnimationFrame` 或后台定时器。

现有 `animated-image-renderer.ts` 已经承担单图形变、动作映射、Canvas 和命中区域等多项职责。固定帧播放器必须拆成独立模块，不能继续把完整状态机堆入该文件。

## 4. v6 资源包

### 4.1 目录结构

```text
assets/
  manifest.json
  body.png
  states/
    breathe/
      f00.png
      f01.png
      ...
    blink/
      f00.png
      ...
    tail-wag/
      f00.png
      ...
```

`body.png` 是静态母版和最终回退图。三个状态目录只保存运行时帧，不保存 GIF、总览图、峰值帧、坐标图或审计截图。

### 4.2 清单示例

```json
{
  "schemaVersion": 6,
  "renderer": "animated-image-v1",
  "petId": "pet-v2-longhair-black-white",
  "variantId": "placeholder-motion-2026-08-21",
  "styleProfileId": "pixel-style-v2-animation-ready",
  "qualityStatus": "placeholder",
  "previewImage": "body.png",
  "alphaBounds": {
    "left": 0.18,
    "top": 0.08,
    "right": 0.86,
    "bottom": 0.96
  },
  "states": {
    "breathe": {
      "frames": [
        { "path": "states/breathe/f00.png", "durationMs": 180 },
        { "path": "states/breathe/f01.png", "durationMs": 180 }
      ],
      "loop": true
    },
    "blink": {
      "frames": [
        { "path": "states/blink/f00.png", "durationMs": 150 },
        { "path": "states/blink/f01.png", "durationMs": 150 }
      ],
      "loop": false
    },
    "tail-wag": {
      "frames": [
        { "path": "states/tail-wag/f00.png", "durationMs": 120 },
        { "path": "states/tail-wag/f01.png", "durationMs": 120 }
      ],
      "loop": false
    }
  },
  "automation": {
    "defaultState": "breathe",
    "blinkIntervalMs": [3000, 8000],
    "tailWagIntervalMs": [12000, 30000]
  },
  "files": [
    {
      "role": "preview",
      "relativePath": "body.png",
      "sha256": "<64位小写SHA-256>"
    },
    {
      "role": "frame",
      "relativePath": "states/breathe/f00.png",
      "sha256": "<64位小写SHA-256>"
    }
  ]
}
```

示例为节选；正式清单必须把每个被引用的 PNG 都列入 `files`。

### 4.3 字段约束

| 字段 | 约束 |
|---|---|
| `schemaVersion` | 必须为整数 `6` |
| `renderer` | 必须为 `animated-image-v1` |
| `petId`、`variantId` | 非空安全 ID，并与安装目标身份一致 |
| `styleProfileId` | 当前必须为 `pixel-style-v2-animation-ready` |
| `qualityStatus` | 必须为 `placeholder` 或 `production`；仅记录，不参与播放判断 |
| `previewImage` | 必须为清单内声明的透明 PNG |
| `alphaBounds` | 全部帧非透明区域的归一化并集；四项有限数值位于 0 至 1，且 left < right、top < bottom |
| `states` | 只允许 `breathe`、`blink`、`tail-wag`，不允许未知动作 ID |
| `frames` | 声明状态必须至少 1 帧；单状态最多 120 个帧条目 |
| `durationMs` | 每帧独立声明，必须为 16 至 10000 的整数毫秒 |
| `loop` | `breathe` 必须为 `true`；`blink` 和 `tail-wag` 必须为 `false` |
| `automation` | 必须存在；区间为两个正整数且最小值不大于最大值 |
| `files` | 只允许 `preview`、`frame` 角色；相对路径唯一、SHA-256 有效；内容必须恰好覆盖母版和全部被引用 PNG |

顶层、`alphaBounds`、状态、帧、自动化和文件条目对象均拒绝未知字段。全包最多包含 36 个不同的 frame PNG；帧序列可以重复引用同一路径。以当前 `1024x1024 RGBA` 资源估算，这把母版和帧的常驻解码内存控制在约 148 MiB 以内。审计、身份档案和联系表保存在运行包之外。

### 4.4 状态缺失与损坏

- `previewImage` 是唯一不可缺失的视觉资源；它无法读取或解码时，整个候选运行时加载失败，原宠物继续显示。
- `breathe` 未声明或图片解码失败时，使用 `previewImage` 静态显示。
- `blink` 或 `tail-wag` 未声明或图片解码失败时，跳过该自动动作，不影响呼吸或静态显示。
- 状态对象一旦声明，就不允许空 `frames`；空数组属于非法清单，不进入运行时降级。
- 清单声明的文件不存在、哈希不匹配或路径越界时，Rust 安装校验直接拒绝整个资源包，不把半成品替换进正式目录。
- 当前三只宠物必须完整声明三个状态；上述降级用于未来资源故障，不是当前交付的省略许可。

## 5. 帧图像合同

1. 所有运行帧必须为 PNG，透明背景，RGBA 解码结果。
2. 同一资源包内 `previewImage` 和全部帧的像素宽高必须完全一致；当前三只均为 `1024x1024`。
3. 帧在同一画布坐标系内，宠物不得因裁切、留白或画布变化发生整体跳动。
4. 播放使用最近邻采样，`imageSmoothingEnabled=false`。
5. 协议不规定 8/5/9 帧，也不规定统一 FPS；实际节奏完全来自逐帧 `durationMs`。
6. GIF 只可作为人工预览证据。GIF 编码器可能合并重复帧，因此不能作为帧数、顺序或时长的权威来源。
7. 允许不同帧条目引用同一个 PNG 路径，以表达停顿或复用，但 `files` 中该相对路径只出现一次。
8. 资源编译器必须从母版和全部帧计算非透明像素并集，写入 `alphaBounds`；桌面命中测试使用该并集，避免摇尾超出母版轮廓后无法点击。

第三方交付时，项目接收的是按最终播放顺序编号的 PNG 帧。第三方可以使用任意软件制作 GIF、视频或工程文件，但进入 PetBaby 前必须离线转换并通过上述合同。

## 6. 自动行为状态机

### 6.1 基本行为

挂载成功且可见后：

1. 有 `breathe` 时立即从第 0 帧开始循环呼吸；没有时显示 `body.png`。
2. 分别为眨眼和摇尾生成下一次随机触发时间。
3. 到达触发时间后播放对应非循环动作。
4. 非循环动作完整结束后，从呼吸第 0 帧重新开始。
5. 重新安排该动作的下一次随机触发时间，避免连续立即触发。

随机区间来自资源包，而不是播放器常量。测试通过注入确定性随机源验证边界，不依赖真实时间等待。

### 6.2 不叠加和优先级

固定帧是整张宠物图，不能把眨眼帧和摇尾帧叠加。任一时刻只允许一个状态占有画面。

当同一次 `update` 有多个候选动作时，优先级固定为：

```text
明确交互动作 > tail-wag > blink > breathe
```

- 自动动作不会在另一个自动动作中途硬切；它等待当前动作结束后重新判断。
- 明确交互动作可以中断自动动作，但不能启动两个帧状态叠加播放。
- 当前动作集对既有 `PetMotion` 的映射只做有语义依据的部分：`idle -> breathe`，`react-happy` 和 `react-curious -> tail-wag`。
- `look-left`、`look-right`、`sleep`、`wake`、`carried`、`landed` 暂无对应固定帧时保持当前呼吸或静态帧；窗口拖拽、落地反馈和特效仍由现有上层逻辑执行，不伪造错误动作。
- 未来新增动作必须先扩展 manifest schema 和映射测试，不能在播放器里用字符串暗接。

### 6.3 可见性与生命周期

- 自动调度只由 `update(deltaMs)` 推进；窗口隐藏、渲染层暂停时，动作时间也暂停，不在后台积累待播放动作。
- 窗口重新显示时从默认呼吸或静态图恢复，并重新抽取随机间隔，不补播隐藏期间错过的动作。
- `destroy()` 必须使未完成的图片加载和动作句柄失效，清空帧数组、Canvas 引用和当前调度状态。
- 切换宠物时，候选资源的必需图片先加载完成；候选可显示后再由现有 `PetRuntimeSlot` 原子替换旧宠物。失败时旧宠物、旧调度和旧画面保持不变。
- 切换提交后立即销毁旧运行时，避免同时保留两套 1024 帧的解码内存。

## 7. 加载、校验与回退数据流

### 7.1 Rust 边界

`apps/desktop/src-tauri/src/runtime_assets/manifest.rs` 增加 `RuntimeAssetManifestV6`，并把 v6 接入现有：

- `parse_manifest`
- `manifest_files`
- `manifest_identity`
- `validate_asset_directory`
- 原子 staging/install
- `asset_manifest`
- `asset_file_b64`

Rust 必须验证清单形状、动作 ID、循环语义、时长区间、帧数量上限、`alphaBounds`、路径规范、声明文件和 SHA-256。v1 至 v5 的解析和序列化结果保持不变。

### 7.2 TypeScript 边界

TypeScript 增加与 Rust 等价的 v6 类型和严格解析器。`loadAnimatedImageAsset` 根据 schema 分支：

- v3：继续返回单图和 `motionProfile`，走历史程序动画。
- v6：返回 `previewImage`、已解码状态帧和自动化配置，走固定帧播放器。

图片加载采用有界并发，避免同时产生大量 base64 中间数据。加载器先保证 `previewImage` 可用，再尝试各状态的完整帧组；某状态只要有一帧解码或尺寸不合格，就整体舍弃该状态，不能播放半个动作。

### 7.3 渲染回退

回退顺序固定为：

```text
完整 v6 动作
  -> v6 呼吸可用、事件动作缺失
  -> v6 body.png 静态图
  -> 候选加载失败，保留当前已挂载宠物
```

不把 v6 失败自动转回 v3 程序形变，因为 v6 包没有 `motion-profile.json`，也不应悄悄改变资源作者声明的运动方式。

## 8. 三只宠物接入方式

当前三只资源来自：

`output/中等简约像素标准验收-2026-08-21`

编译时只提取每只宠物的 `母版.png` 和三个 `动作/*/frames/*.png`，生成三个确定性 v6 运行包：

| 宠物 | petId | 当前帧时长 |
|---|---|---|
| 长毛黑白猫 | `pet-v2-longhair-black-white` | 呼吸 8x180ms；眨眼 5x150ms；摇尾 9x120ms |
| 圆脸狸花猫 | `pet-v2-round-tabby` | 呼吸 8x180ms；眨眼 5x150ms；摇尾 9x120ms |
| 修长黑猫 | `pet-v2-sleek-black` | 呼吸 8x180ms；眨眼 5x150ms；摇尾 9x120ms |

三包作为可重复构建的内置开发宠物登记到现有宠物目录和切换来源表中，在设置页可直接选择。它们使用与普通 v6 宠物相同的解析器、播放器、`PetStage`、窗口和切换协调器；不建立特殊播放模式。内置登记的目的只是让占位资源可随代码库稳定复现，不代表 `qualityStatus=placeholder` 有任何运行时特权。

同时，Rust v6 清单和安装校验必须覆盖 `pets/<petId>/assets` 的正式已安装路径。后续照片生成流程或第三方导入流程产出同样的 v6 目录后，可直接走现有 installed source，无需修改桌面播放器。

## 9. 兼容与迁移

| 版本 | 当前处理 |
|---|---|
| v1 | 保持现有静态/历史资产兼容 |
| v2 | 保持现有 Live2D 历史兼容，不扩展 |
| v3 | 保持单图程序动画兼容，不迁移已有包 |
| v4/v5 | Live2D 冻结；只维持读取，不进入新生成路径 |
| v6 | 新的 `animated-image-v1` 固定帧协议，成为中等简约宠物的新默认运行资产 |

本次不批量改写历史 manifest。新生成和重新编译的中等简约宠物才使用 v6。renderer 名称保持不变，是因为 v3 和 v6 都属于 Canvas 动态图片家族；schemaVersion 明确区分资源形状和播放机制。

## 10. 测试与人工验收

### 10.1 纯逻辑测试

- Rust/TypeScript 对同一份 v6 合法 fixture 得到等价结构。
- 拒绝未知字段、未知动作、错误 loop、空帧、非法 duration、非法 `alphaBounds`、超出帧上限、重复路径、多余文件、越界路径、漏列文件和错误哈希。
- 动态帧数测试不能使用 8/5/9 作为协议假设。
- 帧时间边界、大 delta 跨多帧、循环回卷、非循环结束返回呼吸。
- 同时到期时 `tail-wag` 优先于 `blink`。
- 自动动作不互相中断，明确交互动作可以中断自动动作。
- 缺失眨眼/摇尾时跳过；缺失呼吸时显示静态母版。
- 隐藏期间不推进，重新显示不补播。
- destroy 和宠物切换后旧调度不再更新旧 Canvas。
- v3 fixture 与既有行为保持不变。

### 10.2 加载与切换测试

- 所有图片挂载前完成必需加载，任一状态失败时整组舍弃。
- 帧尺寸与母版不一致时拒绝该状态。
- 候选宠物加载失败时，旧宠物不闪白、不消失。
- 成功切换后旧图片引用和旧动作句柄释放。
- Rust staging 校验失败不替换正式 assets。

### 10.3 真实桌面人工验收

必须在真实 Tauri 桌面窗口完成并记录：

1. 三只宠物分别可从设置页切换到桌面。
2. 每只默认持续呼吸，观察到随机眨眼和随机摇尾，动作后返回呼吸。
3. 连续运行至少 10 分钟，无停止、白帧、动作叠加或越来越快。
4. 隐藏再显示后正常恢复，不集中补播动作。
5. 快速切换三只宠物，不出现旧宠物残帧或两个调度并行。
6. 拖拽、点击区域和窗口层级仍正常。
7. 用一组不同帧数和不同时长的替换 fixture 验证运行时代码无需修改。

动作是否“好看”不属于本轮通过条件；本轮只验收资源协议、播放正确性、自动行为和真实桌面接入。人工记录必须明确标注三只动作仍是 `placeholder`，不得把机械可播放描述成美术质量合格。

## 11. 完成定义

以下条件全部满足才算完成：

- v6 协议在 Rust 和 TypeScript 两端严格落地，v1-v5 回归通过。
- 固定帧播放器独立于 Canvas 宿主，可用纯逻辑测试验证。
- 三只占位宠物在真实桌面中自动呼吸、随机眨眼和随机摇尾。
