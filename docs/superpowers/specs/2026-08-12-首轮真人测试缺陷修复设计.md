# 首轮真人测试缺陷修复设计

## 1. 目标

本轮只修复真人测试确认的四类问题，不扩展新的宠物能力：

1. 当前版本完全停用自动眨眼及其整图压缩替代效果。
2. 只有真正未完成、可安全放弃的长期草稿才触发“处理上次创建”。
3. 认领或切换成功后离开认领选择页，返回创建入口上一级。
4. 用户界面只保留一个常驻陪伴模式：默认显示、保留托盘手动隐藏、同屏独占全屏时自动隐藏、Win+D 不计为手动隐藏并执行非侵入式恢复。

## 2. 已确认根因

### 2.1 眨眼规格回退

`PetStage` 每帧驱动 `BlinkController`，静态 PNG、动画图片和缺少眼部语义的 Live2D 都把 `eyeOpen` 映射为整张画布最多 3% 的纵向压缩。该实现与既有“自动眨眼和嘴部动作不进入当前版本”的冻结结论冲突。

### 2.2 正式宠物会话误占长期草稿槽

`find_long_draft_id` 只按 creation session 的非终态筛选，没有同时验证 pet 仍为未完成 draft、没有 `completed_at` 且不是 active pet。残留的 `finalizing`/`retryableFailure` 会话因此被前端误当成草稿；后端 abandonment 安全边界又会拒绝删除 ready/active pet，形成必现阻塞。

### 2.3 认领成功路径没有导航动作

认领视图成功切换后只刷新目录和状态文案，没有调用已经存在的 `onBack` 端口。失败路径和显式返回路径正常，缺口只在成功收敛。

### 2.4 双模式与产品语义不一致

现有 companion 是置顶并在全屏时隐藏；desktop 是 WorkerW/置底宿主且不按全屏隐藏。用户需要的是单一“常驻陪伴”语义，而不是 WorkerW 桌面图标层。当前机器还存在非标准 Shell 拓扑，既有 M0 结论已经记录 Win+D 可能由 DWM/Shell 隐藏普通窗口，不能靠破坏 Explorer 的方式强行解除。

## 3. 设计决策

### 3.1 眨眼停用但保持持久化兼容

- 删除 `PetStage` 的 blink 调度和 renderer 的 `setBlink` 公共能力。
- 三类 renderer 不再写眼部参数，也不再缩放整张画面。
- 设置页移除“眨眼间隔”控件。
- `blinkIntervalScale` 暂时保留在 Rust/TypeScript 校准 schema 中，并固定使用已保存值或默认值完成旧数据 round-trip；它是休眠兼容字段，不影响画面。
- 后续只有在具备合格眼睑、闭眼贴图或可靠 Live2D 眼部参数后，才能另立专项重新启用。

### 3.2 以宠物事实定义可恢复草稿

长期草稿必须同时满足：

- method 为 `upload` 或 `composer`；
- session 非 `completed`/`abandoned`；
- pet lifecycle 为 `draft`；
- pet `completed_at IS NULL`；
- pet 不是 `app:active_pet_id`。

进入创建入口和创建新草稿前都执行同一后端收敛：若 session 非终态但 pet 已经 `ready` 且存在 `completed_at`，将 session 幂等更新为 `completed`，不删除 pet/资产。其余不一致数据不执行 abandonment，而返回明确诊断。

数据库唯一草稿约束继续保留；收敛必须发生在新 session 插入事务之前，避免残留正式会话继续触发唯一索引。

### 3.3 认领成功统一返回

- 已认领宠物切换成功：先刷新宠物目录，再调用 `onBack`。
- 新宠物认领并完成切换：同样刷新后调用 `onBack`。
- 失败、迟到结果或页面已经离开时不导航。
- 返回目标为创建入口上一级，不直接跳到“我的宠物”标签。

### 3.4 单一常驻模式

公开产品行为固定为：

- 默认 `userVisible=true`；
- 用户可以通过托盘手动隐藏/显示；
- 同一显示器存在独占全屏前台窗口时自动隐藏；
- 全屏结束后，仅当用户没有手动隐藏时恢复；
- Win+D 不修改 `userVisible`；
- 设置页和托盘不再显示 companion/desktop 模式选择。

旧 preferences 中的 `mode=desktop` 在读取时迁移为 companion；写回只产生 companion。现有 WorkerW/BottomFallback 不再从任何生产入口启动。为降低一次性删除风险，原生宿主实现可暂时保留为不可达兼容代码，但测试必须证明生产注册、设置和托盘都无法请求 desktop。

### 3.5 Win+D 非侵入式恢复

新增只读窗口可见性事实：

- Win32 `IsWindowVisible`；
- `DWMWA_CLOAKED`，区分 `DWM_CLOAKED_SHELL`；
- 当前 topmost 扩展样式。

每次 750ms 全屏探针完成后，由后端按 canonical visibility 做一次有界 reconcile：

- 预期隐藏：不恢复。
- 预期显示且仅普通 hidden/非 topmost：重新 `show` 并恢复 topmost/no-activate，不抢焦点。
- 预期显示但被 Shell cloak：记录去重诊断；只允许一次安全的 show/topmost 重申，不循环重建窗口、不发送 Explorer 消息、不 SetParent、不重启 Shell。
- 手动隐藏、全屏隐藏、退出或 mode transition 期间绝不恢复。

若当前 Shell 持续 cloak，应用必须保持低占用并在 cloak 解除后的下一次 probe 自动恢复；不使用可能破坏 Explorer 的技巧来伪造“始终可见”。

## 4. 测试边界

- 所有产品改动先有失败测试。
- 眨眼：三类 renderer、PetStage、设置页静态/控制器契约均断言无视觉眨眼能力。
- 创建：覆盖 ready+completed+active 的残留 session、真正 draft、损坏不一致、唯一草稿索引及无删除副作用。
- 认领：覆盖既有宠物切换、新认领完成、失败、迟到和离页。
- 常驻模式：覆盖旧 desktop preference 迁移、托盘显隐、全屏、manual hide、普通 hidden、shell cloak、topmost 丢失及退出。
- 最终运行 Rust 全目标、前端全量、typecheck、build、fmt 和 diff check。

## 5. 非目标

- 不制作眼睑、闭眼、嘴部或转头素材。
- 不改变宠物资料、尺寸、抠图、生成 provider 或校准保存事务。
- 不重启 Explorer，不发送 undocumented Shell 消息，不引入后台高频窗口重建。
- 不在本轮开发新功能或公开发布安装包。
