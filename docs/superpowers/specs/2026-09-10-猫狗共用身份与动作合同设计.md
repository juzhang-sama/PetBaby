# 猫狗共用身份与动作合同设计

**目标**：让当前 pixel 照片路线接受猫和狗，同时继续使用同一套动作语义、播放器和资产协议。

## 结论

物种信息保留为轻量元数据 \`cat | dog\`，由现有身份分析结果携带。项目不新增独立物种识别服务，不建立猫动作和狗动作两套运行时。

## 边界

- Python、Rust、TypeScript 的 pixel 身份合同都接受 \`cat\` 和 \`dog\`，其他值拒绝。
- 身份分析提示词要求模型从输入照片中返回猫或狗；补全提示词必须保留已分析物种。
- 动作语义继续共用：\`idle\`、\`grab-release\`、点击反馈等由同一套运行时处理。
- 每只宠物仍需根据自己的体型、尾巴、脚掌和取景框生成独立动作帧。
- 旧的 \`animated-film-soft-v1\` 和 Live2D 猫专用路线不在本次范围内。

## 数据流

照片 -> 现有身份分析 -> profile.species(cat|dog)
     -> 同一套身份补全 -> 同一套生成请求
     -> 后续按具体宠物生成动作帧

## 验收

- 既有猫 profile 测试保持通过。
- 狗 profile 在 Python、Rust、TypeScript 三端解析通过。
- bird 等第三物种在三端被拒绝。
- pixel 身份合并结果不会把 dog 重写成 cat。
- 本切片不宣称狗的图像生成、动作帧生成或安装闭环已经完成。
