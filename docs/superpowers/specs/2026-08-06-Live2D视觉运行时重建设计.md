# Live2D 视觉运行时重建设计

## 1. 结论

项目采用 **Live2D-first** 路线：保留已经成立的 Tauri/Rust 平台壳、宠物档案、创建流程、行为决策和窗口物理，重建以单 PNG、Pixi Mesh 和自研蒙皮为中心的视觉运行时。

第一版使用正面坐姿宠物，优先实现表情、视线、呼吸、耳尾物理、点击反馈、睡眠和窗口反馈。主动行走和更复杂的全身 Motion 保留在同一架构内，但不进入第一版验收范围。

这次调整不是在旧网格系统上继续扩展，也不是清空整个项目。新旧视觉运行时通过稳定接口隔离；新 Live2D 路径达到发布门槛后，旧 Mesh 路径退出正式产品，仅保留静态 PNG 故障回退。

## 2. 目标与非目标

### 2.1 第一版目标

- 使用官方 Live2D Cubism SDK for Web 加载 Cubism 4/5 模型包。
- 支持自然眨眼、视线跟随、头部轻微转动、呼吸和物理摆动。
- 支持至少 6 种产品语义表情：中性、开心、好奇、困倦、委屈、生气。
- 支持头部点击、身体点击、抚摸、喂食、玩耍、睡眠和苏醒反馈。
- 支持 TTS 音量驱动口型；TTS 不可用时不影响其他动画。
- 支持窗口轻微抖动、弹性位移和拖拽反馈。
- 保持宠物创建、切换、档案、离线陪伴和行为状态链路可用。
- 在 Live2D 初始化或模型加载失败时显示静态 PNG，不让主程序崩溃或空白。
- Windows 11 为首要验证环境，Windows 10 在发布前完成真机或虚拟机验收。

### 2.2 第一版非目标

- 不实现自动把任意单张 PNG 转换成可发布的 `.moc3` 模型。
- 不实现复杂四足步态、长距离自主巡游和多宠同屏。
- 不让 Agent、LLM 或脚本直接操作 Cubism 参数。
- 不在第一版开放任意代码型角色插件。
- 不直接复用调研仓库中的角色模型、动画、美术或受 GPL/LGPL 约束的实现代码。
- 不继续增强 `PetMesh`、`mesh-rig`、`skinning` 和旧视觉关键帧系统。

## 3. 技术选择

### 3.1 运行时

- 桌面宿主：Tauri 2 + Rust，继续负责透明无边框窗口、置顶、托盘、多屏、DPI、点击穿透、窗口位置和持久化。
- 模型渲染：TypeScript + 官方 Live2D Cubism SDK for Web，使用 Cubism Core 和官方 Framework。
- 特效覆盖层：保留 PixiJS 8 仅用于粒子、调试覆盖层和必要的二维特效，不再负责宠物主体变形。
- 行为层：保留现有事件、意图、状态、冷却和 `PetPhysics` 纯逻辑；行为层只发产品语义命令。
- 故障回退：静态 PNG 渲染器，不使用旧 Mesh 变形作为正式降级路径。

不采用 `pixi-live2d-display` 0.4 作为正式基础。该路径面向 PixiJS 6，不能作为当前 PixiJS 8 项目的长期依赖。项目通过自己的 `Live2DRenderer` 适配官方 SDK，适配层只暴露项目需要的稳定能力。

### 3.2 许可证

- 在引入 SDK 前记录 Cubism SDK、Cubism Core 和模型数据的开发、分发和商业许可边界。
- 代码许可证与模型许可证分开登记；每个模型包必须包含来源、作者、允许用途和分发状态。
- BongoCat、BANDORI-PET-REV、daidai-live2d-pet、VPet 和 Sakura 仅作为 clean-room 架构参考。
- 未通过许可证检查的 Core、模型、纹理、Motion 和 Expression 不进入安装包。

## 4. 架构边界

```text
用户/系统事件
    -> BehaviorDecision
    -> BehaviorIntent
    -> PetPresentationController
       |- PetRenderer
       |  |- Live2DRenderer
       |  `- StaticPngRenderer
       |- WindowMotionController
       `- EffectOverlay

Live2DRenderer
    |- CubismModelLoader
    |- MotionController
    |- ExpressionController
    |- ParameterMixer
    |- LipSyncController
    |- HitAreaResolver
    `- RenderLoop
```

### 4.1 `PetRenderer`

宿主只依赖以下语义接口，不依赖 Cubism 参数名：

```ts
type PetExpression =
  | "neutral"
  | "happy"
  | "curious"
  | "sleepy"
  | "sad"
  | "angry";

type PetMotion =
  | "idle"
  | "look-left"
  | "look-right"
  | "react-happy"
  | "react-curious"
  | "sleep"
  | "wake"
  | "carried"
  | "landed";

interface PetRenderer {
  load(asset: PetRenderAsset): Promise<void>;
  resize(viewport: RenderViewport): void;
  playMotion(motion: PetMotion, options?: MotionOptions): MotionHandle;
  setExpression(expression: PetExpression, weight?: number): void;
  setLookTarget(target: NormalizedPoint | null): void;
  setLipSync(value: number): void;
  hitTest(point: NormalizedPoint): PetHitArea | null;
  setVisibility(visible: boolean): void;
  update(deltaMs: number): void;
  destroy(): void;
}
```

`PetRenderer` 不负责窗口坐标、数据库、生成任务或行为选择。Cubism 参数名、Motion Group 和 Expression 文件名只存在于模型包映射和 `Live2DRenderer` 内部。

### 4.2 `PetPresentationController`

该控制器替代 `PetStage` 中对 `LayeredSprite` 和 `PetAnimator` 的直接创建，负责：

- 将 `BehaviorIntent` 转换为语义 Motion、Expression、窗口反馈和粒子反馈。
- 处理动作优先级、可中断性、冷却和完成回调。
- 协调睡眠、拖拽和 TTS 等正交状态，避免压成单一巨型枚举。
- 不执行 Cubism 参数计算，不直接调用 Tauri 窗口 API。

### 4.3 动作仲裁

动作按以下优先级处理：

```text
系统安全/隐藏
  > 拖拽与下落
  > 直接用户交互
  > 睡眠与苏醒
  > TTS 口型和表情
  > 主动待机动作
  > 基础 idle
```

基础呼吸、眨眼、视线、物理和口型作为可混合通道；身体主 Motion 采用单主轨并支持淡入淡出。低优先级动作不能打断高优先级动作，高优先级动作结束后回到当前状态对应的循环 Motion。

### 4.4 窗口运动

模型内部运动与桌面运动保持分离：

- `Live2DRenderer` 播放身体 Motion。
- `WindowMotionController` 使用现有 `PetPhysics` 结果移动 Tauri 窗口。
- 窗口抖动使用短时局部偏移，不写入持久化位置。
- 主动行走的后续实现将“走路 Motion + 窗口位移”组合，不改变 Renderer 接口。

## 5. 资产协议

### 5.1 Manifest v2

Live2D 资产使用新的 `live2d-v1` 渲染类型，不在 manifest v1 的 `parts` 和 `meshFeatures` 上继续扩展。

```ts
interface Live2DRenderAsset {
  schemaVersion: 2;
  renderer: "live2d-v1";
  modelEntry: string;
  previewImage: string;
  files: AssetFileDigest[];
  semantics: {
    motions: Partial<Record<PetMotion, CubismMotionRef>>;
    expressions: Partial<Record<PetExpression, string>>;
    hitAreas: Partial<Record<PetHitArea, string>>;
    parameters: CubismParameterMap;
  };
  license: ModelLicenseMetadata;
}
```

加载器必须验证：路径不能逃逸模型目录、声明文件存在、摘要匹配、模型入口可解析、必需语义存在、纹理尺寸不超过发布限制。

### 5.2 第一版模型合同

第一版产品模型必须是原创或获得明确商业许可的正面坐姿模型，并至少提供：

- `idle`、`react-happy`、`react-curious`、`sleep`、`wake`、`carried`、`landed` Motion。
- 6 种产品语义表情。
- 头部和身体命中区。
- 眼睛开合、眼球、头部角度、身体呼吸、嘴巴开合参数。
- 耳朵和尾巴的物理配置；无尾宠物允许映射为空能力。
- 静态预览 PNG，用于加载前占位和故障回退。

模型缺少非必需能力时允许降级，但不得让业务层引用具体 Cubism ID。

### 5.3 用户生成宠物

现有“任意图片生成宠物”不能直接产出可靠 Live2D 模型。迁移分两步：

1. 第一版以一套原创、人工绑定的基准模型验证完整运行时；现有用户宠物继续通过静态 PNG 回退显示。
2. 后续建立猫、狗等预绑定模板族。云端生成严格遵守模板分层、构图和遮挡补全合同，只替换可控纹理和部件，不在客户端动态生成 `.moc3`。

只有模板族通过身份相似度、接缝、极限参数、Motion 和许可证验收后，才将对应创建入口切换到 Live2D。自动建模或云端生成 Cubism 模型属于独立研发项目，不阻塞第一版运行时。

## 6. 渲染循环与资源策略

- 连续 Motion、物理、视线或口型活动时使用 active 档；普通陪伴使用 companion 档。
- 完全静止时允许降帧或停止连续更新，但恢复时必须用单调时钟计算增量，避免大步跳帧。
- 隐藏、全屏避让或系统暂停时停止 Cubism 更新和绘制。
- 切宠前停止 Motion、释放 Cubism Model、纹理、WebGL buffer 和事件监听。
- WebGL context lost 时暂停绘制并尝试一次重建；重建失败切换静态 PNG。
- 模型加载、解析或渲染异常进入结构化日志，不影响档案、托盘和设置页。

## 7. GPU 与 Windows 验证门槛

当前 `tauri.conf.json` 的 `--disable-gpu` 与 Cubism WebGL 冲突。不能直接删除后宣称问题解决，必须先做独立技术探针：

- 验证启用 GPU 后透明 WebView2、置顶、拖拽、点击穿透和多屏 DPI。
- 复测曾经的宠物不可见问题，确认其布局修复在 GPU 模式下稳定。
- 测试 WebGL context lost、锁屏恢复、显示器热插拔和睡眠恢复。
- 采集 idle、交互、隐藏三种状态的 CPU、内存、GPU 和 WebView2 子进程数据。
- 若目标设备无法稳定启用 WebGL，启动时进入静态 PNG 模式并给设置页记录可诊断原因。

第一版发布分析线沿用现有目标：微动画 CPU 长期采样 P95 不高于 3%。内存和 GPU 门槛以技术探针的新基线为准，不沿用关闭 GPU 时的数值冒充 Live2D 基线。

## 8. 测试策略

### 8.1 自动化

- Manifest v2：正常模型、缺文件、摘要错误、路径逃逸、未知语义和许可证缺失。
- 语义映射：每个 `PetMotion`、`PetExpression` 和命中区的映射与缺失降级。
- 动作仲裁：优先级、打断、淡入淡出、完成回退和睡眠期间禁止普通待机。
- 参数混合：眨眼、视线、呼吸、口型和 Expression 不互相覆盖。
- 生命周期：切宠、隐藏、恢复、加载失败、context lost 和销毁幂等。
- 窗口反馈：抖动不污染持久化坐标，拖拽和窗口物理不由 Renderer 执行。

### 8.2 视觉与手工验收

- 桌面和移动视口截图检查模型非空白、缩放正确、无遮挡和无裁切。
- 至少录制 idle、六种表情、点击、睡眠、苏醒、拖拽、落地和 TTS 口型片段。
- 检查表情切换无闪帧，眼睛、嘴巴、耳朵和尾巴不存在明显穿帮。
- 检查透明区域点击穿透，头部和身体命中区与视觉位置一致。
- Windows 11 完整验收；Windows 10 完成透明、置顶、穿透、DPI、锁屏和恢复清单。

## 9. 迁移与退役

迁移采用并行替换，不在旧运行时内部嵌入 Cubism：

1. 建立 GPU/Cubism 技术探针，失败时不改产品默认路径。
2. 建立 `PetRenderer`、Manifest v2 和静态回退。
3. 接入基准 Live2D 模型，完成第一版生命感和交互闭环。
4. 将 `PetStage` 拆为展示控制、窗口运动和特效覆盖层。
5. 在 Live2D 路径完成自动化、视觉、性能和 Windows 验收后切换默认渲染器。
6. 删除正式链路对 `PetMesh`、`mesh-rig`、`skinning` 和旧视觉关键帧执行器的引用。
7. 旧 manifest v1 仅通过 `StaticPngRenderer` 读取预览主图，不再执行网格和骨骼变形。

退役删除必须在默认切换和回归验收之后进行，避免一次提交同时失去可用产品和调试基线。

## 10. 分阶段交付与闸门

### 阶段 A：Cubism/GPU 技术探针

交付：官方示例或内部测试模型在 Tauri 透明窗口中稳定渲染，完成 GPU、WebGL、窗口和基础性能报告。

闸门：模型可见、透明正确、交互不丢失、连续运行无明显增长、静态回退可触发。未通过则停止产品接入，先解决宿主兼容性。

### 阶段 B：渲染器与资产协议

交付：`PetRenderer`、`Live2DRenderer`、`StaticPngRenderer`、Manifest v2、语义映射、生命周期和错误隔离。

闸门：纯逻辑测试、模型加载测试、失败回退和切宠释放全部通过。

### 阶段 C：第一版生命感

交付：正面坐姿基准模型、六种表情、眨眼、视线、呼吸、耳尾物理、点击、睡眠、拖拽、落地、口型和窗口反馈。

闸门：视觉验收视频、命中区、行为仲裁和 TTS 降级通过。

### 阶段 D：默认切换与旧运行时退役

交付：Live2D 成为支持模型的默认渲染器；旧宠物使用静态 PNG；旧 Mesh 正式链路删除。

闸门：全量测试、Windows 验收、性能采样、安装包许可证清单和回滚演练通过。

### 阶段 E：模板化个性宠物

交付：至少一个猫或狗预绑定模板族，打通云端分层生成、纹理/部件装配、预览、选择、安装和离线使用。

闸门：身份相似度、遮挡补全、接缝、极限参数、模型包完整性和商业许可通过。该阶段独立于第一版运行时计划。

## 11. 前人经验的采用边界

- 从 VPet 采用“语义动作 × 状态 × start/loop/end”和窗口验收清单，不采用其 WPF/PNG 运行时或角色资产。
- 从 Sakura 采用 Renderer SPI、角色包配置、异常隔离和静态回退，不把其预留接口误认为现成 Live2D 实现。
- 从 BANDORI-PET-REV 采用 Motion、Expression、Physics、命中区和 alpha 穿透的产品经验，不复制 GPL/LGPL 实现。
- 从 daidai-live2d-pet 采用模型注册、视线和嘴型交互经验，不采用 PixiJS 6/Cubism 2 技术栈。
- 从 BongoCat 采用单实例、托盘、窗口位置和轻量状态经验，不采用 GDI+ 图片状态实现。

## 12. 成功标准

第一版成功不是“SDK 能显示模型”，而是同时满足：

- 用户在正常待机、点击、说话和睡眠场景中能明显感知表情与生命感提升。
- Live2D 故障不会破坏宠物档案、创建流程、设置、托盘和静态显示。
- 业务行为、窗口物理和模型参数保持分层，后续增加行走 Motion 不需要再次重写平台架构。
- 旧 Mesh 路径不再承担产品能力，新开发不会继续向其增加功能。
- 模型、SDK 和安装包的许可证边界可审计。
