# 宠物资料、显示尺寸、真实校准、窗口模式与抠图安全设计

## 1. 背景与目标

第一轮真实测试确认桌宠能够启动并显示，同时暴露五个产品缺口：已创建宠物无法编辑资料、桌宠缺少尺寸控制、校准入口未接入真实运行时、陪伴/桌面双模式被删除，以及浅色宠物在浅灰背景下发生严重过度抠图。

本轮采用风险优先的分阶段交付：先阻断损坏候选进入正式资产，再补齐资料与尺寸，随后让校准真正作用于当前宠物，最后重建具有可靠回滚能力的双窗口模式。每个阶段独立验证，不能以未完成的后续阶段掩盖当前阶段失败。

## 2. 范围与非目标

### 2.1 本轮范围

- 用户创建的宠物可编辑名称、性别和出生日期。
- 桌宠显示尺寸支持全局 50%–150% 连续调节、实时生效和重启恢复。
- 校准参数作用于当前宠物的真实运行时，支持实时预览、保存、取消和恢复默认。
- 恢复陪伴模式与桌面模式切换；桌面模式优先使用 WorkerW，失败时尝试兼容置底，两者均失败则回滚陪伴模式。
- `needs-review` 抠图候选不能定稿；前后端展示质量原因并保留原图供重试。
- 供应商结果若自带透明通道，不得在抠图前丢弃 alpha。

### 2.2 本轮非目标

- 内置虚拟宠物不开放资料编辑。
- 不从旧 `age` 自由文本推算出生日期。
- 不把旧 `source`、`breed` 字段恢复成正式资料字段。
- 不在本轮直接把 Python `rembg` 实验服务打包进桌面主程序。
- 不通过调节固定色键阈值声称解决浅色毛发与背景同色问题。
- 不在动画校准页实现像素级抠图画笔、眼区移动或头身分界编辑。
- 不承诺 Windows 10、所有第三方桌面外壳或所有虚拟桌面实现未经实机验证即通过。

## 3. 交付顺序

1. **阶段 A：抠图安全闸门。** 先保证坏图无法成为正式资产。
2. **阶段 B：宠物资料与显示尺寸。** 完成用户可见的日常管理能力。
3. **阶段 C：真实校准。** 移除测试壳，让参数作用于当前宠物。
4. **阶段 D：双窗口模式。** 在安全状态机上恢复高风险 Windows 能力。

阶段之间可以共享基础设施，但每个阶段必须有独立提交、自动测试和手工验收记录。

## 4. 阶段 A：抠图安全闸门

### 4.1 已确认根因

当前主流程对生成结果执行固定 RGB 色键：背景色取边缘中位数，与背景曼哈顿色差不超过 40 的像素完全透明，40–100 的像素渐变为半透明。白色、奶油色和浅灰色毛发与浅灰背景不可由该规则可靠区分。

质量检查能够把当前真实白猫候选标记为 `needs-review`，但任务仍成功、会话仍进入 `candidateReady`，候选 DTO 不包含质量，定稿也不检查质量。因此问题由“算法歧义”和“告警不参与准入”共同造成。

### 4.2 候选质量契约

候选投影新增结构化质量信息：

```text
CandidateQuality
├─ status: acceptable | needsReview
├─ reasons: QualityReason[]
├─ opaqueRatio
├─ transparentRatio
├─ partialAlphaRatio
└─ visibleBounds

QualityReason
├─ excessiveTransparency
├─ interiorHoles
├─ lowContrastSubject
├─ nonUniformBackground
└─ invalidSourceAlpha
```

数据库保留现有 `quality` 兼容字段，并增加能够恢复结构化原因的版本化质量报告。候选快照和预览 command 必须返回同一份后端事实，前端不得自行重新判定。

### 4.3 状态与准入

- `acceptable`：允许预览、命名和定稿。
- `needsReview`：允许查看原图和诊断用抠图结果，但“完成创建”保持禁用。
- 后端 finalization 必须再次读取候选质量并拒绝非 `acceptable`，防止绕过前端。
- 恢复旧会话时同样执行质量准入，不因为 `candidateReady` 或历史快照而放行。
- 失败候选保留原图、诊断抠图和质量报告；用户可以重新生成或放弃会话。
- 质量失败不是供应商任务失败，界面文案应为“图片已生成，但自动抠图未通过”，不能误导为网络错误。

### 4.4 alpha 处理

- 解码生成结果时先检查原始颜色类型。
- 来源具备有效 alpha 时保留并验证其 alpha，不得先 `to_rgb8()`。
- 来源不具备 alpha 时才进入背景移除策略。
- 色键结果只在质量为 `acceptable` 时进入正式候选。
- `needsReview` 不得自动回退为带灰色矩形背景的正式运行资产。

### 4.5 UI

候选复核区同时提供：

- 原图预览。
- 自动抠图预览。
- 清晰的失败说明。
- “重新生成”和“放弃创建”。
- 后续形象修复入口的预留位置；本轮不提供像素编辑器。

不得将用户真实生成图提交到仓库。自动测试使用合成的浅色宠物 fixture，覆盖浅色主体、深色特征、柔和阴影和抗锯齿边缘。

## 5. 阶段 B：宠物资料编辑

### 5.1 数据模型

新增独立表，避免与部分历史数据库遗留的 `gender/age/source/breed` 列冲突：

```sql
CREATE TABLE pet_profiles (
  pet_id TEXT PRIMARY KEY REFERENCES pets(pet_id) ON DELETE CASCADE,
  gender_code TEXT CHECK(gender_code IN ('male','female') OR gender_code IS NULL),
  birth_date TEXT,
  schema_version INTEGER NOT NULL,
  updated_at TEXT NOT NULL
);
```

- 名称继续存储在 `pets.display_name`。
- 性别未知时存 `NULL`，不使用空字符串。
- 出生日期使用 ISO `YYYY-MM-DD`，未知时存 `NULL`。
- 年龄由出生日期和当前日期计算，不落库。
- 内置虚拟宠物不创建 profile 记录。

### 5.2 迁移要求

现有迁移器的 legacy repair、最新版本和统一 schema 验证存在耦合。新增迁移前必须先使 legacy repair 固定落到 v6，再由普通循环执行后续迁移，防止追加迁移后跳过新表。

历史额外列处理：

- `name` 已由现有修复映射到 `display_name`，不重复处理。
- 合法旧 `gender` 可以在明确映射规则下回填 `gender_code`。
- 旧 `age` 不推算生日。
- 旧 `source/breed` 保留但不进入正式 domain。

### 5.3 后端协议

新增：

- `pet_profile_get(pet_id)`
- `pet_profile_update(request_id, pet_id, display_name, gender_code, birth_date)`

保存要求：

- 名称复用现有 Unicode 字素级校验。
- 出生日期必须是有效日期且不得晚于当天。
- 宠物必须存在、属于用户目录且不是内置虚拟项。
- 名称和 profile 在同一 SQLite 事务中更新。
- 更新纳入宠物 mutation gate，不能与同一宠物的删除或其他写操作并发。

### 5.4 设置 UI

“我的宠物”每行增加“编辑”。点击后展开资料面板：

- 名称输入框。
- 性别：未知、公、母。
- 出生日期选择器，允许清空。
- 保存、取消。
- 保存中禁用重复提交；失败保留用户输入并显示具体错误。

列表主视图继续保持紧凑，不强制显示完整资料。

## 6. 阶段 B：桌宠显示尺寸

### 6.1 语义

尺寸是全局桌宠窗口设置，不是某个 renderer 的内部 scale，也不是每只宠物独立设置。以当前 420×520 为 100%，允许 50%–150%。

### 6.2 实现边界

- 新增版本化 `displayScale`，不重新启用旧的 dormant `scale` 字段。
- 由桌宠窗口统一 resize，使 static PNG、animated image 和 Live2D 共用同一语义。
- 尺寸变化后沿用现有 resize 链重新布局 renderer、刷新 hit region。
- 调整前后保持窗口底部中心的屏幕坐标不变。
- 新矩形必须 clamp 到当前显示器工作区。
- 隐藏或全屏抑制期间可以保存尺寸，但恢复显示前必须先应用尺寸和命中区。
- settings 通过显式 command/event 请求 pet 窗口调整，并等待成功回执后更新已保存值。

### 6.3 UI

- 设置页提供连续滑杆和当前百分比。
- 提供“小 75% / 中 100% / 大 125%”快捷值。
- 拖动时实时预览，但持久化进行去抖；释放滑杆时确保最终值落盘。
- 调整失败时回滚滑杆到最后确认值。

## 7. 阶段 C：真实校准

### 7.1 产品边界

本阶段校准只负责动画表现：

- 呼吸幅度。
- 眨眼间隔缩放。
- 点击反馈强度。

抠图失败属于候选形象修复，不与动画参数混在同一表单。眼区、头身分界和像素级命中区编辑保留为后续资产校准项目。

### 7.2 数据与协议

使用按宠物隔离、带 schema version 的结构：

```text
PetCalibrationV1
├─ schemaVersion: 1
├─ breathAmplitudePercent: 0..5
├─ blinkIntervalScale: 0.5..2.0
└─ feedbackStrength: 0..1
```

- Rust command 接受 `pet_id`，验证范围后返回结构化对象，不再传递未解析 JSON 字符串。
- 存储 key 为 `pet:{pet_id}:calibration`，或迁移到等价的专用表；无论选择哪种，必须按宠物隔离。
- 当前活动宠物切换后加载对应校准；没有记录时使用默认值。

### 7.3 实时应用

- 设置页修改滑杆时通过事件发送临时校准值给 pet 窗口。
- pet runtime 将参数注入统一 presentation 接口，不能只影响遗留 Pixi renderer。
- 呼吸参数控制真实呼吸变形。
- 眨眼参数控制真实 blink 调度。
- 点击反馈控制真实点击动画强度。
- 保存提交当前临时值；取消恢复进入页面前的值；恢复默认立即预览但需显式保存。
- 切换宠物、关闭设置或运行时重载时必须清理临时预览状态。

### 7.4 入口收敛

- 校准界面整合进 settings。
- 托盘“校准”打开 settings 的校准页并聚焦当前宠物。
- 删除或停止使用固定测试图片的独立原型入口。
- 正式构建必须包含所有实际使用页面，避免开发服务器可用而 release 丢失。

## 8. 阶段 D：陪伴模式与桌面模式

### 8.1 模式定义

**陪伴模式：** 顶层透明工具窗口，TOPMOST、NOACTIVATE；普通窗口不能遮住宠物；全屏抑制时隐藏。

**桌面模式：** 宠物位于桌面层或兼容置底层，普通窗口覆盖宠物，桌面未被覆盖的区域可见；仍允许命中区域内点击和拖动。

### 8.2 正交状态

```text
desiredMode      = companion | desktop
userVisibility   = shown | manuallyHidden
suppressionSet   = fullscreen | lockSleep | virtualDesktopMismatch | ...
desktopHostState = unsupported | probing | workerW | bottomFallback | lost
```

派生规则：

- `effectiveVisible = userVisibility == shown && suppressionSet 为空`。
- 托盘显示/隐藏只修改 `userVisibility`。
- 全屏退出只移除 `fullscreen`，不能覆盖手动隐藏。
- hidden 时统一暂停 renderer；显示前恢复模式、位置、尺寸和命中区。
- `RenderTier::companion` 与无惩罚 `CompanionPolicy` 是渲染/行为概念，不参与窗口模式状态机；实现中应避免继续混淆命名。

### 8.3 桌面模式双策略

1. 探测标准 Explorer 桌面宿主并尝试 WorkerW/Progman 正式路径。
2. 保存原 parent、style、exstyle、rect 和 Z 序恢复信息。
3. 应用桌面宿主后进行可见性和坐标验证。
4. 正式路径不可用时，恢复原窗口状态，再尝试明确标注的兼容置底模式。
5. 两条路径均失败时，完整回滚陪伴模式并向 UI 返回可解释错误。

不能在半 reparent 状态下继续运行。Explorer 重启使 host 进入 `lost`；重绑失败则回滚陪伴模式。

### 8.4 出现判定

- 陪伴模式：用户未隐藏、没有抑制原因时可见。
- 桌面模式：除上述条件外，桌面宿主必须健康。
- Show Desktop、Explorer 生命周期、虚拟桌面切换和全屏是不同事件，不能互相冒充。
- 全屏判定继续以宠物所在显示器为主；多屏策略必须有自动测试和实机清单。
- 兼容置底模式必须在 UI 中标明兼容性，不伪装为 WorkerW 正式模式。

### 8.5 UI 与持久化

- 托盘提供可点击的“陪伴模式”和“桌面模式”。
- settings 同步显示当前 requested mode、实际 applied strategy 和降级原因。
- 模式切换只有收到后端成功回执后才更新持久化偏好。
- 启动恢复失败时默认回到陪伴模式，不能让宠物永久不可见。

## 9. 错误处理与恢复

- 所有资料、校准、尺寸和模式写操作必须有 request id 或等价幂等边界。
- 数据库迁移失败不改变 `user_version`，且保留原数据。
- 抠图质量失败保留原图和会话，不自动安装损坏资产。
- 尺寸应用失败回滚最后确认尺寸。
- 校准临时预览失败不覆盖持久值。
- 桌面模式失败原子回滚陪伴模式。
- 任一恢复流程不得覆盖用户手动隐藏意图。

## 10. 测试与验收

### 10.1 自动测试

- 迁移：新库、v6 升级、带历史额外列的旧库、回滚和幂等。
- 资料：名称 Unicode 边界、性别枚举、未来生日、并发删除冲突。
- 尺寸：50%/100%/150%、底部中心锚点、工作区 clamp、混合 DPI 换算、命中区刷新失败。
- 校准：按宠物隔离、范围验证、临时应用、取消回滚、切宠清理。
- 抠图：浅色主体、深色特征、原生 alpha、结构化质量原因、前后端和 finalization 双重拒绝。
- 模式：状态机组合、手动隐藏优先级、全屏进出、WorkerW 成功、正式路径失败后 bottom fallback、两者失败回滚、Explorer host lost。

### 10.2 Windows 手工验收

- 编辑资料后重启仍存在，切换宠物后资料不串。
- 尺寸实时变化，位置不跳、透明区穿透准确、重启恢复。
- 三个校准参数对真实当前宠物可见，取消与默认值正确。
- 陪伴模式不抢焦点且保持置顶。
- 桌面模式普通窗口可覆盖，Win+D、Explorer 重启和失败回滚行为有记录。
- 手动隐藏后进入并退出全屏，宠物不得自行显示。
- 白色/浅色候选质量失败时不能完成创建，原图仍可查看并可重试。

### 10.3 发布闸门

- 各阶段自动测试通过。
- 对应手工清单完成或明确记录未验证环境。
- 不新增无消费者的设置字段、灰色占位菜单或只在开发服务器存在的页面。
- 不把 `needs-review` 资产安装为正式运行资产。
- 桌面模式无法验证的环境必须显示降级策略和原因，不能宣称正式路径成功。

## 11. 实施约束

- 先修迁移版本耦合，再追加资料相关迁移。
- 保留现有用户数据和原始生成文件。
- 不触碰与本轮无关的工作区修改。
- 每阶段先建立失败测试，再实现最小修复。
- 完成每阶段后进行独立代码审查和合并后验证。
