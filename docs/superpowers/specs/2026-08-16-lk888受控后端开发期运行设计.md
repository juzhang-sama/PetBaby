# lk888 受控后端开发期运行设计

## 1. 结论

照片分身开发阶段新增一个可部署的受控后端服务。服务在本机 QA 时只监听 `127.0.0.1`，后续生产阶段再补域名、TLS、部署、监控和密钥托管。桌面应用继续只连接 `ControlledBackendProvider`，不得读取或保存 `LK888_API_KEY`。

真实供应商为 `lk888.ai` 聚合平台。远端模型分工固定为：

- `gpt-4o`：`analyzeIdentity` 与 `completeAppearance`；
- `gpt-image-2`：`renderTextureAtlas`。

用户已明确接受：lk888 当前没有公开删除 API，公开保存期限和隐私政策版本也无法核验。开发期可以使用已授权的非人类宠物照片继续真实验收，但产品必须显式披露该风险，不能把本地或自有后端删除表述为 lk888 上游已删除。

## 2. 范围

本阶段包含：

- 可独立启动、可后续部署的照片分身受控后端；
- lk888 文本/视觉分析和图像生成适配；
- 桌面端开发期安全连接方式；
- 身份中立的三体型 UV 引导；
- 同意版本升级、清理结果分域记录和真实调用审计；
- Task 13 首只角色与第二体型的本地完整 UI 验收。

本阶段不包含：

- 公网域名、正式 TLS 证书、云部署、弹性伸缩、告警和生产密钥托管；
- 承诺 lk888 上游图片已删除；
- 四方向边缘藏身、音效或领养猫；
- 把开发期本地后端描述为已上线的生产服务。

## 3. 服务位置与组件

在现有 `services/appearance-generation` 下新增 `photo_avatar_backend` Python 包，复用当前 Python/httpx 供应商实验基础，但不复用旧单图候选编排。

组件职责：

1. `contracts`：严格解析桌面端既有 `/v1/photo-avatar/*` JSON 合同，拒绝未知字段、未知步骤、越界图片和空标识。
2. `auth`：校验桌面端专用 bearer token；日志不得输出 token、原图 base64 或完整 prompt。
3. `jobs`：保存本进程内的轻量 session/job 状态、步骤结果和临时 artifact；相同幂等键不重复提交 lk888。
4. `lk888_client`：分别封装 OpenAI 兼容文本接口与现有媒体生成接口，统一错误分类。
5. `identity_pipeline`：用 `gpt-4o` 输出严格的 `AppearanceProfileV1` 和补全结果。
6. `atlas_pipeline`：用 `gpt-image-2` 根据照片、已验证 profile 和身份中立 UV 引导生成目标体型 atlas。
7. `cleanup`：删除自有后端 job、临时 artifact 和可下载地址；把 lk888 上游状态记录为 `unsupported`。

服务测试态使用内存 job store；开发期真实 QA 使用受控临时目录，进程重启后只允许恢复不含原图的轻量 job 元数据。原图不写入日志、数据库或长期缓存。

## 4. HTTP 合同

保持桌面端已经冻结的路径：

- `POST /v1/photo-avatar/steps`
- `GET /v1/photo-avatar/jobs/{jobId}`
- `POST /v1/photo-avatar/jobs/{jobId}/cancel`
- `DELETE /v1/photo-avatar/sessions/{providerSessionId}`
- `GET /v1/photo-avatar/artifacts/{artifactId}`

提交接口立即返回本后端的 `providerSessionId` 和 `jobId`。后台任务只执行请求中的一个步骤；桌面端 manager 仍是三步骤、三次总尝试和 revision 隔离的唯一编排真相。

开发期允许 HTTP 的条件必须同时满足：

- Rust 为 debug 构建；
- URL host 精确为 `127.0.0.1` 或 `localhost`；
- 显式设置 `PHOTO_AVATAR_ALLOW_INSECURE_LOOPBACK=1`。

release 构建和非回环地址始终只接受 HTTPS。该开关不得绕过 bearer token。

## 5. 模型数据流

### 5.1 身份分析

`analyzeIdentity` 把 1–8 张规范化 PNG 和固定系统约束发送给 lk888 的 `gpt-4o`。响应必须是严格 JSON，并经过与 Rust 相同的字段、来源、证据照片 ID、唯一 trait 和体型白名单校验。

模型观察到的字段标记为 `user`，并引用至少一个 `evidencePhotoId`；无法从照片确定的字段不得在本步骤伪造证据。

### 5.2 外观补全

`completeAppearance` 接收上一阶段 profile、照片和允许的三个体型模块。模型只补全缺失字段，来源固定为 `ai-completed`，并把对应键写入 `completionSummary`。体型证据不足时必须显式标记 AI 推断，不允许静默选择均衡型。

局部修改必须把锁定字段原样带入，后端和桌面端都重新执行 lock 校验。

### 5.3 纹理生成

`renderTextureAtlas` 使用 `gpt-image-2`，输入包括已验证 profile、原始宠物照片和目标模块的身份中立 UV 引导。

身份中立 UV 引导必须：

- 保持模块需要的画布尺寸、透明区域和 UV 岛位置；
- 只使用角色区域标签、透明度和边界提示；
- 不包含标准猫的脸、毛色、花纹、眼色、鼻口细节或中性纹理像素；
- 分别绑定 `body-slender-v1`、`body-balanced-v1`、`body-rounded-v1` 的合同哈希。

生成结果必须通过尺寸、PNG 解码、alpha、SHA-256、最大字节数、标准猫纹理不相等和可见差异门槛。任一失败按现有 provider 错误分类返回，不允许回退到标准猫、v3 或静态 PNG。

## 6. 隐私告知与清理语义

同意版本升级为 `photo-avatar-third-party-ai-lk888-no-delete-v2`。首次使用必须明确显示：

- 照片将发送给 `lk888.ai`；
- `gpt-4o` 用于身份分析和资料补全，`gpt-image-2` 用于纹理生成；
- lk888 当前没有公开删除 API，保存期限和隐私政策版本未核验；
- PetBaby 会在终态立即删除本地与自有后端副本，但无法承诺 lk888 上游副本已删除。

清理结果分为三个域：

| 域 | 终态动作 | 可声明结果 |
|---|---|---|
| 桌面本地 | 删除规范化原图、preview staging 中非安装产物 | `deleted` 或 `pending` |
| 自有受控后端 | 删除 session/job/artifact 和下载地址 | `deleted` 或 `pending` |
| lk888 上游 | 无公开删除 API | 固定为 `unsupported`，不得写 `deleted` |

现有 `cleanupPending` 只表示前两个可控域仍有删除失败；lk888 的 `unsupported` 不造成无限重试。接受 v2 风险告知后，前两个域清理完成即可把本地 run 标记为 `completed`，同时在审计记录和 Task 13 验收中保留上游风险。

SQLite 需要新迁移以允许 v2 同意版本，并保存供应商、模型路由、上游清理能力和当次告知摘要哈希。旧 v1 同意不能自动等同于 v2，同一用户必须重新确认一次。

## 7. 调用和费用边界

每只角色正常路径为：两次 `gpt-4o` 步骤和一次 `gpt-image-2` 步骤，共 3 次远端提交。每个步骤最多三次总尝试，因此单只角色最多 9 次、Task 13 两只角色最多 18 次。

即使用户未设置业务费用上限，以下工程限制仍不可放宽：

- 轮询不重复提交；
- 相同 session/revision/step/attempt 使用幂等键；
- 不可重试错误立即停止；
- 达到三次总尝试后失败关闭；
- 每次提交、结果、模型、task ID 和可取得的计费字段写入不含照片的审计日志；
- lk888 未返回单价或用量时，验收记录必须写“供应商未提供可核验计费明细”，不能估造费用。

## 8. 错误与取消

lk888 HTTP、协议和模型响应映射到现有九类错误。结构化 JSON 错误、未知体型、锁定字段变化、atlas 尺寸或哈希异常均按不可安装处理。

取消分两层：

- 自有后端立即停止未提交任务、停止继续轮询并删除本地 artifact；
- lk888 已提交任务没有公开取消能力时记录 `upstreamCancel=unsupported`，不得声明远端任务已取消。

迟到响应必须按 session、revision、step、attempt 和 job ID 隔离，不能覆盖新 revision，也不能重新创建已删除的下载地址。

## 9. 测试与验收

实现严格遵循 RED、GREEN、REFACTOR：

1. 合同测试：鉴权、未知字段、步骤路由、幂等、错误分类和路径编码。
2. wiremock/fake lk888 测试：结构化分析、补全、图片任务、轮询、迟到响应、取消不支持和上游删除不支持。
3. UV 引导测试：三体型尺寸/hash 固定，不含标准猫纹理像素，生成 atlas 与标准猫纹理不相等。
4. 清理测试：本地和自有后端删除成功/失败可恢复，lk888 `unsupported` 不被误写为成功且不造成无限 `cleanupPending`。
5. debug loopback 安全测试：只有显式开关加回环地址可用 HTTP，release/非回环仍拒绝。
6. 无照片探针：启动真实后端，验证鉴权、健康检查、空 session 删除和临时 artifact 删除，不调用 lk888 生成。
7. Task 13 真实验收：只从完整桌面 UI 选择已授权的 8 张宠物照片，记录实际调用数、task ID、可取得的费用信息、两体型 v5 包、八动作、两种打断和三域清理状态。

任何真实调用失败、身份不相似、atlas 错位、动作穿帮或清理失败都必须停止并回到对应实现任务，不进入第二体型或边缘藏身。

## 10. 阶段完成定义

开发期阶段只有同时满足以下条件才可关闭：

- 受控后端合同、模型路由、身份中立 UV 引导和 v2 风险同意均有自动化证据；
- 真实 UI 链路完成首只角色和不同体型第二角色；
- 本地与自有后端副本清理有证据；
- lk888 上游删除明确记录为 `unsupported`；
- 全量前端、Rust、Python、typecheck、build、格式和 diff 检查通过；
- 验收文档明确写“开发期本地后端已验证，生产域名/TLS/部署未完成”。

生产域名、TLS、部署、监控、生产密钥托管和正式供应商合同作为后续独立运维阶段，不阻塞本地开发验证，但阻塞“生产服务已上线”的声明。
