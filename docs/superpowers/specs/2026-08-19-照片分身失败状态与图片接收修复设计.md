# 照片分身失败状态与图片接收修复设计

## 背景与目标

当前照片分身链路存在四个相互关联的问题：旧失败草稿会在首次进入创建页时恢复；“取消创建”只取消照片运行而不放弃创建草稿；取消状态可能被迟到的后台失败覆盖；LK888 已成功返回的图片会因本地透明边距和半透明像素合同不匹配而被拒绝，并被错误分类为可重试的 provider 故障，造成重复付费生成。

本次修复的目标是：新进入创建页时不显示已结束会话的旧错误；取消后彻底结束本次创建；迟到结果不能复活已取消任务；成功下载的 GPT-image-2.0 图片经过确定性标准化后进入本地审计；机械审计失败不得触发新的 LK888 任务；用户能够看到安全且有实际意义的错误提示。

## 会话生命周期

- 用户点击“取消创建”时，先取消照片分身运行，再调用创建服务的 `abandon` 完整放弃草稿并清理会话资源，最后返回创建方式首页。
- 进入上传路线时，如果恢复到的照片运行已经是 `failed` 或 `cancelled`，则将其视为已结束会话：放弃旧草稿，并启动新的上传会话。首次进入的新会话必须处于 `collecting`，不得携带旧错误或旧文件选择。
- 用户主动点击“重新生成”仍表示在当前会话中创建新 revision，不走自动清理逻辑。
- 后台线程提交状态时必须带 revision 与当前状态约束。已经进入 `cancelled`、`completed` 或被新 revision 取代的运行，不得被迟到线程写回 `failed`。

## 图片标准化与审计

LK888 返回的原始 PNG 在进入现有机械审计前执行确定性标准化：

1. 解码为 RGBA 并确认存在可见主体。
2. 根据 alpha 可见区域裁切主体。
3. 将主体等比缩放到目标画布内，四周保留不少于 4% 的透明安全区。
4. 将 alpha 确定性二值化，消除模型输出的大面积抗锯齿半透明像素；完全透明像素的 RGB 归零。
5. 居中放回原尺寸透明画布，再运行现有尺寸、边距、连通主体和透明度审计。

标准化只改变背景边界与透明度表达，不重绘猫的颜色、纹理、五官或轮廓语义。原始 provider 哈希与标准化后哈希分别记录，保持审计可追溯性。

## 错误分类与重试

- 网络中断、超时、LK888 5xx 和 provider 明确声明的临时不可用继续允许重试。
- PNG 解码、尺寸、主体、透明边距、半透明和连通性等本地合同错误归类为非重试的输出不合格，不得再次调用 LK888。
- 本地后端保存安全的结构化错误码和面向用户的中文消息；详细技术原因只写本地日志，不包含照片、提示词、密钥或 provider URL。
- Rust 不再把所有后端失败压缩成同一句 `photo avatar provider failed`，而是保留安全错误码与消息供前端展示。
- 前端针对输入错误、输出不合格、网络/超时和其他失败显示不同提示。

## 验证范围

实施采用最小回归验证，不触发新的 LK888 生成：

- TypeScript：旧失败草稿进入时自动放弃并创建新会话；取消同时调用照片取消和创建放弃；新会话清空旧文件与错误。
- Rust：取消后的迟到失败不能覆盖 `cancelled`；本地审计错误不得触发第二次远程提交；网络类错误仍按上限重试。
- Python：使用已存在的三张 LK888 历史成功图片验证标准化后通过机械审计；验证本地合同错误返回非重试分类；验证日志与持久化错误不泄露敏感数据。
- 运行必要的聚焦测试、TypeScript 类型检查和相关 Rust/Python 测试。完整桌面真实生成闭环留给用户手动测试，且只有用户再次明确授权时才允许触发新的 LK888 请求。

## 不在本次范围

- 不调整照片分身的视觉提示词或项目风格。
- 不删除审计门，也不接受未经标准化的任意 provider 图片。
- 不修改三次总尝试的产品规则，只修正哪些错误有资格重试。
- 不处理其他创建路线或无关的 Live2D、标准猫功能。
