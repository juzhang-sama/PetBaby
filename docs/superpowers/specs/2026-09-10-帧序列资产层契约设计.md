# 帧序列资产层契约设计（schema 7 进入 Rust 资产层）

**目标**：让 Rust 资产层能够表示、校验并安装 `frame-sequence-v1`（schemaVersion 7）资产，
使「用户上传的宠物」在原理上具备走通帧序列运行时的可能。

## 背景：为什么这是通用性的第一根因

产品目标是「用户上传任意猫/狗照片 → 生成与内置宠物（04/05）同等视觉与互动效果的桌宠」。
核实后的现实是**两条物理隔离的路径**：

| | 内置宠物 04/05 | 用户上传宠物 |
| -- | -- | -- |
| 位置 | `apps/desktop/public/builtin-pets/<petId>/` | Rust 安装目录 |
| 解析方 | **TypeScript** `parseFrameSequenceManifest` | **Rust** `validate_asset_directory` → `parse_manifest` |
| 产物 schema | 7（帧序列） | 3（`animated-image-v1` + life-v1 运动档） |

`parse_manifest` 只接受 schema 1/3/4/5，对 7 直接返回 `unsupported schemaVersion`；
`ALLOWED_EXTENSIONS` 甚至不含 `.webp`（帧序列资产的编码）。
因此用户资产**无论怎样生成都无法成为 schema 7 资产** —— 生成出来也会在校验层被判 Corrupt。
缺口不在运行时（`pet-renderer-bootstrap.ts` 早已支持 schema 7），而在**资产层不具备该类型**。

## 结论

新增 `apps/desktop/src-tauri/src/runtime_assets/frame_sequence.rs`，
承载 schema 6/7 的类型与解析；`parse_manifest` 把 6 与 7 一并归一化为 `RuntimeAssetManifest::V7`。

**契约纪律：与前端 `src/runtime/frame-sequence-manifest.ts` 逐条同构。**
校验顺序、错误文案、宽松度全部对齐，且**刻意不做比前端更严格的检查**
（例如不校验 `idleSchedule` 里的 `actionId` 是否真的被声明）。
理由：同一份 manifest 在内置播放路径（TS）与用户安装路径（Rust）必须给出同样的接受/拒绝结论；
一侧更严会造成「装上但渲染不出来」的静默分裂。要加严必须两侧同时加。

## 边界

- 本切片只解决**资产层契约**：解析、校验、路径归一化、schema 6→7 归一化。
- **不**新增帧序列的生成/打包能力，**不**改用户上传链路，**不**接入 AI 视频。
- 不改变 schema 1/2/3/4/5 的既有行为（`validate_files` 等原有校验保持原样）。
- 归一化规则：`schemaVersion` 6 与 7 都解析成 `7`；路径统一成正斜杠；`sha256` 统一小写。
- `blink` 保留为 schema 6 兼容字段；未声明 `idleSchedule` 时由 `blink` 推导出眨眼条目。

## 数据流

```
manifest.json
  -> parse_manifest (按 schemaVersion 分派)
  -> parse_frame_sequence_manifest
       -> validate_frame_sequence（顺序/文案对齐 TS 校验器）
       -> serde 反序列化为 RuntimeAssetManifestV7
       -> 归一化：schemaVersion=7、路径正斜杠、sha256 小写、blink→idleSchedule
  -> validate_asset_directory（逐个文件比对 sha256）
  -> 安装
```

## 验收

以**真实内置资产**为主要验收依据（不用人造样例替代）：

- 04 `idle-combo/yawn/lick`：287 帧、`idleSchedule` 两条 + `alignToDefaultLoop`
- 05 含 `grab-release`：81 帧、`holdRange [30,59]`、`carried`/`landed` 语义
- 01/02/03/04/05 全部：每个动作的每一帧都实际出现在 `files` 清单中
- `validate_asset_directory` 对真实 01/04/05 资产目录（64+525+607 个文件）通过
- 反向：篡改帧内容、删除帧文件、`sha256` 非法、`.jpg` 帧、路径穿越、`holdRange` 越界、
  `species` 非 cat/dog 等情况必须被拒 —— 确认校验不是"看见 schema 7 就放过"

## 明确不在本切片内宣称完成的能力

用户上传的狗／猫图像生成、动作帧生成、AI 视频与抠像链路的产品化、真实桌面安装闭环 ——
以上均未被本切片验证，仍属未完成。
