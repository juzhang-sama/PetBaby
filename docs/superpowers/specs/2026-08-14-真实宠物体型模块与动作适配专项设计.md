# 真实宠物体型模块与动作适配专项设计

## 1. 文档状态

- 日期：2026-08-14
- 状态：设计已确认
- 适用范围：猫咪照片分身角色包、公共 Live2D 动作底座与动作回归
- 上位设计：`docs/superpowers/specs/2026-08-12-猫咪形象与动态视觉专项设计.md`
- 决策来源：用户明确指出不同真实宠物身体比例会改变呼吸、眨眼、耳动和尾根的实际作用位置；固定画布与固定范围会造成错位。
- 2026-08-15 方向校准：体型证据不足时允许 AI 补全并记录来源，不再中途要求用户确认；完整动态角色完成后统一预览。照片流程、供应商隐私和阶段顺序以 `docs/superpowers/specs/2026-08-15-真实宠物照片分身生成方向校准设计.md` 为准。本文第 5 节低置信处理、第 8 节数据流和第 11 节执行顺序中与新规格冲突的内容已被取代。

## 2. 修正后的产品方向

真实宠物照片生成是产品主线。标准猫只用于验证资源结构、动作调度、60 FPS、窗口交互和边缘动态尾巴等公共技术能力，不证明真实宠物身份、体型或动作适配已经成功。

照片分身猫必须同时满足三类保真：

1. **身份保真**：毛色、花纹、脸型、耳形、眼型、眼睛颜色、局部标记和整体气质可辨认。
2. **体型保真**：不得把明显纤细或圆润的宠物统一改造成标准猫身材；正面坐姿与平衡构图不等于统一身体比例。
3. **动作保真**：眨眼、呼吸、耳动、尾动和伸展必须作用在该角色自己的生理位置，且不超出自己的安全幅度。

领养猫是后置支线。在首只真实照片分身猫通过完整链路且至少两个不同身体模块完成交叉体型回归前，不制作六只领养猫。

## 3. 方案选择

### 3.1 采用方案：统一语义、有限体型模块、角色级空间档案

- 统一 `cat-a-live2d-v1` 动作语义：动作名、参数含义、状态优先级和归一化输入保持一致。
- 首期提供有限的预绑定身体模块，而不是从任意照片自动生成完整网格。
- 每个模块独立绑定网格、变形器、轴心和参数端点。
- 每个正式角色包携带自己的 `MotionSpatialProfileV1`，描述动作实际作用区域和安全幅度。
- 每只照片分身猫安装前执行角色级视觉回归。

该方案在保留真实体型差异的同时，避免首期承担“任意照片自动拆层绑骨”的高风险承诺。

### 3.2 不采用方案

1. **所有宠物缩放进同一骨架并共用固定像素范围**：实现简单，但必然导致胸腹、眼睑、耳根或尾根错位。
2. **每张照片自动生成一套完整 Live2D 网格和骨骼**：理论自由度最高，但首期缺乏可预测性、可复验性和稳定质量，不作为产品承诺。

## 4. 标准化边界

### 4.1 必须统一

- 画布坐标系和正面坐姿构图规范。
- 动作语义版本 `cat-a-live2d-v1`。
- 八组动作名称、调度优先级、打断和回退规则。
- 参数的归一化输入范围与角色包校验方式。
- 证据录制格式、失败判据和安装门槛。

### 4.2 不得强制统一

- 身体宽高比例、胸腹宽度和四肢相对长度。
- 眼睛、耳根、尾根等部位的实际像素坐标。
- 呼吸、伸展、耳动和尾动对应的网格范围。
- 不同体型和毛长的动作最大形变量。

固定画布只用于交换资源；任何运行时都不得从画布尺寸推导呼吸或眨眼区域。

## 5. 首期形体模块

首期身体模块精确限定为：

| 模块 ID | 用途 | 约束 |
| --- | --- | --- |
| `body-slender-v1` | 明显纤细、胸腹较窄、四肢观感修长 | 呼吸集中于胸腔，横向幅度最小 |
| `body-balanced-v1` | 中等身材、比例均衡 | 作为标准猫迁移基准，但不是其他体型的默认强制回退 |
| `body-rounded-v1` | 胸腹较宽、轮廓圆润 | 呼吸区更宽，限制整体横向拉伸，避免腹部橡胶化 |

脸、耳、眼、尾模块必须声明 `compatibleBodyModuleIds`。长毛首先作为兼容外观/轮廓模块处理；若长毛轮廓改变关键网格或轴心，则必须新增独立的已绑定模块版本，不能只替换贴图。

照片分析输出必须包含 `bodyModuleId`、证据来源和置信度。无法落入白名单模块时：

- 有明确身体证据时，按照片选择最合适的白名单模块。
- 身体资料不足时，由 AI 推断并补全合理体型，来源记录为 `ai-completed`，最终预览明确说明。
- 只有输入无法支持合理生成或不属于产品范围时才停止。
- 禁止用 `body-balanced-v1` 静默吞掉未知体型。

## 6. `MotionSpatialProfileV1`

### 6.1 坐标系统

所有空间坐标使用相对于 Live2D 逻辑画布的归一化坐标 `[0, 1]`。档案必须声明实际画布宽高用于证据换算，但画布宽高不是动作区域。

```ts
interface NormalizedPointV1 { x: number; y: number }
interface NormalizedRectV1 { left: number; top: number; right: number; bottom: number }

interface MotionSpatialProfileV1 {
  schemaVersion: 1;
  bodyModuleId: "body-slender-v1" | "body-balanced-v1" | "body-rounded-v1";
  canvas: { width: number; height: number };
  alphaBounds: NormalizedRectV1;
  faceSafeZone: NormalizedRectV1;
  eyes: {
    left: { center: NormalizedPointV1; bounds: NormalizedRectV1 };
    right: { center: NormalizedPointV1; bounds: NormalizedRectV1 };
  };
  earRoots: { left: NormalizedPointV1; right: NormalizedPointV1 };
  breathZone: NormalizedRectV1;
  stretchAxis: { origin: NormalizedPointV1; direction: NormalizedPointV1 };
  swayPivot: NormalizedPointV1;
  tailRoot: NormalizedPointV1;
  edgeTailBounds: NormalizedRectV1;
  amplitude: {
    breath: { min: number; max: number };
    blink: { min: number; max: number };
    ear: { min: number; max: number };
    tailAngle: { min: number; max: number };
    tailCurl: { min: number; max: number };
    tailTip: { min: number; max: number };
    bodyStretch: { min: number; max: number };
  };
}
```

### 6.2 几何约束

- 所有点和矩形必须位于 `[0, 1]`，矩形必须具有正面积。
- 双眼 bounds 必须位于 `faceSafeZone` 内，左右顺序不得颠倒。
- `breathZone` 不得与双眼 bounds 正面积重叠，且必须位于主体轮廓内。
- 耳根必须位于主体上部；尾根必须同时接近主体与独立尾巴的连接区。
- `edgeTailBounds` 只能覆盖独立尾巴 ArtMesh 的可见范围，不能包含身体。
- 所有 amplitude 最小值必须小于最大值，且不得超过对应形体模块模板的批准范围。

## 7. 角色包版本与兼容性

- 现有 manifest v1–v4 继续兼容加载，不能因本次方向修正而使已安装宠物失效。
- 新增 manifest v5 `cat-spatial-live2d-v1`，在 v4 能力上增加 `bodyModuleId` 和 `motionSpatialProfile` 文件引用及哈希。
- 标准猫从 v4 迁移为 `body-balanced-v1` 的 v5 基准包；迁移完成前，当前 v4 包只用于 Task 8 公共底座回归。
- 所有新照片分身猫只允许构建 v5；builder 缺少档案、模块未知、坐标越界或幅度越界时必须失败，不能降级成 v4 后安装。

## 8. 生成与运行时数据流

1. 本地质量门槛确认照片可安全解码、主体唯一且输入属于产品范围。
2. 照片分析输出结构化身份特征、缺失资料、体型候选、置信度和 `user` / `ai-completed` 来源。
3. 生成服务依据原图和锁定身份特征补全缺失区域，生成 A 风格正面坐姿完整外观与动作所需素材，不直接生成任意 Live2D 网格。
4. builder 选择白名单形体模块，写入专属外观层和角色级 `MotionSpatialProfileV1`，完成完整动态角色。
5. v5 校验器验证路径、哈希、模块兼容、空间几何和幅度；真实运行时动作证据通过后才进入最终统一预览。
6. 用户在最终预览接受后原子安装；重新生成或局部修改不把半成品加入宠物目录。
7. 运行时读取角色自己的档案，将统一动作输入夹紧到该角色安全幅度；不得使用全局固定像素区域。

## 9. 动作适配规则

- **呼吸**：作用于角色自己的 `breathZone` 和模块绑定网格；脸部安全区不得出现局部形变。不同模块允许使用不同幅度。
- **眨眼**：分别作用于左右眼睑网格；不按画布坐标移动整张眼睛贴图，不得出现眼球穿睑。
- **耳动**：围绕各自 `earRoots` 发生，耳根不得产生透明洞或脱离头部。
- **尾巴**：围绕 `tailRoot`，使用独立尾巴 ArtMesh；普通动作和边缘藏身复用同一条尾巴。
- **身体伸展**：沿 `stretchAxis` 发生，幅度受模块档案夹紧；不得把整只猫等比缩放当作伸展。
- **长毛轮廓**：毛边允许随已绑定网格轻微运动，但不得出现直线拉伸、重复纹理或橡胶化。

## 10. 验收门槛

### 10.1 模块级

三个身体模块分别通过：中性首帧、动作峰值、回退帧、五帧序列、局部安全区和四方向尾巴。缺任一证据，该模块不得用于照片分身。

### 10.2 角色级

每只照片分身猫都必须重新验证：

- 呼吸只在胸腹产生可见但温和的变化。
- 脸部安全区稳定，双眼闭合准确。
- 双耳从耳根自然运动。
- 尾根连续，尾巴独立运动。
- 伸展没有纹理拉花或身体错位。
- 用户抚摸和拖拽立即、平滑地打断自主动作。
- 四边藏身时身体完全在屏幕外，只保留可命中、持续运动的尾巴。
- 角色包以约 60 FPS 运行，无静态降级。

### 10.3 发布级

首只真实照片分身猫完整通过是主线最低门槛；正式宣称“不同体型适配”前，至少使用两个不同身体模块完成同能力交叉回归。领养猫不能替代这两项证据。

## 11. 执行顺序修正

1. 完成标准猫 Task 8，验证公共动作播放链。
2. 建立 v5、三个体型模块和 `MotionSpatialProfileV1`。
3. 使用 `body-balanced-v1` 迁移标准猫，并重新验证动作空间。
4. 完成照片输入、AI 补全、完整动态 v5 角色构建和最终统一预览。
5. 完成至少一只真实照片分身全流程。
6. 补第二种身体模块交叉体型回归。
7. 再完成边缘藏身公共底座，保持身体全离屏、只留动态尾巴。
8. 最后处理可选通用音效和六只领养猫支线。

## 12. 非目标

- 首期不支持无限连续体型、猫以外动物或任意姿态。
- 不承诺从单张遮挡照片恢复不可见的精确骨骼比例。
- 不为每张照片自动创建任意新骨架。
- 不使用整图缩放、固定像素矩形或标准猫坐标冒充角色级动作适配。
