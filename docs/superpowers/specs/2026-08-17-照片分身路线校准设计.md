# 照片分身路线校准设计

日期：2026-08-17

状态：待用户审阅

适用工作树：`D:\petBaby\desktop-pet\.worktrees\cat-visual-runtime`

## 1. 校准结论

PetBaby 不更换 Tauri、Cubism Web SDK、`Live2DRenderer` 或现有行为系统。当前真正需要校准的是“照片身份外观如何进入预绑定 Live2D 模块”的资产生产链。

正式路线冻结为：

```text
用户照片
  ↓
身份特征提取与来源标记
  ↓
完整、正面坐姿的 A 风格身份参考图
  ↓
选择 body module
  ↓
按固定语义模板分别重绘外观层
  ↓
确定性遮罩、扩边和 atlas 合成
  ↓
复用已验收 moc3、动作和空间档案
  ↓
真实 Live2D 动态预览
  ↓
用户确认后安装
```

模块决定“怎么动”；照片和 AI 决定“长什么样”。AI 不得决定 atlas 坐标、遮罩、零件前后关系或 Cubism 绑定。

## 2. 与旧路线的关系

旧的 2026-08-17 设计和实施计划证明了“不透明工作画布 + 确定性 alpha 合成”能够解决 provider alpha 不可信的问题，但真实样本证明它不能单独解决语义零件接缝、眼睑遮挡和身份映射问题。

因此：

- 旧方案中的透明拓扑、canonical hash、独立 Rust 复验和失败关闭语义继续保留。
- “provider 直接生成接近最终 atlas”不再是身份外观的正式生产方式。
- 本文件作为新路线的权威入口；旧文件只保留历史背景和已完成的确定性基础设施。

## 3. 组件边界

### 3.1 身份档案与参考图

输入一张或多张用户照片，输出：

- 结构化身份档案：毛色、花纹、眼色、脸型、耳形、体型、尾巴等；
- 每个字段的来源：`user` 或 `ai-completed`；
- 一张完整、正面、坐姿、A 风格的身份参考图。

参考图用于约束后续语义层外观一致性，不得直接作为桌宠纹理或静态成功降级。

### 3.2 Body module 选择器

只允许选择经过验收的 `body-slender-v1`、`body-balanced-v1` 或 `body-rounded-v1`。模块提供：

- 固定画布和语义槽位；
- UV、遮罩、锚点和接缝安全区；
- moc3、动作、空间档案和许可证；
- 体型选择的身份来源记录。

如果照片缺少体型证据，必须显式记录 `bodyModuleSource: ai-completed`，不得静默伪装为照片事实。

### 3.3 语义层重绘器

使用同一份身份档案和同一张参考图，围绕模块模板分别生成：

- 身体底层与胸腹；
- 脸部；
- 双眼与眼睑；
- 双耳；
- 前肢；
- 尾巴与尾根遮挡层。

每个语义层必须固定尺寸、锚点、遮罩和输出格式。AI 只能改变外观，不能改变零件位置、透明边界、层级或动作绑定。

被前肢、尾巴、眼睑遮住的底层区域由模板提供完整延展，不依赖模型临时猜测。

### 3.4 确定性合成器

程序负责：

- 对每个语义层应用模块权威遮罩；
- 裁掉越界像素；
- 在接缝安全区执行固定扩边规则；
- 按固定 atlas 坐标合成 canonical RGBA PNG；
- 复算 alpha、透明 RGB、尺寸、覆盖率和 hash。

合成器不做身份判断，不把标准猫纹理作为默认补丁，也不把 provider raw PNG 交给 builder。

### 3.5 v5 构建与动态预览

只复制已验收的模块 moc3、model3、动作和空间档案，替换经过 canonical 复验的专属纹理。预览必须使用真实 `Live2DRenderer`，不允许静态 PNG、GIF 或标准猫作为成功降级。

## 4. 失败与生命周期

- 每个语义层最多三次尝试；失败只重做对应语义层，但继续锁定其余身份字段。
- 尺寸、格式、遮罩越界、接缝、身份漂移、hash 或动态门失败时，当前尝试关闭，不生成可安装包。
- provider raw、原始照片和临时产物按终态立即清理；删除失败保留 `cleanupPending`，不得写成成功。
- 真实供应商的保存期限、删除 API 和价格未核实前，验收记录继续使用 `unverified`/`unsupported`，不得伪报供应商已删除。

## 5. 三层验收门

### 5.1 机器结构门

验证语义层完整性、尺寸、格式、遮罩、接缝安全区、atlas 引用、moc3/model3、动作、空间档案和 hash。任一失败都不能构建角色包。

### 5.2 真实动态门

使用真实 renderer 检查待机、八组动作、打断、回退和恢复。必须确认：

- 模型不是静态降级；
- neutral、peak、fallback 画面确实不同；
- `ParamBodyStretch` 等关键参数产生顶点或 framebuffer 变化；
- 眼睑、耳根、胸腹、前肢、尾根没有破洞、穿插或黑线；
- 动作结束后回到稳定坐姿。

### 5.3 用户确认门

向用户展示一套完整动态预览、身份摘要和来源标记。只有用户接受并完成安装，才算照片分身生成成功。

```text
机器通过 ≠ 生成成功
动态通过 ≠ 用户接受
用户接受并完成安装 = 最终成功
```

## 6. 当前范围与非目标

本轮只处理猫、正面坐姿、三种预绑定体型和现有八组微动作。独立 Live2D 绑定、任意姿势、边缘藏身、领养猫、声音和生产运维不进入本计划。

See-through、Bunraku、AutoLive2d 等作为研究或辅助工具，不成为基础版生产链的硬依赖；它们的输出仍必须经过本项目语义映射、确定性合成和真实动态验收。

## 7. 完成定义

只有以下条件全部满足，才允许恢复真实 20 样本矩阵：

1. 纤细型伸展参数通过真实顶点/framebuffer 变化门。
2. 语义层重绘和确定性合成在三体型模块上通过结构测试。
3. 一个新的受控真实样本通过机器结构门、真实动态门和人工视觉门。
4. 失败样本的原图、raw artifact 和远端清理状态得到正确处理。
5. 新计划的实现提交、测试证据和文档状态一致。
