## 2. 路线调整结论

本次改变技术路线的目的，是绕过照片分身在 Live2D 语义分层、atlas、UV、体型适配、moc3 构建、接缝和动作验收上的连续卡点，不是推倒 PetBaby 项目本身。

正式路线冻结为：

```text
保留成熟的照片分身外围系统
  ↓
停止继续投入 Live2D 照片分身视觉生产核心
  ↓
用完整像素宠物单图替换语义分层与 atlas
  ↓
复用并扩展 animated-image-v1 固定动作运行时
  ↓
动态预览、用户确认后安装
```

实施必须遵循三条原则：

1. 与 Live2D 无关且已经可靠的产品能力优先原位复用，不因新路线而重写。
2. Live2D 照片分身能力冻结保留，不删除，不再进入当前主路径。
3. 新像素路线使用独立、版本化的生成与运行合同，不伪装成 v5 Live2D 包。

## 3. 方案比较与选择

### 3.1 方案一：完整像素皮肤加整图变换

每只宠物只生成一张完整透明像素图，运行时通过整图位移、旋转、缩放、压缩、拉伸和已有局部呼吸切片表达动作。

优点：最稳定、无部件接缝、身份只生成一次、可以复用现有 `animated-image-v1`。缺点：眨眼、摆尾、走动等局部或大幅动作表现有限。

### 3.2 方案二：完整角色多帧动画

每个动作由若干张完整宠物帧组成，不做脸部贴片或身体零件拼装。

优点：动作更自然，仍能避免运行时部件接缝。缺点：每个动作都需要解决跨帧身份一致性、资产规模和生成成本，不能作为首版闭环的前置条件。

### 3.3 方案三：分阶段混合路线

首版采用方案一，先打通真实照片生成、质量检查、固定动作预览、重新生成、局部修改、接受和安装。后续只为高价值动作增加方案二的完整角色帧序列。

本项目选择方案三。任何阶段都禁止恢复“程序身体加 AI 脸部贴片”、语义部件拆分、逐宠物骨骼适配或逐帧独立生成整套身份不一致的动作。

### 4.2 统一项目视觉身份

所有正式像素分身必须满足：

- 高细节硬边像素风，不是极小低分辨率 sprite；
- 使用清楚的像素簇、有限色阶和明确轮廓塑形；
- 均衡 Q 版大头，头部约占全身高度 `38%～42%`，整体约 `1:2.5`；
- 身体紧凑但仍保留胸毛、脚袜、身体斑块和尾巴等身份信息；
- 眼睛允许适度强化，但不得改变真实眼色和主要形状；
- 保留真实宠物的脸型、耳形、毛色、脸部花纹、身体标记和尾巴特征；
- 固定为正面或轻微侧前方的完整宠物姿态；
- 透明背景，无场景、文字、装饰、投影或独立零件。

明确排除：

- 极小尺寸、信息不足的游戏角色 sprite；
- 通用圆脸幼儿图标；
- 把平滑插画缩小、马赛克化或套滤镜后冒充像素画；
- 极端大头导致不同宠物脸型趋同；
- 因风格统一而抹除真实身份特征。

- provider 提交、轮询、错误分类和幂等；
- 每个远端步骤最多三次总尝试；

- 取消、放弃、安装后的本地与受控后端清理；
- `user` 与 `ai-completed` 身份特征来源；
- 重新生成、局部修改、动态预览和显式接受；
- 最终安装、宠物切换和启动恢复。

### 5.2 改造复用

| 现有能力 | 像素路线中的处理 |
|---|---|
| 身份档案 | 保留来源与证据结构，调整为像素身份字段 |
| `renderTextureAtlas` | 替换为生成完整像素宠物单图 |

当前 `AnimatedImageRenderer` 主要具备待机能力，`setLookTarget` 等接口仍未完成。它是首版的稳定基础，不是完整固定动作库已经完成的证据。

### 5.4 冻结保留

- 照片分身专用 `.moc3`、Cubism 参数与动作绑定；

## 6. 总体架构

```text
用户照片
  ↓
既有照片校验、授权与临时存储
  ↓
身份特征档案
  - 脸型、耳形、眼色
  - 毛色与脸部花纹
  - 胸毛、脚袜、身体斑块、尾巴
  - user / ai-completed 来源
  ↓
项目像素风格档案 pixel-style-v1
  - 已认可视觉基准
  - 均衡 Q 版比例
  - 高细节硬边像素规则
  - 固定姿态、画布与透明背景
  ↓
lk888 + gpt-image-2
  ↓
完整像素宠物单图
  ↓
机械与生成合同检查
  ↓

  ↓
```

程序不理解或拼装脸、眼睛、耳朵、嘴巴、四肢和尾巴等语义部件。AI 每个 revision 生成一张完整宠物候选，同一候选图用于该 revision 的全部首版动作。

## 7. 版本化生成合同

每次生成必须持久化等价于下列信息的严格合同：

```text
PixelAvatarGenerationV1
├─ sessionId / revision / generationToken
├─ 用户照片 ID 与内容哈希
├─ 身份特征档案
│  ├─ 特征值
│  ├─ user / ai-completed 来源
│  └─ evidencePhotoIds 或 completionSummary
├─ styleProfileId: pixel-style-v1
├─ 视觉基准版本与哈希
├─ provider: lk888
├─ model: gpt-image-2
├─ 提示词模板版本与生成参数
├─ provider task ID 与可取得的审计信息
└─ 当前候选 ID、文件哈希与检查结果
```

提示词由四个互相隔离的区块组成：

1. 不可修改的项目风格；
2. 当前宠物身份特征及来源；
3. 完整单图、透明背景、画布和姿态输出合同；
4. 禁止项，包括场景、配饰、通用猫替换、平滑插画和身份特征漂移。

重新生成继续使用同一风格版本和身份档案。局部修改的含义是锁定未要求改变的身份字段后生成新的完整候选，不是只替换图片中的一个运行时部件。

## 8. 产物与质量门

生成源文件必须是一张完整宠物的透明背景 PNG。原始候选源文件与运行资产分开保存；运行资产只能进行确定性的边界归一化、整数比例缩放和最近邻采样。后处理不得把非像素插画转换成“伪像素风”。

质量门分为三层：

### 8.1 机械检查

- PNG 可安全解码；
- 尺寸、最大字节数和颜色格式在合同范围内；
- 存在有效 alpha，主体非空；
- 四足、耳朵和尾巴未被画布裁断；
- 主体位于安全边距内；
- 文件哈希与审计记录一致；
- 最近邻缩放后不存在新增半透明模糊边缘。

### 8.2 生成合同检查

- provider、模型、风格版本、提示词版本和身份档案齐全；
- 所有 `user` 特征都有照片证据；
- 所有 `ai-completed` 特征都进入补全摘要；
- 输出是单只完整宠物，无场景、文字、装饰和独立零件；
- 机械检查与必要运行产物全部存在。

缺失任一必要字段或产物时，候选不得进入动态预览。

### 8.3 用户身份确认

自动检查不能代替主人对“像不像”的判断。用户必须在完整动态预览中确认脸型、耳形、眼色、花纹、胸毛、脚袜、身体斑块和尾巴等身份特征，并选择接受、重新生成或描述需要修改的地方。

## 9. 状态与数据流

像素路线采用明确状态，不继续使用带 Live2D 含义的步骤名称：

```text
collecting
  → analyzeIdentity
  → generatePixelAvatar
  → qualityCheckPending
  → runtimeCheckPending
  → previewReady
  → finalize
  → completed
```

允许的终止与恢复状态继续包括 `failed`、`cancelled` 和 `cleanupPending`。

规则如下：

- 生成结果先进入隔离候选目录，不直接覆盖当前桌宠；
- 机械检查或真实运行检查失败时不能进入 `previewReady`；
- 只有用户在动态预览中明确接受，才能执行安装和宠物切换；
- 安装失败时保留原桌宠，候选保持可恢复状态；
- 安装成功后才清理原照片和非安装临时产物；
- 新 revision 创建后，旧请求的迟到响应不得覆盖新候选；
- 应用重启只能依据持久化状态和真实 provider 状态恢复，不得凭等待时间推断任务仍在运行。

## 10. 首版固定动作

首版动作通过整只宠物的固定变换和现有局部呼吸切片完成，不拆脸、不拆尾巴、不建立新骨骼系统。

首版动作语义至少包括：

| 动作 | 首版表达方式 |
|---|---|
| `idle` / `breathe` | 轻微上下位移与稳定呼吸切片 |
| `attention` | 整体轻微前移或倾斜 |
| `happy` | 小幅弹跳、左右摇晃和可选非身份特效 |
| `sleepy` | 整体下沉、慢呼吸和睡眠状态特效 |
| `startled` | 快速后移、短暂缩放后恢复 |
| `stretch` | 整体前倾、纵向轻微拉伸后回到稳定姿态 |
| `dragged` | 跟随拖动状态，释放后平滑恢复 |

所有变换使用受限幅度，不得明显扭曲脸部、像素簇或身份斑纹。动作结束后必须回到稳定中性姿态。首版不要求独立眨眼、独立摆尾、张嘴、真实走动或肢体级动画。

## 11. 后续完整角色帧动画

首版闭环通过后，只为高价值动作逐项增加完整角色帧序列，例如走动、跳跃和更自然的伸展。

完整角色帧必须：

- 每帧包含完整宠物，不依赖脸部或身体贴片；
- 共享同一身份档案、风格版本、调色约束和关键特征锁；
- 通过跨帧身份一致性和轮廓稳定性验收；
- 作为可选动作资产，不阻塞单图候选的生成、预览和安装；
- 不把 AI 独立生成的未经校验帧直接作为动画序列。

独立眨眼、摆尾或嘴部动作只能作为后续独立设计讨论，不能在实施首版时悄悄恢复语义拆层。

## 12. 错误、重试、取消与恢复

- 网络超时、临时不可用和 provider 5xx：沿用每阶段最多三次总尝试；
- 鉴权、额度、内容策略、输入无效和合同错误：立即停止并显示准确原因；
- 质量检查失败：记录具体原因并允许重新生成，不伪装成运行检查通过；
- lk888 或 `gpt-image-2` 不可用：明确失败，不自动切换模型、Live2D 或通用猫模板；
- 用户取消或放弃：停止未开始的后续提交，删除本地照片和临时文件，继续追踪可重试的受控后端清理；
- 上游不支持取消或删除时，必须记录 `unsupported`，不得声明远端已取消或删除；
- provider 没有真实任务 ID、日志增量或产物变化时，不得显示虚假的持续生成状态；
- 应用重启后无法确认远端状态时显示需要恢复或准确失败，不得假装任务仍在执行。

## 13. 用户交互与隐私

用户在最终动态预览中只需要三个主要选择：

1. 接受并安装；
2. 重新生成；
3. 描述需要修改的地方。

首次正式调用前继续使用 lk888 风险告知，明确模型用途、上游删除能力和保存期限的已知与未知情况。原始照片只在活动会话中临时保存；接受、取消、放弃或会话终止后按现有合同清理本地和受控后端副本。

开发和自动化默认使用非个人测试素材。真实付费调用或真实用户照片上传必须在实际发生前取得当次明确授权。

## 14. 测试与验收

### 14.1 合同测试

- 像素身份档案、生成记录和运行包严格解析；
- `provider=lk888`、`model=gpt-image-2`、风格版本和来源字段不可缺失；
- 未知字段、错误版本、错误模型和不完整审计失败关闭；
- 旧 Live2D 包继续可识别，但不能与像素包混淆。

### 14.2 状态与恢复测试

- 覆盖成功、重试、取消、重新生成、局部修改、迟到响应和重启恢复；
- 未到 `previewReady` 不能安装；
- 安装失败不破坏当前桌宠；
- 接受、取消或放弃后的本地与受控后端清理可验证、可恢复；
- lk888 上游 `unsupported` 不被误写为 `deleted`。

### 14.3 运行时测试

- `animated-image-v1` 能加载真实候选并稳定播放首版固定动作；
- 动作切换、循环、打断、拖动和窗口缩放无闪烁、模糊或布局跳变；
- 最近邻采样保持像素边缘清楚；
- 设置页动态预览与桌面宠物运行表现一致；
- 旧 Live2D 宠物不因像素路线改造发生回归。

### 14.4 真实视觉与完整闭环验收

- 使用已授权的非个人宠物照片完成一次真实 lk888 / `gpt-image-2` 生成；
- 对照身份档案检查脸型、耳形、眼色、花纹、胸毛、脚袜和尾巴；
- 对照已认可视觉基准检查高细节硬边像素风与均衡 Q 版比例；
- 在真实应用中逐个播放首版动作，留存截图或录像及可核验任务 ID；
- 完整走通“生成、质量检查、动态预览、修改或重新生成、接受、安装、重启恢复”；
- 验证终态清理和原桌宠保护。

自动测试通过、伪 provider 通过或单独生成一张好看的 PNG，都不能称为首版完成。

## 15. 首版完成定义

只有以下条件全部满足，才允许声明像素照片分身首版完成：

1. 一个真实照片测试样本通过完整生成、检查、动态预览、接受、安装和重启闭环；
2. 主人或授权验收人确认宠物身份可辨认；
3. 像素风格、比例、透明边界和运行缩放通过人工视觉门；
4. 首版固定动作在设置页和真实桌面运行时均有差异且稳定恢复；
5. 合同、状态、恢复、清理和旧运行时回归测试全部通过；
6. lk888 task ID、模型、哈希、运行截图或录像和清理结果均有证据；
7. 失败路径不使用通用猫、静态占位、其他模型或 Live2D 静默降级。

## 16. 后续实施顺序

本规格批准后，另行编写详细实施计划。计划必须按最小可验证切片推进：

```text
冻结旧 Live2D 照片分身主路径并建立像素合同
  ↓
把 lk888 gpt-image-2 输出改为完整像素宠物单图
  ↓
接入机械质量门与 animated-image-v1 候选包
  ↓
扩展首版固定动作并接入真实动态预览
  ↓
复用重新生成、局部修改、接受、安装和清理闭环
  ↓
完成一个非个人真实样本的端到端验收
  ↓
单独规划完整角色帧动画
```

计划和实施不得把边缘藏身、领养猫、声音、生产部署或完整角色帧动画混入首版闭环。每个任务开始前必须重新检查当前工作树、受保护脏文件和最新测试证据，只暂存该任务拥有的路径。

## 17. 当前事实边界

截至本文写入时：

- 像素视觉方向和五部分设计已经得到用户确认；
- 已有一张 lk888 / `gpt-image-2` 生成的认可样张；
- 现有 `animated-image-v1`、候选动态预览、编译安装链路和照片分身外围状态机可作为基础；
- 首版像素生成合同、状态迁移、固定动作扩展和真实应用闭环尚未实施；
- 认可样张不是正式安装资产，单张生成成功不等于产品闭环完成；
- 旧 Live2D 照片分身实现只冻结保留，不作为当前主线继续投入。
