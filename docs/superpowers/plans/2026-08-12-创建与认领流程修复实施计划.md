# 创建与认领流程修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让正式 ready/active 宠物不再占用长期草稿槽，并让认领/切换成功后返回创建入口上一级。

**Architecture:** Rust 领域服务定义唯一的“可恢复长期草稿”谓词并在读取/新建前收敛已完成事实。前端只消费 canonical draft，不自行猜测；认领视图通过既有 `onBack` 端口完成成功导航。

**Tech Stack:** Rust、rusqlite、TypeScript、Vitest。

## Global Constraints

- 不得删除或 abandon ready/active pet。
- 数据库收敛必须在事务中完成并保留正式 pet、variant 和资产。
- 认领失败或迟到结果不得导航。

- [ ] **Step 3: Write minimal implementation**

Inside the same locked connection/transaction:

```sql
UPDATE creation_sessions
SET status='completed', last_stable_status='completed', current_step='completed',
    completed_at=COALESCE(completed_at, pets.completed_at), error=NULL
WHERE method IN ('upload','composer')
  AND status NOT IN ('completed','abandoned')
  AND EXISTS (
    SELECT 1 FROM pets
    WHERE pets.pet_id=creation_sessions.pet_id
      AND pets.lifecycle='ready'
      AND pets.completed_at IS NOT NULL
  );
```

Then query only sessions joined to a draft, incomplete, inactive pet. Reuse this reconciliation in `draft()` and before `start()` inserts.
