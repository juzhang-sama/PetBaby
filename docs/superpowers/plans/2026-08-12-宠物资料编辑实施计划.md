# 宠物资料编辑实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让每只用户创建的宠物都能在“我的宠物”中编辑名称、性别和可选出生日期，同时保持内置宠物只读。

**Architecture:** 使用独立的 `pet_profiles` 一对一表承载可编辑资料，避免与旧数据库可能残留的 `pets.gender/age` 列冲突。Rust 仓储和 mutation gate 提供唯一写入口，设置页按需读取详情并在保存成功后刷新目录；目录列表继续保持轻量。

**Tech Stack:** Rust、rusqlite、serde、Tauri 2、TypeScript、Vitest、SQLite migration v8

## Global Constraints

- 本计划以前序抠图安全计划的 v7 为数据库基线，本计划只新增 v8。
- 只允许编辑用户创建且 `lifecycle='completed'` 的宠物；`pet-live2d-v1` 等内置宠物必须只读。
- 名称复用 `creation::name::normalize_display_name`：去除首尾空白后为 1–20 个 Unicode 字素簇，且不含控制/换行字符；性别只接受 `unknown`、`male`、`female`；出生日期为空或严格有效的 `YYYY-MM-DD`，且不得晚于 Windows 本地当天。
- 不从旧 `age` 推算出生日期；若旧库存在 `pets.gender`，只安全回填可识别的枚举值。
- 更新必须使用事务，并同步更新 `pets.display_name` 与 `pets.updated_at`；失败时不得部分写入。
- 不修改现有未提交的 `apps/desktop/src-tauri/Cargo.toml` 和 `docs/新对话开发交接摘要.md`。
- 除非步骤另有说明，Rust 命令从 `apps/desktop/src-tauri` 执行，npm 命令从 `apps/desktop` 执行。

- [ ] **Step 3: 添加 v8 migration**

```sql
CREATE TABLE pet_profiles (
  pet_id TEXT PRIMARY KEY REFERENCES pets(pet_id) ON DELETE CASCADE,
  schema_version INTEGER NOT NULL DEFAULT 1 CHECK(schema_version = 1),
  gender_code TEXT CHECK(gender_code IN ('male','female') OR gender_code IS NULL),
  birth_date TEXT CHECK(birth_date IS NULL OR birth_date GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]'),
  updated_at TEXT NOT NULL
);
INSERT INTO pet_profiles(pet_id, schema_version, gender_code, birth_date, updated_at)
SELECT pet_id, 1, NULL, NULL, updated_at FROM pets WHERE lifecycle='completed';
```

migration Rust 钩子先通过 `PRAGMA table_info(pets)` 检测 `gender`；存在时仅把小写后的 `male/female` 回填到 `gender_code`，`unknown` 和不可识别值保持 `NULL`，忽略 `age`。验证最新 schema 时检查表与五列完整存在。

- [ ] **Step 3: 实现类型与严格校验**

```rust
#[derive(Debug, Clone, Copy, Serialize, Deserialize, PartialEq, Eq)]
#[serde(rename_all = "camelCase")]
pub enum PetGender { Unknown, Male, Female }

#[derive(Debug, Clone, Serialize, PartialEq, Eq)]
#[serde(rename_all = "camelCase")]
pub struct PetProfile {
    pub schema_version: u32,
    pub pet_id: String,
    pub display_name: String,
    pub gender: PetGender,
    pub birth_date: Option<String>,
    pub editable: bool,
    pub updated_at: String,
}

#[derive(Debug, Deserialize)]
#[serde(rename_all = "camelCase", deny_unknown_fields)]
pub struct PetProfileUpdate {
    pub display_name: String,
    pub gender: PetGender,
    pub birth_date: Option<String>,
}
```

`validate_profile_update` 直接调用 `crate::creation::name::normalize_display_name`。在 `profile.rs` 内实现无依赖的 Gregorian 校验：拆分固定 10 字节格式，检查月份天数和闰年；Windows 下用本文件声明的最小 `GetLocalTime` FFI 读取当天，测试通过注入 `today: DateParts` 保持确定性。非 Windows 编译分支用 `SystemTime` 转 UTC civil date，仅用于维持静态编译，不扩展其他平台产品行为。不得为此修改当前脏的 `Cargo.toml`。

- [ ] **Step 4: 实现事务读取/更新和只读规则**

`get_profile` 对内置 ID 返回 `editable=false` 的投影；对用户宠物用 `LEFT JOIN pet_profiles`，缺行时在事务内补默认行。API 的 `PetGender::Unknown` 与数据库 `NULL` 双向映射；`update_profile` 先确认宠物存在、completed、非内置，再在同一事务更新 `pets.display_name/updated_at` 和 UPSERT `pet_profiles`。

#[test]
fn profile_edit_conflicts_with_delete_for_same_pet() {
    let gate = Arc::new(PetMutationGate::new(Duration::from_secs(1)));
    let _delete = gate.scoped("delete-1", MutationKind::Delete, "pet-a").unwrap();
    let waiting = gate.clone();
    let (sent, received) = std::sync::mpsc::channel();
    let thread = std::thread::spawn(move || {
        let _edit = waiting.scoped("edit-1", MutationKind::ProfileEdit, "pet-a").unwrap();
        sent.send(()).unwrap();
    });
    assert!(received.recv_timeout(Duration::from_millis(20)).is_err());
    drop(_delete);
    assert_eq!(received.recv_timeout(Duration::from_secs(1)), Ok(()));
    thread.join().unwrap();
}

#[tauri::command]
fn pet_profile_update(
    repo: tauri::State<'_, SharedPetRepository>,
    gate: tauri::State<'_, SharedPetMutationGate>,
    request_id: String,
    pet_id: String,
    value: PetProfileUpdate,
) -> Result<PetProfile, String> {
    let _lease = gate.scoped(&request_id, MutationKind::ProfileEdit, &pet_id)?;
    repo.lock().map_err(|_| "pets lock poisoned")?.update_profile(&pet_id, value)
