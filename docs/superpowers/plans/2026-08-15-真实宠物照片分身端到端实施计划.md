> **⚠️ 路线已淘汰（历史留痕）：** 本文是 2026-08-15「动画电影软萌风 + Live2D」路线的实施计划，已于 **2026-08-18** 被**像素照片分身路线**（pixel-style-v1，16-bit 硬边像素插画）取代，**不再执行**。当前权威：`docs/项目开发交接文档-2026-08-19.md`、`docs/superpowers/specs/2026-08-18-真实宠物像素分身路线设计.md`、`docs/设计/猫咪A风格视觉规范.md`。

> **For agentic workers:** REQUIRED SUB-SKILL：逐 Task 使用 `subagent-driven-development`（推荐）或 `executing-plans` 实施；每个步骤使用 `- [ ]` 跟踪。任何真实付费调用、真实用户照片上传或第三方供应商调用发生前，必须在当次停下取得用户明确授权。

**目标：** 用一张或多张真实猫照片生成主人可辨认、保持 A：动画电影软萌风、从首次安装起即具备完整 Live2D 微动作的 v5 照片分身猫，并用首只真实分身与第二体型交叉回归证明身份、体型和动作空间均成立。

**架构：** 保留现有创建会话、mutation gate、原子安装器、Manifest v5、三种只读体型模块和真实 Live2D renderer；用新的 `PhotoAvatarProvider` 受控后端端口替换上传入口中的 LK888/绿色背景/v3 静态候选链路。Rust 后台持久化轻量远端任务、逐步骤尝试和资料来源，AI 只产出身份档案与和白名单模块 UV 对齐的专属纹理；builder 只读复制预绑定模块，生成并严格校验 v5 包，前端只在完整动态包就绪后统一预览。

**技术栈：** Tauri 2.11、Rust 2021、rusqlite/SQLite、reqwest、serde、TypeScript 7、Vite 8、Vitest 4、PixiJS 8、Cubism Web SDK、PowerShell、Playwright CLI。

## 全局约束

- 第一产品目标是真实宠物照片分身；标准猫只提供公共动作基准，领养猫最后开发。
- 视觉保持 **A：动画电影软萌风**；保持真实猫身体结构，不生成大头短躯玩偶比例。
- 标准模块只负责怎么动；用户照片与有来源记录的 AI 补全决定长什么样。不得把标准猫脸、毛色、花纹、眼色或中性纹理带入正式照片分身。
- 上传入口一次接受 `1..8` 张照片；每张原始文件不超过 `10 MiB`、长宽各不超过 `4096`、总像素不超过 `16,000,000`，全部规范化 PNG 合计不超过 `40 MiB`。这些是本地安全边界，不把第 2 张照片变成开始生成的门槛。
- 第一次使用前显示并保存 `photo-avatar-third-party-ai-v1` 同意；告知照片发送第三方 AI、缺失资料由 AI 补全及可能存在差异。同一会话内不重复打断。
- 最终身份字段来源只允许 `user` 或 `ai-completed`；没有体型证据时必须显式记录 AI 推断，不得隐藏默认 `body-balanced-v1`。
- 首次只生成一个完整候选；分析、补全、体型选择、贴图生成与 v5 构建之间不插入用户确认。
- 最终预览只提供：接受安装、完整重生成、简短局部修改。局部修改必须把未要求改变的身份字段作为锁定字段发送并在响应后逐项校验。
- 可重试远端步骤精确为 `analyzeIdentity`、`completeAppearance`、`renderTextureAtlas`；每个 `sessionId + revision + step` 最多三次总尝试。轮询不计为尝试。
- `invalidInput`、`auth`、`quota`、`contentPolicy`、`unsupported` 为不可重试错误；`network`、`timeout`、`provider5xx`、`temporaryUnavailable` 可重试。三次失败后直接失败，不得降级为标准猫、animated-image v3 或静态 PNG。
- 原图在接受、放弃、取消或会话终止后删除；正式 provider 必须支持远端删除。远端删除失败进入明确的 `cleanupPending`，不得伪报隐私清理完成。
- 关闭主界面销毁创建 WebView，不取消后台任务；只持久化远端任务 ID、阶段、revision 和尝试次数。重新打开后轻量恢复，不发 Windows 系统通知。
- 新照片分身只输出 `schemaVersion: 5`、`renderer: cat-spatial-live2d-v1`。v1-v4 继续兼容，但照片分身成功路径不得使用它们。
- 空闲 CPU 长期采样 `P95 <= 1%`，微动画 `P95 <= 3%`，空闲私有内存目标 `<= 120 MB`；release 实测超过 `180 MB` 不得放行。隐藏状态 CPU 接近 `0%`。
- 真实验收必须逐张检查中性、峰值、回退和打断证据：无白线、透明破洞、脸部错位、眼球穿睑、耳根脱离、尾根断裂或错误形变。
- 标准猫鼻梁透明缝保留为已知视觉债务，不阻塞本计划前十二项；Task 13 阶段审查必须重新登记处置节点，不能写成已修复，也不能让新照片分身出现同类新接缝。

- 任一命令、构建、GUI、外部调用或等待超过两分钟，立即检查真实 PID、任务 ID、日志增量、Git、文件时间和产物；无进展停止并纠偏。同一工具错误连续两次后停止重试并定位根因。

- 真实入口支持一次提交 1-8 张照片，第一张即可开始；首次第三方 AI/补全告知和同意有持久记录。
- profile 所有身份字段和体型均有 `user | ai-completed` 来源，体型无隐藏均衡默认。
- 三个远端步骤分别最多三次，取消、不可重试错误、迟到响应和崩溃恢复均有测试证据。
