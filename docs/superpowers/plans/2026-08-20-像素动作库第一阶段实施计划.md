# 像素动作库第一阶段实施计划

> **执行要求：** 本阶段按测试驱动方式逐项实施；Git 操作不在本计划范围内。

**目标：** 使用已经验证的呼吸和眨眼动作，打通“确定性帧生成、动作资产合同、Canvas 帧播放、照片分身运行检查”完整链路，为摇尾巴、耳朵微动和睡觉提供稳定扩展点。

**架构：** 离线动作引擎负责从静止 RGBA 图和人工标注的动作坐标生成完整 PNG 帧，并执行锚点、循环和目标区域验证。桌面端继续使用 manifest schema v3，但允许声明可选的 `motionLibrary`；存在动作库时播放完整帧，不存在时保持当前单图渲染，避免破坏已经安装的像素宠物。

**技术栈：** Python 3.13、Pillow、NumPy、ffmpeg（仅生成验收 GIF）、TypeScript、Canvas 2D、Vitest。

## 全局约束

- 不删除或修改 Live2D 代码、资产和测试。
- 所有像素操作使用整数坐标；禁止缩放、旋转、羽化和插值。
- 动作坐标来自人工查看真实图后的标注，不使用自动轮廓算法猜测。
- 循环动作首帧和尾帧像素必须完全一致。
- 声明为锚点的区域在全部动作帧中必须零像素变化。
- 运行时不得依赖 Python 或 ffmpeg；它们只在开发期生成资产和证据。
- 保留 schema v3 旧包兼容性；没有 `motionLibrary` 的现有包继续走当前渲染路径。
- 不执行 Git 提交、分支或远程操作。

**接口：**

- `MotionFrame(image: Image.Image, duration_ms: int)`：一张完整 RGBA 帧及其播放时长。
- `MotionSequence(name: str, loop: bool, frames: tuple[MotionFrame, ...])`：一个可播放动作。
- `MotionAuthoringProfile`：保存人工确认的呼吸锚点、左右眼区域、目标变化区和锚点区。
- `build_front_sitting_cat_motion(image, profile, motion_name) -> MotionSequence`：生成 `idle` 或 `blink`。
- `validate_sequence(sequence, anchor_boxes, target_boxes) -> MotionValidationReport`：验证尺寸、RGBA、时长、首尾同帧、锚点零变化和目标区变化。
- `export_motion_library(sequences, output_dir) -> Path`：写入完整 PNG 帧和 `motion-library.json`。
