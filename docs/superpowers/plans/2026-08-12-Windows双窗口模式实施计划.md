# Windows 双窗口模式实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 恢复“陪伴模式（置顶）”与“桌面模式”切换，桌面模式优先挂载 WorkerW、明确降级到底层窗口，并在失败时原子回滚到陪伴模式。

**Architecture:** 将“用户期望模式”“用户显隐”“自动抑制原因”“实际桌面宿主状态”拆成正交状态，由纯状态机输出窗口动作。Windows adapter 只负责 HWND 快照、WorkerW 探测/挂载、bottom fallback 与恢复；控制器执行动作并 ACK，只有成功后才持久化模式并更新托盘/UI。

**Tech Stack:** Rust、windows-sys/Win32、Tauri 2、TypeScript、Vitest、Windows 10/11

## Global Constraints

- 只开发和验证 Windows；其他操作系统继续编译现有 stub，不扩展功能。
- `companion`：topmost、no-activate、toolwindow，参与全屏自动隐藏。
- `desktop`：优先 `WorkerW` 父子宿主；失败后尝试 `HWND_BOTTOM` 兼容策略；两者都失败时完整恢复原 HWND 状态并保持 companion。
- 桌面模式的出现判定不依赖前台窗口：仅由用户显隐、Explorer/宿主可用性和进程生命周期决定；全屏应用不得隐藏桌面模式。
- 手动隐藏是持久用户意图；全屏、切换中、Explorer 丢失是可组合 suppression，清除一个原因不得覆盖其他原因。
- 模式切换期间先暂停 renderer，成功或回滚完成后再恢复；不得出现双窗口、失焦激活、任务栏按钮或不可找回窗口。
- 只有收到实际宿主 ACK 后写 `preferences.mode`；失败 ACK 保持旧模式。
- 不使用 Win+D 前景判断作为桌面模式依据，不恢复历史 WinEvent hook 判定。
- 不修改现有未提交的 Cargo manifest 和交接摘要。
- 除非步骤另有说明，Rust 命令从 `apps/desktop/src-tauri` 执行，npm 命令从 `apps/desktop` 执行。

- [ ] **Step 3: 实现串行事务控制器**

控制器持有 mutex，拒绝并发不同 requestId；切换顺序：加入 Transition suppression → 发 `pet-runtime:pause` 并等待 `window_mode_runtime_ack(requestId,"paused")` 最多 2 秒 → capture → attach/restore → 按状态机决定 visibility → 发 `pet-runtime:resume` 并等待 `resumed` ACK → 保存 mode → 返回 `WindowModeSnapshot`。任何失败逆序补偿并恢复旧 mode；补偿错误附加到原始错误，不掩盖根因。ACK 状态以 requestId 为 key，迟到或重复 ACK 不得完成另一个切换。

```rust
#[derive(Debug, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct WindowModeSnapshot {
    pub desired_mode: WindowMode,
    pub actual_mode: WindowMode,
    pub desktop_strategy: Option<DesktopStrategy>,
    pub user_visible: bool,
    pub suppressions: Vec<SuppressionReason>,
}
```
