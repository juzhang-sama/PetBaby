# 桌宠显示尺寸实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在设置页提供 50%–150% 的全局桌宠尺寸调节，实时预览、底部中心锚定、重启保留，并保证点击区域同步。

**Architecture:** 用版本化 `displayScale` 表示相对 420×520 基准尺寸，纯函数计算新窗口矩形；宠物窗口执行 resize/position/hit-region 刷新并返回 ACK，设置页仅在 ACK 后持久化。尺寸与渲染器资产解耦，静态图、动画图和 Live2D 统一跟随 viewport。

**Tech Stack:** TypeScript、Tauri 2 window/event API、Rust preferences、Vitest

## Global Constraints

- 有效范围为 0.50–1.50，设置页步进 0.05，预设为 75%、100%、125%。
- 基准逻辑尺寸固定为 420×520；`displayScale=1` 对应基准尺寸。
- 改变尺寸时保持窗口底部中心点不变，然后按当前显示器工作区夹紧，至少保留 64px 可见。
- 只有宠物窗口完成 setSize、setPosition、renderer resize 和 hit-region 刷新后才返回成功并保存。
- resize 失败必须恢复旧尺寸与位置；隐藏/全屏抑制期间可更新期望值，但不得意外 show 窗口。
- 旧 preferences 的 dormant `scale` 明确忽略，不把它重新解释为显示尺寸；升级时从实际 `width/height` 推导一次 `displayScale`，写回使用 `schemaVersion: 2` 与 `displayScale`。
- 不修改现有未提交的 `apps/desktop/src-tauri/Cargo.toml` 和交接摘要。
- 除非步骤另有说明，Rust 命令从 `apps/desktop/src-tauri` 执行，npm 命令从 `apps/desktop` 执行。

- [ ] **Step 3: 实现精确几何和控制器**

```ts
export function displayRectForScale(current: WindowRect, scale: number, area: WorkArea): WindowRect {
  const width = Math.round(420 * clamp(scale, 0.5, 1.5));
  const height = Math.round(520 * clamp(scale, 0.5, 1.5));
  const bottomCenterX = current.x + current.width / 2;
  const bottomY = current.y + current.height;
  return clampRectToWorkArea({
    x: Math.round(bottomCenterX - width / 2), y: Math.round(bottomY - height), width, height,
  }, area, 64);
}
```

`apply` 顺序固定：读取旧 rect/工作区 → 计算 → `setRect(next)` → `resizeRenderer()` → `refreshHitRegion()` → 返回 ACK；任一步失败均尽力 `setRect(old)`、`resizeRenderer()`、`refreshHitRegion()`，原始错误附带 rollback 错误信息。
