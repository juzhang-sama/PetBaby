# 猫咪形象与动态视觉专项实施计划

> **⚠️ 路线已淘汰（历史留痕）：** 本文是 2026-08-12「动画电影软萌风 + Live2D」路线的实施计划，已于 **2026-08-18** 被**像素照片分身路线**（pixel-style-v1，16-bit 硬边像素插画）取代，**不再执行**。当前权威：`docs/项目开发交接文档-2026-08-19.md`、`docs/superpowers/specs/2026-08-18-真实宠物像素分身路线设计.md`、`docs/设计/猫咪A风格视觉规范.md`。

> **执行代理必读：** 实施时必须逐任务使用 `subagent-driven-development`（推荐）或 `executing-plans`。所有步骤用复选框跟踪；任一阶段门槛未通过，不得开始后一阶段。

**目标：** 先用一只 A 风格标准猫验证统一的 `cat-a-live2d-v1` 角色包、8 组坐姿动作和四边动态尾巴藏身，再优先把已验证能力用于照片分身猫，最后接入 6 只次优先级标准领养猫。

**架构：** 保留现有 manifest v1/v2/v3、Static PNG、animated-image 与旧 Live2D 宠物的兼容加载；为新基线新增 manifest v4，并把角色包校验、Live2D 适配、动作调度、边缘藏身、照片会话、角色包构建和宠物目录分开。Rust 继续负责 SQLite、资源所有权、安装事务和窗口能力，TypeScript 负责渲染、调度与指针交互；美术源文件保存在 `D:\PetBabyAssets`，仅经校验的运行时导出进入仓库。

**技术栈：** Tauri 2.11、Rust、TypeScript 7、Vite 8、Vitest 4、SQLite/rusqlite、PixiJS 8、Cubism Web SDK、PowerShell、lk888.ai `gpt-image-2`（仅静态预览生成；真实调用需用户动作时确认）。

> **2026-08-14 执行修正：** 标准猫只作为公共技术基线，不构成真实宠物生成成功证明。硬顺序修正为：本计划 Task 8 → 新计划 Task 1–5 → 本计划 Task 10–13 → 新计划 Task 6–9 → 本计划 Task 9 → 本计划 Task 18–20。原 Task 14–17 被新计划 Task 6–8 取代，不再重复执行；Task 18 领养猫仍为最后支线。新计划路径：`docs/superpowers/plans/2026-08-14-真实宠物主线与动作空间适配实施计划.md`。

## 全局约束

- 当前只支持 Windows 和猫；不扩展其他动物或操作系统。
- 新角色统一采用 A：动画电影软萌风、平衡构图、正面坐姿；保留纤细型、均衡型、圆润型的体型差异，现有写实 Live2D 猫和旧领养素材不是质量基线。
- 新角色统一使用 `cat-a-live2d-v1` 动作语义；不同形体模块分别绑定网格、轴心和安全幅度，已安装角色包不得被静默替换。
- 固定画布不得被当作固定动作区域。所有新角色包必须具有 `MotionSpatialProfileV1`，且照片分身 builder 不得在缺失动作空间档案时安装角色。
- 单猫完整专属 Live2D、照片自动拆层绑骨、多姿态完整行为、捏脸/花纹编辑、服饰配饰、专属声音和性格系统均不进入本计划。
- 首期 8 组动作固定为：呼吸、自然眨眼、耳动、尾巴待机、鼠标关注、抚摸开心回应、困倦/哈欠、半站式伸懒腰。
- 鼠标关注只驱动眼神、耳朵和尾巴，不转头、不倾身；当前旧 renderer 中冻结的眨眼/眼球/头部/嘴部能力不得借本计划恢复。
- 新 Live2D 在正常桌面和边缘藏身状态均以 60 FPS 为目标；隐藏、系统休眠、显示器关闭或环境暂停时停止循环。
- 默认静音；首期只预留并实现用户主动开启后的通用低频互动音，不采集真实猫声音。
- 一张合格照片必须能走完照片分身流程；第二张照片始终可选。
- 照片分身猫是规模化阶段的第一优先级；2026-08-14 新计划 Task 6–9、至少一只真实照片分身猫完整回归和第二体型交叉回归未通过前，不得开始 Task 18 的 6 只标准领养猫制作。
- 边缘藏身必须只显示可持续运动和响应悬停的独立尾巴 ArtMesh；猫身及其他部件完全不可见、不可命中，不得用普通坐姿尾巴的静态裁切图冒充。
- 原始照片只在活动创建会话中临时保存；确认静态预览、放弃或终止时必须删除，后续角色包构建不得读取原图。
- 未经用户在真实请求发生前明确确认，不调用付费生成提供方；测试使用 fixture 或 mock server。
- 不覆盖未跟踪的 `docs/新对话开发交接摘要.md`，不触碰 `.worktrees/breath-sway-runtime`。
- 纯逻辑严格先写失败测试；系统能力补中文人工验收记录和可复核截图/帧证据。

## 阶段总览与硬门槛

| 阶段 | 可交付结果 | 进入下一阶段的硬门槛 |
| --- | --- | --- |
| 0. 标准猫视觉验证 | 唯一一张获批 A 风格正面坐姿母版 | 用户逐项确认风格、比例、轮廓和可绑定性；未确认不得拆层/绑定 |
| 1. 角色包 | `cat-a-live2d-v1` 标准猫 v4 包 | 双端结构校验、哈希/路径/许可证、必需参数/动作/四尾状态全部通过，桌面加载无静态降级 |
| 2. 运行时动作 | 标准猫 8 组动作和统一调度器 | 自动化通过；真人逐项无整图闪烁、穿帮和跳帧；用户操作可平滑打断 |
| 3. 边缘藏身 | 四边磁吸、仅动态尾巴可见、点击/拖拽唤回 | 四边四角、尾巴持续动作、猫身零露出、多显示器/DPI、窗口恢复自动化与真人验收通过 |
| 4A. 照片分身猫 | 照片会话、形体模块选择、参数化构建、安装与同能力回归 | 单图全流程、体型与身份特征保真、角色级动作区域校准、隐私清理、失败重试和至少一只照片分身猫完整回归通过；发布前至少两个不同身体模块完成交叉体型回归 |
| 4B. 标准领养猫 | 6 只领养猫与多猫目录 | 仅在 4A 通过后开始；6 只角色同能力回归和单宠显示全部通过 |

标准猫在阶段 0 至 3 的任一门槛失败时，修复仍限定在标准猫及公共基线；不得提前批量制作照片分身猫或领养猫。
