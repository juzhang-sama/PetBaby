# 三条宠物创建链路实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保留现有上传生成能力的基础上，交付“上传图片、引导组合、直接认领”三个正式创建入口，并保证三种来源都通过同一可靠完成事务成为具有呼吸和微动的桌面宠物。

**Architecture:** Rust 建立统一创建会话、候选所有权、内容校验、完成事务和恢复服务；上传、组合、认领只负责生成标准候选。TypeScript 提供统一创建入口、确定性分层合成和动态预览，并通过现有两阶段热切换协议完成桌面激活。组合包与认领目录均为离线版本化资源，正式用户宠物始终安装为独立 schema v3 动态单图资产。

**Tech Stack:** Rust 2021、Tauri 2.11.5、SQLite/rusqlite 0.40.1、Serde、`image` 0.25.5、TypeScript 7、Canvas 2D、Vitest 4、Vite 8、现有 `animated-image-v1` schema v3 运行时。

## Global Constraints

- 第一版只支持猫，所有新建会话的 `species` 固定为 `cat`。
- 所有正式用户宠物必须具备呼吸和微动；`static-png` 不得成为合格完成态。
- 引导组合采用离线分层所见即所得，不调用 AI，不提供自由图层、自由取色或完成后重新编辑。
- 组合正式导出固定为 1024×1024 透明 RGBA PNG。
- 组合素材最低数量固定为：3 个身体、4 套耳朵、5 套眼睛且各有闭眼状态、4 套鼻嘴表情、4 条尾巴、6 种毛色、4 种花纹加无花纹。
- 认领目录固定提供 8 个成品猫模板；模板只读且永久保留，用户实例可删除。
- 同一模板最多存在一个未放弃或已完成的用户实例；删除或放弃后才可重新认领。
- 名称按 Unicode 字素簇计数，去除首尾 Unicode 空白后为 1～20 个字符；拒绝换行、行分隔符、控制字符和纯空白，允许重名。
- 上传与组合共享一个未完成长期草稿；认领短期安装会话不能覆盖该草稿。
- 完成成功必须同时满足：资源有效、独立目录安装、桌面显示、数据库提交、当前宠物一致、会话完成。
- 创建完成、普通切换和删除必须通过同一宠物变更门串行；相同 `sessionId` 的完成请求必须幂等。
- 系统默认 `pet-live2d-v1` 始终不可删除，也不属于 8 个认领模板。
- 不实现猫以外物种、AI 融合、衣饰、完成后重命名、眨眼/嘴部/耳朵/尾巴动作、远程商店、账号或云同步。
- 所有生产代码严格执行 RED → GREEN → REFACTOR；每个 Task 独立提交，不混入已有用户文档改动。
- Rust 命令从 `apps/desktop/src-tauri` 执行；npm 命令从 `apps/desktop` 执行；Git 命令从工作树根目录执行。

```rust
use unicode_segmentation::UnicodeSegmentation;

pub fn normalize_display_name(value: &str) -> Result<String, String> {
    let normalized = value.trim().to_owned();
    if normalized.is_empty() {
        return Err("宠物名称不能为空".into());
    }
    if normalized.chars().any(|c| c.is_control() || matches!(c, '\n' | '\r' | '\u{2028}' | '\u{2029}')) {
        return Err("宠物名称不能包含换行或控制字符".into());
    }
    let count = normalized.graphemes(true).count();
    if !(1..=20).contains(&count) {
        return Err("宠物名称必须为 1 到 20 个字符".into());
    }
    Ok(normalized)
}
```

`domain.rs` 中所有对外枚举使用 `#[serde(rename_all = "camelCase")]`，并提供不会发生秒级碰撞的 ID：

```rust
static ENTITY_NONCE: std::sync::atomic::AtomicU64 = std::sync::atomic::AtomicU64::new(0);

pub fn new_entity_id(prefix: &str) -> String {
    use std::time::{SystemTime, UNIX_EPOCH};
    let nanos = SystemTime::now()
        .duration_since(UNIX_EPOCH)
        .map(|duration| duration.as_nanos())
        .unwrap_or_default();
    let nonce = ENTITY_NONCE.fetch_add(1, std::sync::atomic::Ordering::Relaxed);
    format!("{prefix}-{:x}-{nanos:x}-{nonce:x}", std::process::id())
}
```

```ts
export interface FinalizerPorts {
  prepare(sessionId: string, requestId: string): Promise<PreparedCreation>;
  switchPet(petId: string, options: PetSwitchOptions): Promise<PetSwitchResult>;
  abort(sessionId: string, error: string): Promise<CreationSnapshot>;
  cancel(requestId: string): Promise<void>;
}

export async function finalizeCreation(
  sessionId: string,
  ports: FinalizerPorts = tauriFinalizerPorts,
): Promise<PetSwitchResult> {
  const requestId = crypto.randomUUID();
  const prepared = await ports.prepare(sessionId, requestId);
  if (prepared.alreadyCompleted) {
    return { ok: true, requestId, petId: prepared.petId };
  }
  const result = await ports.switchPet(prepared.petId, {
    requestId,
    acceptedVariantId: prepared.variantId,
    creationSessionId: prepared.sessionId,
  });
  if (!result.ok) {
    await ports.abort(prepared.sessionId, result.message).catch(() => undefined);
    await ports.cancel(requestId).catch(() => undefined);
  }
  return result;
}
```

`FinalizerPorts` 固定为 `prepare(sessionId, requestId)`、`switchPet(petId, options)`、`abort(sessionId, error)`、`cancel(requestId)`。协调器在 creation request 失败时也先调用幂等 `creation_abort_finalize`，再调用幂等 cancel gate；settings finalizer 的同样操作是桌面窗口完全无响应时的兜底，重复调用不得删除其他资源。若数据库提交已经成功而仅旧 runtime 清理失败，返回成功并记录清理警告，不能 abort 已完成 session。`prepare` 对 completed session 返回同一 pet/variant 且 `alreadyCompleted=true`，不重新编译、不重新占 gate。
