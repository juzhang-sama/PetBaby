# 真实宠物主线与动作空间适配实施计划

> **执行代理必读：** 必须逐任务使用 `executing-plans` 实施。所有步骤用复选框跟踪；本计划不采用逐 Task 独立代理审查，保留实现者自检、规定测试、阶段集中审查和最终分支审查。

> **2026-08-15 路由修正：** `docs/superpowers/specs/2026-08-15-真实宠物照片分身生成方向校准设计.md` 已确认完整动态角色后置预览、AI 补全来源、三次重试、取消/恢复、供应商隐私和“真实照片分身先于边缘藏身”。本计划 Task 1–5 继续有效；Task 6–9 及下文旧照片流程不再可执行，必须在 Task 5 完成并复核后依据新规格重写实施计划。

**目标：** 在不破坏 v1–v4 已安装宠物的前提下，为真实照片分身猫建立有限体型模块、角色级动作空间档案和 v5 角色包，并用至少一只真实照片宠物及两个不同体型模块证明动作不会错位。

**架构：** `cat-a-live2d-v1` 只统一动作语义；`body-slender-v1`、`body-balanced-v1`、`body-rounded-v1` 分别提供预绑定形变。新 manifest v5 引用 `MotionSpatialProfileV1`，Rust 和 TypeScript 双端校验空间几何与安全幅度；运行时把统一动作输入夹紧到角色档案，照片 builder 只从白名单模块装配，不生成任意骨架。

**技术栈：** Tauri 2.11、Rust、TypeScript 7、Vite 8、Vitest 4、SQLite/rusqlite、Cubism Web SDK、PowerShell、Playwright CLI、Krita、Live2D Cubism Editor 5.3。

## 全局约束

- 真实宠物照片生成、体型保真和动作适配为主线；标准猫只验证公共底座，领养猫最后执行。
- 统一的是画布、动作语义、归一化输入和验收，不统一实际像素动作区域。
- 首期身体模块仅允许 `body-slender-v1`、`body-balanced-v1`、`body-rounded-v1`。
- 新照片分身只构建 v5；v1–v4 保持兼容，不静默迁移已安装宠物。
- 边缘藏身必须身体完全离屏，只显示同一条可持续运动、可命中的独立尾巴。
- 一张合格照片可以完成；第二张照片始终可选。
- 原图只存在于活动会话；用户接受、放弃、取消或会话终止后删除。照片流程的原图读取边界必须在新实施计划中依据 2026-08-15 方向校准规格重新定义。
- 任何真实付费生成仍需用户在调用发生时确认；文档、fixture 和 mock 不触发费用。
- 每个命令、构建、GUI、生成或外部调用超过两分钟立即检查进程、日志、Git、文件时间和产物变化；无进展则停止并纠偏。
- `apps/desktop/src-tauri/Cargo.toml` 当前存在内容与 HEAD 相同的行尾伪修改，不纳入任何提交。

## 与原计划的执行路由

1. 先完成原计划 Task 8 标准猫八动作视觉回归。
2. 执行本计划 Task 1–5，建立 v5、三个形体模块、标准猫迁移和运行时动作空间消费。
3. 停下复核，并依据 2026-08-15 方向校准规格重写照片分身实施计划。
4. 先完成照片输入、AI 补全、动态 v5 builder、首只真实照片分身和第二体型交叉回归。
5. 再返回原计划 Task 10–13，实现并验收身体全离屏、只留动态尾巴的边缘藏身公共底座。
6. 最后才执行可选通用音效、领养猫与内容扩展。

原计划 Task 14–17 仍不得执行。本计划旧 Task 6–9 同样已被 2026-08-15 方向校准取代；新照片会话和 builder 只能在新实施计划中定义一次。
