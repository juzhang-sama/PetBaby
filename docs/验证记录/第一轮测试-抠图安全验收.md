## 自动化层级与边界

本仓库当前没有一个在不修改产品代码、不连接真实供应商的前提下，能够把“供应商返回图片 → Tauri 命令 → 真人浏览器 UI 点击 → 定稿”统一驱动起来的单一测试入口。因此，本记录采用已提交的跨层精确测试组合：纯内存 RGBA 算法测试、真实临时 SQLite/文件系统的 Rust 集成测试、Tauri 候选投影测试，以及 Vitest DOM 假体测试。它验证了各层之间的持久化和安全契约，但**不声称执行过真人 UI 端到端测试**。

所有图片均由测试代码按像素生成；没有读取或写入用户图片。生成测试直接调用 `complete_download` 或算法入口，`https://example.invalid/out.png` 只作为持久化用的不可达占位字符串；UI 测试使用 mock port。整个验收没有调用真实供应商。

### 逐项验收

- 浅色/内洞：算法报告为 `needsReview` 且包含 `interiorHoles`。临时 SQLite/文件系统集成测试确认 generation job 为成功候选，`raw.png`、`cutout.png` 和可反序列化的 `quality_report_json` 同时存在，session 为 `candidateReady`；`motion_profile_path` 为 `NULL`，且 `motion-profile.json` 不产生。
- UI 阻断：DOM 假体收到 schema v3 的 raw/cutout data URL、`needsReview` 与 `interiorHoles` 后，原图和抠图均显示；完成按钮为 disabled 且 hidden，命名入口隐藏，重新生成和放弃仍可用，动态预览不启动。
- 直接定稿阻断：真实临时 SQLite/文件系统中的 needs-review 候选调用 `prepare`，返回包含 `automatic cutout did not pass quality review` 的错误；数据库/文件快照不变，mutation gate 可再次获取，runtime `manifest.json` 不产生。
- 原生 alpha：`SourceAlpha` 路径的输出 `RgbaImage` 与输入逐字节相等，alpha=77 的像素不被改写，也不误报 `InvalidSourceAlpha`。
- 深色/可接受：深色主体报告 `acceptable` 且原因列表为空；候选事务同时记录 successful job、可接受质量报告与 motion profile；正常 `prepare` 生成 runtime manifest 并把 session 推进 `finalizing`。这三条是跨层组合证据，不声称同一个测试进程把同一张 fixture 一路传到 UI。
- recovery：把已进入 finalizing 的候选降级为 needs-review 后调用 `recover`，质量闸门仍拒绝处理；warning 包含质量错误，session/候选/宠物/runtime row、源文件与 manifest 快照均不变。
- junction：在数据库 ownership 完整的情况下，把 `jobs/job-1` 指向外部目录的 Windows junction；候选投影返回包含 `link or reparse point` 的错误，外部 `raw.png` 测试字节保持不变。
