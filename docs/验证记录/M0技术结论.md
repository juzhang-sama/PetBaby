# M0 技术结论

## 阶段判定

- 总体：有条件通过，可进入 M1，桌面模式判定为未通过（环境限制）
- 默认陪伴模式：通过（W-01 人工实测通过：启动不抢焦点）
- Alpha 窗口区域穿透：通过（W-02/W-03 人工实测通过：透明区穿透、宠物区可点击）
- 桌面模式：未通过（当前设备桌面层被深度修改，三种方案均不可行，详见下）
- 全屏避让：通过（750ms 轮询探针实测隐藏后 CPU 0%，无持续占用；人工视频全屏验证待补）
- 性能预算：有条件通过（空闲 CPU P95 0% 达标；内存 156 MB 高于 120 MB 目标但低于 180 MB 分析线）

## 实测证据

| 能力 | 实现策略 | 结果 | 证据 |

## M1 冻结决策

- **保留当前实现**：透明窗口 + SetWindowRgn 命中区域 + WS_EX_NOACTIVATE/TOOLWINDOW 扩展样式、原子 JSON 偏好存储、RenderScheduler 档位、750ms 全屏探针、前端手动拖动（证据：W-01/W-02/W-03 人工实测 + 三组性能采样 idle/hidden CPU P95 均 0%）。
- **桌面模式移除出 M1 范围**：当前设备尝试了 WorkerW parent、置底模拟、Progman parent、WinEvent 钩子共四种方案，均因环境限制失败（详见 `M0手工验证清单.md`）。M1 不包含桌面模式；如未来在标准桌面环境验证任一方案可行，再单独评审引入。陪伴模式（置顶）作为唯一窗口模式。
- **M1 重点关注**：空闲私有内存 156 MB 高于 120 MB 目标，需在 M1 记录内存构成（WebView2 基线 vs 应用自身）并评估优化空间；交互状态的真实拖拽采样待人工补采。

## 未验证范围

- Windows 10 22H2 测试机：无设备，保持未测试，不做推断性通过。
- 125%/150%/200% DPI 与混合 DPI 双屏：未在真实环境验证命中区域缩放。
- 睡眠/唤醒/锁屏恢复：待人工验证。
- 真实拖拽交互下的 CPU 采样：自动化环境无人工操作，interaction.csv 为参考值。
- 标准桌面环境下的 WorkerW 桌面模式：当前设备桌面层被第三方工具替换，无法验证。

默认陪伴模式、穿透、位置恢复和合理资源基线均已通过（W-01/W-02/W-03 实测 + 资源采样），满足进入 M1 的条件。桌面模式未通过不阻止 M1，作为已知环境限制记录。
