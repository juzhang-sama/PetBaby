- 任务：新计划 Task 4，将 `cat-a-standard-v1` 迁移为均衡型 v5 基准包。
- 状态：功能通过，视觉条件通过。
- 角色包合同：`schemaVersion: 5`。
- renderer：`cat-spatial-live2d-v1`。

## 构建与合同

- 构建器先校验三个只读形体模块，再只读复制均衡模块的 `.moc3`、显示信息和中性纹理。
- 构建继续使用临时 staging；所有引用、文件存在性和 SHA-256 校验通过后才原子替换正式目录。
- Windows PowerShell 子进程使用隔离后的系统模块路径；构建器自身使用 .NET SHA-256，不依赖可能被 PowerShell 7 模块污染的 `Get-FileHash`。
- 最终包保留 8 个基础动作、4 个边缘尾巴状态、12 个语义参数、`body` / `edgeTail` 命中区和原项目许可证。
- 耳动按 profile 批准幅度限制为 `-0.15…0.15`，避免大幅形变再次暴露眼睛上方白弧。
- 呼吸保持 `ParamBreath=0.15`，由 `ParamBodyStretch` 在 `0 → 0.9 → 0` 间执行轻微胸腹变化。

### 兼容录制边界

现有 `cat-motion-evidence.ts` 仍直接调用 v4 manifest parser，不在 Task 4 允许修改范围内。动作录制时仅临时把正式 manifest 的 schema/renderer 标记为 v4 兼容值，模型、纹理、动作文件及均衡模块 `.moc3` 保持不变；录制后重新运行构建器恢复最终 v5 包。

因此动作证据索引诚实记录 `packageSchemaVersion: 4`，不能单独证明 v5 parser 路径。v5 无静态降级由上一节的独立真实 Chromium 加载证据证明；动作截图用于证明相同最终模型、纹理和动作资源的视觉结果。

## 条件通过与视觉债务

- 2026-08-15 产品决定允许 Task 4 在保留轻微呼吸和额头至鼻梁透明接缝的情况下条件通过，以便继续真实宠物照片分身主线开发。
- 该决定只豁免本阶段的视觉完成门槛，不代表接缝已经修复，也不能作为后续角色“无白线、无透明破洞”的验收证据。
- 接缝只出现在 Live2D 分层运行态，原始 `preview.png` 不存在同一缺陷；当前尚未确认根因是纹理透明边缘、UV 留白还是 ArtMesh 拼接/遮罩。
- 修复节点设在第一只真实照片分身完成后、第二体型交叉回归前。修复后必须重新导出受影响模块、更新角色包哈希，并重录标准猫及受影响照片分身的中性、闭眼峰值和回退证据。

## 已知后续优化

- 均衡模块当前呼吸幅度较轻。批准范围内的参数扫描确认更大曲线无法显著增强该 `.moc3` 的胸腹变化；本轮不回改已经冻结的 Task 3 模块。
- 该问题不影响 v5 schema、资源哈希、真实 Live2D 加载、八动作存在性或静态降级判定，按产品决定暂不阻塞后续主线开发。
- 若后续增强呼吸，应从可逆 Cubism 健康源重新绑定并导出 `body-balanced-v1`，同步更新模块哈希和跨体型视觉证据，不能只在动作文件中越过批准幅度。
- 额头至鼻梁透明接缝是独立于呼吸幅度的视觉债务。后续应先区分纹理/UV 与 ArtMesh/遮罩根因，再在可逆 Cubism 健康源上修复；不得用验收文案掩盖或用静态预览替代真实运行态复核。
