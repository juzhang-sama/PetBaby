## 首轮 Rust 失败、根因与修复闭环

### 首轮结果

在初始基线 `2f5b450` 的正确 Rust 目录首次执行 `cargo test --lib` 时，共 544 项：

- 521 passed。
- 23 failed。
- 0 ignored。
- 用时 89.07 秒。

23 项均位于 `generation::tasks::tests`，在旧 `src/generation/tasks.rs:1030` 插入 upload draft session 时触发同一 SQLite 错误：

```text
UNIQUE constraint failed: index 'creation_one_long_draft'
```

### 聚焦排除

在没有修改产品尺寸代码、没有删除旧临时目录的前提下，随后聚焦运行：

- generation 分组单线程：35/35 通过，0 ignored，33.30 秒。
- generation 分组默认并行：35/35 通过，0 ignored，21.99 秒。
- 首个原失败 exact：1/1 通过，0 ignored，0.07 秒。

这组矩阵排除了稳定的 generation 产品断言失败，也没有指向桌宠尺寸逻辑。

### 根因证据

旧 generation 测试夹具使用“进程 PID + 进程内 counter”作为系统临时目录名，并以 `create_dir_all` 打开候选目录。Windows 上夹具 `Drop` 发生时 SQLite 字段仍存活，删除失败又被忽略，导致旧测试数据库残留。系统复用 PID 后，counter 从 0 重新开始，夹具便会重新打开旧数据库，再插入第二个未完成 upload/composer 会话，从而命中 `creation_one_long_draft` 唯一索引。

首轮失败进程 PID `18148` 的临时目录提供了直接证据：33 个同前缀目录早在 02:53 已创建，07:05 首轮运行只有 counter 4、13、14、19 对应目录为新建，另有 26 个旧目录在该时段被重新触碰。

该问题属于 `#[cfg(test)]` 测试夹具隔离与析构顺序，不是产品尺寸实现失败。修复链 `be248f3`、`2b67ac9`、`05a837e` 完成了高熵候选、原子 claim、有界重试、SQLite 句柄释放后的 owned-root 清理，以及“不得清理未 claim 路径”的所有权约束。修复过程没有删除旧临时目录或真实数据库。

修复报告记录 generation 分组最终 40/40 通过，并在复核过程中多次取得 549/549 全量通过；本验收又在最终 `HEAD=05a837e` 独立 fresh 执行一次 `cargo test --lib`，得到 549 passed、0 failed、0 ignored。因此最终门禁没有沿用首轮失败前的结果，也没有用聚焦测试替代全量测试。

## 已知风险与边界

- 自动测试使用 mock 端口验证逻辑/物理像素边界，不能证明 Windows 在所有 GPU、WebView2、显示器驱动与混合 DPI 拓扑上的真实行为。
- “脚底位置近似不动”“点击区域与画面一致”包含视觉与输入体验判断，必须由真人在真实窗口中确认。
- build 仅证明两个 HTML 入口和资源可生产构建，不证明安装包、Tauri 原生窗口或 WebView 交互端到端正确。
- 4 个 Cubism SDK 条件跳过测试不属于本次尺寸功能，但仍是整仓环境覆盖缺口。
- 2 条 Rust lint expectation 警告为既有技术债，未阻塞本次测试；后续可单独清理。
- 历史 generation 临时目录仍保留在系统临时目录中；本轮没有为取得绿色结果而删除或篡改它们。夹具修复通过隔离和所有权清理消除了 PID 重用导致的复用风险。
