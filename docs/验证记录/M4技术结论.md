## 2026-08-04 透明窗口“看不到宠物”根因（已修复）

- 现象：应用重启后宠物窗口透明且屏幕无任何内容；页面加载、纹理上传、PixiJS 渲染循环（draw call）全部正常，但画布输出为空。
- 排查方法：CDP 远程调试逐步取证——页面网络/IPC 全 200；WebGL 上下文“丢失”为 PixiJS 自身探测逻辑（`isWebGLSupported` 主动 `loseContext`）；纹理经 `texImage2D(ImageBitmap)` 成功上传；最终通过捕获 PixiJS Application 实例检查舞台树，发现精灵全局坐标在 y≈515~791（画布仅 520 高），宠物整体在窗口下方。
- 根因：`computeAnchorPosition` 容器偏移公式与子元素坐标系不一致。子元素按视口坐标布局（精灵局部 y≈-9），容器缩放 0.5 后偏移应为 `锚点 × (1 - scale)`（420×520 → (105,260)），原实现返回 `锚点 × (1/scale - 1)`（(210,520)），实际渲染位置被推到视口外；`getBodyBounds`（命中区域依据）使用另一套公式，恰好与意图一致，导致“区域正确但渲染不可见”的假象。
- 修复：修正 `computeAnchorPosition` 公式与文档；同步修正 `getBodyBounds` 为真实变换 `position + local × scale`；更新单元测试。`focusable: false` 与 `--disable-gpu` 保留为基线。
- 验证：修复后屏幕可见/隐藏像素差异 36438（修复前 0）；`执行M4检查.ps1` 全量通过（前端 57 + Rust 54 + Python 24）。

## 2026-08-05 Release 复测（通过）

- 现象：release 构建（内嵌资源 + tauri.localhost）下宠物不显示；dev 模式正常。
- 根因（release 专属 CSP）：内嵌页面注入 CSP 后依次暴露三个问题——PixiJS WebGL 渲染器要求 `script-src 'unsafe-eval'`；PixiJS 创建的 blob worker 被 `worker-src` 拦截；PixiJS Assets 用 `fetch()` 加载 data: 图片被 `connect-src` 拦截（dev 页面未注入 CSP，故不暴露）。
- 修复：`tauri.conf.json` CSP 增加 `script-src 'unsafe-eval' blob:`、`worker-src blob:`、`connect-src ipc: http://ipc.localhost data: blob:`。
- 验证：release 构建下宠物显示（可见/隐藏像素差异 31062）、多宠切换（pet_set_active + 刷新）、命中区域（105,286-315,520）、动画循环（GPU 进程持续活动）均正常；全屏前台应用时宠物正确隐藏（全屏避让）。
- 遗留：Win10 真机兼容待测（`docs/验证记录/Win10兼容性检查清单.md`）；8 小时挂机冒烟未执行。

## 2026-08-05 部件化 + 骨骼化技术收尾（P2 地基）

- 背景：眨眼/呼吸/点击形变等动态显示是“生成方式 + 运行时形变”的深水区。实测确认生成平台“闭眼编辑”为整图重绘（89% 像素全变），无法做局部眨眼，因此 AI 闭眼自动生成移出 MVP。
- 契约：manifest v1 增加可选 `parts` 数组（role/relativePath/anchor/pivot/zIndex/deformable/boneId），TS `parseManifestV1` 与 Rust `parse_manifest` 同步支持并校验（归一化 0..1、整数 zIndex、role 唯一、boneId 非空）；旧 manifest 不升级仍可解析，现有单图/分层行为不变。
- 运行时地基：`runtime/bone.ts` 提供层级骨架与仿射变换纯函数（`applyBoneTransform`/`composeTransforms`/`transformPoint`）；`runtime/part-rig.ts` 的 `computePartRig` 按 manifest pivot 把部件挂到骨骼，输出世界变换与 zIndex 排序；`LayeredSprite` 新增可选 rig 挂钩（`applyRig` + `toPixiMatrix`），不破坏现有布局接口。数据链路已接通：编译器/导入器产出默认 parts（单图 `main`、分层 `body/eye-open/eye-closed`），主窗口从 manifest 读取 parts 经 PetStage 传入 LayeredSprite。
- 关闭自动闭眼：设置向导“满意”后不再发起 `kind=eye-closed` 生成；后端 `kind` 字段、`compile_layered`、`layered-v1` manifest 保留并标注为未来 mask/inpaint 局部编辑预留。
- 验证：前端 79 + Rust 66 + Python 24 全量闸门通过（`执行M4检查.ps1`，含 tauri debug 构建）。
- 后续：不实现具体动画；动态效果在生成侧（mask/inpaint、身份一致生成、LoRA）与运行时侧（Live2D/Spine 式部件化 + 骨骼形变）两条路线上推进。

## 产品架构决策（用户反馈 2026-08-04）

- 当前版本 API Key 由用户本地配置——**仅限开发期方案**，不作为最终产品形态。
- 正式产品应为 SaaS 模式：用户无需接触任何 API Key。桌面端只上传照片到**自有后端服务**，由服务端持有第三方生成平台密钥并完成生成调用与数据生命周期管理；这也同时解决照片隐私边界（照片不再直连第三方）。
- 后端中转服务（密钥托管、任务代理、照片生命周期）列入发布前关键迭代项。
