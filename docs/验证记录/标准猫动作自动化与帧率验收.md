# 标准猫动作自动化与帧率验收

日期：2026-08-14

分支：`feature/cat-visual-runtime`
对象：`cat-a-standard-v1`（v4 Live2D 标准猫）

## 验收结论

- 统一动作调度已接入 v4 运行时：用户拖拽／边缘召回优先级 100、抚摸 90、pointer focus 60、自主动作 30、idle 10。
- 双眼使用独立眼睑参数，眨眼曲线首尾连续；未使用整图缩放伪造眨眼。
- 耳朵和尾巴使用低频、有界、可暂停的确定性自动化；pointer focus 只增强眼耳尾交互，拖拽时自动化降幅。
- v4 companion 与 active 使用 60 FPS；旧宠物 companion 保持 24 FPS；隐藏、窗口模式切换和暂停状态停止帧循环，不补跑墙钟时间。
- 真实 Tauri 标准猫已成功挂载，运行日志包含 `stage-mounted`、`mount-complete` 和持续 `frame-sample`。
- 帧率目标通过；CPU 数值仅作为当前 debug 构建观察值，不判定为 CPU 性能通过。

## 自动化与调度证据

- `cat-automation.test.ts` 覆盖：双眼独立闭合、偏移曲线首尾连续、首次挂载保持睁眼、耳尾有界、pointer focus 增幅、拖拽降幅、暂停不推进且恢复不补跑。
- `cat-motion-scheduler.test.ts` 覆盖：固定优先级、用户打断、夜间权重、暂停随机计时、迟到 completion、edgeHidden 锁定与 edgeRecall 回退。
- `pet-stage.test.ts` 覆盖：v4 挂载、任意身体命中抚摸、4px 拖拽阈值、pointer enter/leave、pointer 参数映射、热切换同步、60/24 FPS 实际 cadence 和一秒帧样本。
- `parameter-mixer.test.ts` 覆盖：自动化层之后由交互层覆盖，物理层最后混合；所有写入由模型参数范围夹紧。

## 真实运行时纠偏

真实 Tauri 验证先后暴露并修复两项仅靠 mock 未发现的问题：

1. Cubism SDK 实际循环接口是 `motion.setLoop(boolean)`，错误的 `setIsLoop` 会令标准猫挂载失败。已增加源码合同测试，禁止错误方法名重新进入 bundle。
2. 原帧限速以“上一实际渲染帧”为硬阈值，受 16.6/16.7ms rAF 浮点抖动影响，真实 v4 约只有 40 FPS。改为 deadline 调度后，真实日志稳定在 16.5–16.8ms。

## 判定边界

- 专项规格的 60 FPS 体验目标：通过。
- 当前短时采样未见内存单向增长，但不能替代长时稳定性测试。
