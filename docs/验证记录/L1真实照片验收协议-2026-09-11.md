## 3. 步骤

1. 设置两个环境变量，启动 Python 后端（FastAPI，`app.py`）。
2. 用生产构建启动桌面应用：
   ```
   npx vite build --emptyOutDir=false
   npx tauri build --no-bundle --config _codex-threads/tauri-build-override.json
   ```
   验收 exe 大小 **86.5 MB**（内嵌 assets，二进制内可搜到 `builtin-pets`）。
   17 MB 那种是 dev 模式，不能用。
   **GUI 必须老王手动启动** —— 工具侧拉不起桌面进程。
3. 在设置页逐个上传，走完 pixel 流程直到安装完成。
4. 每只记录下表；失败要记错误码（`domain.rs:43-54` 的 10 类之一）。

## 4. 通过判据（L1）

**肉眼判定 = 权威**，机械指标只用来排雷。L1 通过 = 同时满足：

- **身份可辨认**：主人能认出这是同一只（五官比例、毛色、花纹、瞳色）。
- **动态自然**：呼吸与整体摇摆无可见穿帮（无撕裂、无边缘抖动、无背景残留）。

**不要求**逐帧动作。用户上传产物是 schema 3，只有程序化呼吸/摇摆，
与内置 04/05 的帧序列视觉**必然有差距**，这属预期，不算失败。

## 6. 跑之前先知道的既有问题（否则会把已知缺陷当新 bug）

- **D2 硬拒绝依赖模型诚实**：鸟 / 风景 / 多只合影可能被幻觉成 `cat` 而通过。
- **上传宠物的 `pets.species` 被硬编码 `'cat'`**（`pets/repository.rs:359` 传入 `Species::Cat`），
  即使分析判定为 `dog` 也一样。当前无消费者，不影响外观，但拿 dog 样本时别因此误判。
- 输入侧已有约束：1–8 张、仅 JPEG/PNG、单张 ≤10 MiB、总计 ≤40 MiB、边长 [256,4096]、≤16M 像素。
