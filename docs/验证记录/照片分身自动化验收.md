# 照片分身自动化验收

## 范围

本次仅使用非个人 PNG 与 `FakePhotoAvatarProvider`，不请求真实供应商、不上传真实照片、不产生付费调用。fake provider 输出明确的合成非身份 atlas，不复用标准猫的脸、毛色、眼睛或花纹；fake 证据只证明链路与动态，不证明真实宠物身份相似。

## 已验证

- 前端 `photo-avatar-e2e.test.ts`：命令参数按 `createCreationApi` 真实实现转发；验收页存在并以 `mountPhotoAvatarPreview` 为唯一入口。
- Rust `tests::task_12_balanced_success_crosses_commands_builder_and_finalization_port`：真实 fake provider submit 3 次，manager 经过 build V5，builder 产出 `schemaVersion: 5`、`renderer: cat-spatial-live2d-v1`，runtime check 通过，`PhotoAvatarFinalizationPort` 安装并清理原图，零 v3/static fallback。
- Rust 场景实际提交两张不同的非个人 PNG；验收页由 `mountPhotoAvatarPreview` 装配真实 `Live2DRenderer`，并以原始 `manifest.json` 字节 hash 驱动 runtime check。
- Chromium 证据已生成 26 张截图（八动作各中性/峰值/回退，另含 2 张独立抚摸与拖拽打断），`证据索引.json` 记录 `schemaVersion=5`、`renderer=cat-spatial-live2d-v1`、原始 manifest hash、真实动作调用、统一 420x520 尺寸和八动作关键帧像素差；截图人工抽查未复用标准猫旧证据。呼吸帧明确记录为 authored motion 加现有 idle automation，因为 fake atlas 的 authored ParamBreath 在该 moc 上无可见几何变化；没有放宽像素门槛。
- 既有聚焦测试承担的场景：重试与第三次失败（`retries_each_remote_step_three_total_attempts_without_counting_polls`、`non_retryable_and_third_retryable_failure_are_terminal`）、取消迟到响应（`cancellation_rejects_late_result_and_stops_submits`）、关闭恢复（`restart_with_attached_job_polls_without_resubmitting`）、局部锁定（`tail_only_revision_rejects_a_changed_body_module`）、远端删除恢复（`failed_remote_delete_is_resumed_until_cleanup_completes`、`accepted_preview_deletes_local_sources_and_resumes_remote_cleanup_without_reinstall`）。

## 限制

当前 Cargo 依赖未启用 `tauri` 的 `test` feature，命令级夹具调用与 Tauri command 相同的 manager/helper，而不能构造 `tauri::test::mock_builder`；生产命令注册和前端参数接线仍有独立证据。为支持 Windows 下 v5 nested asset 读取，`photo_avatar/store.rs` 已将规范化 `/` 路径按安全组件逐段拼接，Rust 回归已通过。

录制使用受控 Rust fake fixture 导出和带 `Access-Control-Allow-Origin: *` 的本地静态服务；不请求真实供应商、不上传真实照片、不产生付费调用。Playwright CLI daemon 在本机 Windows 触发既有 UV assertion，因此脚本最终使用同一 Chromium 通过 `playwright-core` 直接驱动；这不改变浏览器页面、renderer 或截图边界。
