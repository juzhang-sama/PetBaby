## 前端状态机精确证据

使用完整 `describe + it` 名称构造转义后的首尾锚定正则，通过 `npx vitest run <文件> -t <精确正则>` 串行执行。每条都是 1 passed、0 failed；本组 11/11：

1. `PetProfileEditor does not let a stale load failure clear the current pet`
2. `PetProfileEditor clears the previous pet immediately and keeps controls locked when the next load fails`
3. `PetProfileEditor disables the form while saving and preserves input on failure`
4. `PetProfileEditor keeps canonical values and reports saved-but-not-refreshed without a success claim`
5. `PetProfileEditor treats a repeated open for the same loaded pet as focus, not another request`
6. `PetProfileEditor cancels with Escape and restores focus to the edit trigger`
7. `PetProfileEditor can cancel while loading and ignores the late response`
8. `PetProfileEditor handles Escape while loading and restores the trigger`
9. `buildPetListRows offers edit only for user pets and never for the built-in pet`
10. `PetProfileEditor opens a user profile and saves the canonical result before refreshing and closing`
11. `pet profile contract rejects an invalid birth date value at the runtime boundary`

组合证据：

- A→B 切换：A 的迟到失败不会清空 B；B 开始加载时立即清除 A 的旧字段，B 失败后字段仍锁定且可取消。
- 保存失败：保存期禁用表单，update reject 后用户输入“保留我”仍在，表单恢复可编辑，错误区为 alert。
- 刷新失败：update 已返回 canonical 但 `refreshCatalog` 返回 false/reject 时，保留 canonical 字段和编辑面板，显示“已保存但刷新失败”的内联错误，不发出全局保存成功提示。
- 焦点：已加载的重复打开只聚焦名称；Escape/取消在已加载和加载期均能关闭面板、忽略迟到响应并将焦点还给编辑触发按钮。
- 内置宠物：view-model 仅向用户宠物生成 edit action，内置宠物无编辑按钮；后端仍有独立只读防线。
- 正常保存：编辑器应用 canonical 返回值，调用列表刷新，在刷新成功后关闭并发出成功状态。
