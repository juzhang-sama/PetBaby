# 固定帧动作资源协议 v1（schemaVersion 6 / renderer: frame-sequence-v1）

## 1. 背景与目标

PetBaby 的宠物动画路线是**逐帧重绘**（整数位移 + 覆盖重画，锚点零变化、循环首尾同帧、像素硬边），而非形变或骨骼。当前运行时（`apps/desktop/src/runtime/`）只消费两类资源：

| schemaVersion | renderer | 说明 |
|---|---|---|
| 1 | static-png | 单张静态图 |
| 2 / 4 / 5 | live2d | Live2D 模型（Cat 系列） |
| 3 | animated-image-v1 | 单张整图 + 程序化形变（呼吸切片/摇摆），**非逐帧** |

三只像素宠物（01-longhair-black-white、02-round-tabby、03-sleek-black）已产出逐帧动作资源（GIF + 逐帧 PNG + 审计数据），但运行时**没有对应的逐帧契约**，无法被桌面运行时消费。

本协议定义**固定帧动作资源契约（schemaVersion 6）**，让逐帧产物以与 v1~v5 相同的方式进入运行时管线，是"把三只宠物接入真实桌面运行时"的第一步，也是后续动作精细化/第三方代工 GIF 填入的固定接口。

## 2. 设计原则

1. **兼容并存**：新增 schemaVersion 6，不改动 v1~v5 的解析与渲染路径；`parseRuntimeAssetManifest` 的 switch 增加一个 case。
2. **帧资源是事实来源**：逐帧 PNG 直接进 manifest 的 `files`（带 sha256），渲染器只做"按时序贴帧"，不推导、不形变。
3. **动作语义由产物决定**：PetMotion（idle/react-* 等）到具体动作资源（breath/blink/tail-wag）的映射写在 manifest 的 `semantics` 里，运行时不硬编码，未来加动作只改资源包。
4. **每动作独立帧时长**：GIF 实测各动作帧延迟不同（breath≈180ms、blink≈150ms、tail-wag≈120ms），因此帧时长按动作声明，不用全局 fps。
5. **锚点纪律显式声明**：产物审计已保证 `ground_anchor_changed_pixels = 0`，契约用 `anchorPolicy: "fixed"` 声明，渲染器按同一锚点贴帧。

## 4. 字段详解

### 4.1 顶层

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `schemaVersion` | number | ✅ | 固定为 `6` |
| `renderer` | string | ✅ | 固定为 `"frame-sequence-v1"` |
| `petId` | string | ✅ | 宠物唯一 ID（如 `01-longhair-black-white`），须与运行时激活 petId 一致 |
| `variantId` | string | ✅ | 形象变体 ID（如 `pixel-mid-simple-v1`） |
| `displayName` | string | ✅ | 展示名（长毛黑白猫） |
| `species` | string | ✅ | `"cat"` 或 `"dog"` |
| `baseImage` | string | ✅ | 母版静态图相对路径（PNG，用于预览/降级/命中判断） |
| `defaultAction` | string | ✅ | 无动作时的常驻动作（通常 `"breath"`），必须存在于 `actions` |
| `anchorPolicy` | string | ✅ | 固定为 `"fixed"`，声明地面锚点零变化纪律 |
| `actions` | array | ✅ | 动作资源列表，至少 1 项，见 4.2 |
| `semantics` | object | ✅ | PetMotion → actionId 映射，见 4.3 |
| `blink` | object | 可选 | 眨眼自动触发参数，见 4.4 |
| `hitBounds` | object | 可选 | 归一化命中框（0~1），缺省时按 baseImage 全幅 |
| `files` | array | ✅ | 全部资源文件清单（含 sha256），复用 v1/v3 校验规则 |

### 4.2 actions 项

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `actionId` | string | ✅ | 动作 ID（`breath` / `blink` / `tail-wag` …），全局唯一 |
| `loop` | boolean | ✅ | 是否循环；占位动作全部 `true`（循环首尾同帧） |
| `frameDurationMs` | number | ✅ | 单帧停留毫秒数（GIF 实测：breath=180、blink=150、tail-wag=120） |
| `frames` | string[] | ✅ | 帧 PNG 相对路径，按播放顺序排列；**首帧与末帧必须视觉一致（循环闭合）** |

### 4.3 semantics（PetMotion 映射）

运行时 `PetRenderer.playMotion()` 收到的语义动作（`PetMotion`）映射到本协议的动作资源：

| PetMotion | 映射建议 | 说明 |
|---|---|---|
| `idle` | `defaultAction`（breath） | 常驻呼吸 |
| `react-happy` / `react-curious` | `tail-wag` | 交互反应 |
| `look-left` / `look-right` / `sleep` / `wake` / `carried` / `landed` | 可缺省 | 当前无对应帧资源；渲染器回退到 `defaultAction`，未来产物补齐后加映射 |
| CatMotionNameV1（live2d 系列） | 不可映射 | 固定帧渲染器 `supportsCatMotionV1()` 返回 false，由上层回退 |

### 4.4 blink 自动触发

| 字段 | 类型 | 说明 |
|---|---|---|
| `enabled` | boolean | 是否启用自动眨眼 |
| `minIntervalMs` / `maxIntervalMs` | number | 下次眨眼随机间隔区间 |

渲染器在 idle 状态下按随机间隔插入一次 `blink` 动作（播完回到 defaultAction）。

## 5. 与现有契约的关系

- **解析入口**：`manifest-schema.ts` 的 `parseRuntimeAssetManifest` switch 增加 `case 6`，复用现有 `object`/`requiredString`/`parseRect`/sha256 校验工具（v3 同款），文件条目校验与 v1/v3 完全一致。
- **渲染器分发**：`pet-renderer-bootstrap.ts` 的 `createPetRendererRuntime` 增加 `manifest.schemaVersion === 6` 分支，创建 `FrameSequenceRenderer`（新实现），与 animated-image-v1 并存。
- **资源类型**：`PetRenderAsset` 增加 `{ kind: "frame-sequence"; baseImageUrl; actions; semantics; blink; hitBounds }`。
- **加载器**：新增 `loadFrameSequenceAsset`（仿 `loadAnimatedImageAsset`：解析 manifest → 生成帧 URL 列表）。
- **渲染器接口**：`FrameSequenceRenderer implements PetRenderer`，复用 `AnimatedImageRenderer` 的视口/布局/命中模式（`computeContainRect`、dpr 变换、`imageSmoothingEnabled = false` 硬边、hit canvas），仅把"形变绘制"替换为"按帧索引贴帧"。

## 6. 资源打包

三只宠物帧资源实测体积（1024×1024 PNG）：

| 宠物 | blink | breath | tail-wag | 母版 | 合计 |
|---|---|---|---|---|---|
| 01-longhair-black-white | 112KB (5帧) | 179KB (8帧) | 203KB (9帧) | 21KB | ≈516KB |
| 02-round-tabby | 129KB (5帧) | 207KB (8帧) | 234KB (9帧) | 25KB | ≈597KB |
| 03-sleek-black | 65KB (5帧) | 105KB (8帧) | 118KB (9帧) | 12KB | ≈301KB |

三只合计 ≈1.4MB，适合作为 **builtin 资源**（`apps/desktop/public/builtin-pets/<petId>/`）由 Vite 直接 serve，与现有 Live2D builtin 宠物同路径策略；后续接入 installed（Tauri 资源安装）时只需把目录迁移。

## 7. 未来扩展（动作精细化 / 第三方代工）

- **换动作不改契约**：第三方代工交付符合规范的 GIF → 导出逐帧 PNG（与现有帧同尺寸同锚点）→ 替换 `frames/` 并更新 `files` 的 sha256 → 契约结构零改动。
- **加动作不改渲染器**：新增 actionId + semantics 映射即可，渲染器按帧列表泛化播放。
- **质量门槛**：新帧资源须通过现有动作审计（`loop_closed=true`、`ground_anchor_changed_pixels=0`）后才允许替换。

## 8. 验收标准

1. `parseRuntimeAssetManifest` 能解析 schemaVersion 6 示例，且对缺字段/错类型/坏 sha256/非循环闭合帧数异常报错（单测覆盖）。
2. `pet-renderer-bootstrap` 对 v6 manifest 分发到 `FrameSequenceRenderer`，v1~v5 行为不变（现有测试全绿）。
3. 三只宠物注册为 builtin 宠物后，桌面运行时能加载并显示，idle 下自动 breath + 随机 blink，触发 react 播放 tail-wag。
4. 逐帧渲染硬边（`imageSmoothingEnabled=false`），首尾帧循环无跳变。
5. 测试基线保持全绿（当前 1044 passed | 17 skipped）。
