## 二、每个模型有两条协议；我们走「本站媒体协议」

`seedance-2.0-guanfang` 的 `protocols` 数组给出两条：

| | 火山方舟格式（默认） | **本站媒体协议（我们用这条）** |
|---|---|---|
| base | `{domain}/api/v3` | `{domain}` |
| 创建 | `POST /api/v3/contents/generations/tasks` | **`POST /v1/media/generate`** |
| 查询 | `GET /api/v3/contents/generations/tasks/{id}` | **`GET /v1/skills/task-status?task_id=`** |
| model 字段 | `doubao-seedance-2-0-260128`（`-fast-` / `-mini-`） | **`seedance-2.0-guanfang`** |
| 请求体 | 火山原文（content 按 role 排） | 本站 `{model, prompt, params}` |

→ **走本站协议不需要碰火山格式**，现有 `photo_avatar_backend.lk888_client` 的提交/轮询/下载骨架可直接复用。

## 三、`seedance-2.0-guanfang` 的参数表（本站协议）

| 参数 | 类型 | 必填 | 取值 | 说明 |
|---|---|---|---|---|
| `mode` | segment | 否 | `shouweizhen` / `cankaosheng` | 首尾帧 / 参考生。**这是我们的图生视频入口** |
| `version` | select | **是** | `Mini` / `快速` / `标准` | 映射 Ark model 字段 |
| `duration` | select | **是** | `auto` / `4`…`15` | 按秒版**没有 `auto`**，必须整数 |
| `resolution` | select | **是** | `480p` / `720p` / `1080p` / `4K` | `1080p`/`4K` 仅 `version=标准` |
| `aspect_ratio` | select | 否 | `adaptive` / `16:9` / `4:3` / `1:1` / `3:4` / `9:16` / `21:9` | 我们要 `1:1` |
| `images` | upload | 否 | 数组 | 按 mode 解读：首帧 / 首尾帧 / 参考图（≤9） |
| `_quan_neng_mode` | select | 否 | `quan_neng` / `edit` / `extend` | 全能参考/改片/续写，本路线不用 |
| `image_url` / `video_url` / `audio_url` | upload | 否 | 数组 | 全能参考用；**视频只能传公网 URL** |

**图片可 base64 内联**（仅 `POST /v1/media/generate` 支持）：单文件解码后 ≤10MB、单次合计 ≤30MB、请求体 ≤50MB。1024×1024 绿幕首帧 PNG 约 1~2MB，安全。

## 四、价格与余额（决定能不能真跑）

### ✅ 已定性（2026-09-12 真跑）：这把 key 的余额确实是 2.7，不是 50+

`GET /v1/skills/balance`（同一把 key，前缀 `sk-94960…`）→
```json
{"api_key_quota":{"limit":0,"used":303.6},"balance":2.7,"unit":"算力"}
```
官方 `v1-skills.json` 对该字段的定义是「**用户账户的算力余额**」（账户级），`api_key_quota.limit=0` 表示该 key 不限额。

**真跑一支按秒版视频（Mini+480p+4s）后，三处数据精确对账：**
- `usage?detail=1` 新增一条：`seedance-2.0-guanfang-anmiao | video | success | cost=0.6912 | 官方特惠`
- `balance`：2.7 → **2.0**（下降 0.7 = 0.6912 四舍五入）
- `api_key_quota.used`：303.6 → **304.3**（增加 0.7）

→ **余额是真实可消费的算力，真的扣了钱、视频真的生成了**。老王网页看到的「50+」与这把 key 不是同一个口径
（另一个账号，或网页显示的是别的单位/累计值，而非当前「算力余额」）。

**结论：按秒版 Mini+480p = 0.1728 算力/秒，本 key 余额只剩 ~2.0 算力（约 11 秒的 Mini+480p 视频）。**

### 单价（按秒计费版，`官方特惠` 渠道，active）

| 配置 | 算力/秒 | 5s 合计 | 2.7 够不够 |
|---|---|---|---|
| 标准 + 720p | 0.7776 | 3.89 | ❌ |
| 快速 + 720p | 0.6192 | 3.10 | ❌ |
| Mini + 720p | 0.3888 | 1.94 | ⚠️ 勉强 |
| **Mini + 480p** | **0.1728** | **0.86** | ✅ |

按 token 版（`官方特惠`）只给单价、**无法预估单条总价**。
→ 首次真跑建议用**按秒 + Mini + 480p + 4s（≈0.69 算力）**：这个档位即使余额真是 2.7 也跑得起，
跑完还能顺便把上一节的余额矛盾验掉。

## 七、已知风险 / 未验证

1. ✅ **`mode` 参数（type=segment）已被真跑验证接受**（2026-09-12：`mode=shouweizhen` 提交成功、正常出视频）。
2. 网页上有的旋钮 API 没有对应参数：**运动强度**、**音频开关**、**独立负向提示词字段**。建国那批视频是网页手工做的，**API 出来的结果可能与之不同**；脚本目前把负向词追加进主提示词作为替代。
3. 按 token 版单价无法预估总价，容易一次超预算。
4. ✅ **余额已定性**（见第四节）：本 key 只剩 ~2.0 算力，动钱之前用按秒 + Mini + 480p 最省。
5. 全链路（视频 → 抠像 → 帧序列打包 → 安装）仍未打通；本次补了「视频生成」这一环并真跑验证，抠像起仍是缺口。
