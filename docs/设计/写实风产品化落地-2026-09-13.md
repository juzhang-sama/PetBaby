## 一、摸清的硬约束（决定切法，别绕过）

1. **artifact 只认 PNG，且一个 job 只能有一个 artifact。**
   `job_store._decode_artifact` 硬校验路径必须以 `.png` 结尾；`app.py` 的
   `/v1/photo-avatar/artifacts/{id}` 写死 `media_type="image/png"`。
   → 最终产物（288 帧 + manifest）**必须打成 zip** 才走得通现有通道，需要扩契约。

2. **job 结果不跨后端重启。** `job_store._load_state` 对
   `step != "renderTextureAtlas"` 的 succeeded job：删 artifact + 标记 failed
   （`"job result unavailable after restart"`）。视频链路耗时 5~15 分钟，
   客户端必须在下一次后端重启前把包下载并安装完。**这条要确认能不能接受。**

3. **服务缺 scipy。** `requirements.txt` 有 numpy/pillow，**没有 scipy**；
   `poc_抠像.py` 依赖 `ndimage.label / ndimage.sum / binary_closing /
   binary_opening / gaussian_filter`。启动脚本的探测串也只探
   `fastapi, uvicorn, httpx, PIL, numpy`。
   → **加依赖**（不改算法），并同步更新探测串。重写这 5 个调用有质量回归风险。

4. **步骤名是硬编码白名单**：`contracts._STEPS` / `_PIXEL_STEPS`、
   `job_store._STEPS`。`attempt` 上限 3。

5. **`creation_photo_avatar_*` 八个命令全绑在 `PixelPhotoAvatarManager`**
   （`lib.rs:1070-1179`）→ 新路线要按 route 分派，不是加命令。

## 二、步骤切分：两个，不是六个

| step | 内容 | 产物 | 为什么这样切 |
|---|---|---|---|
| `generateMotionSource` | 母版 → 绿幕首帧（取景收敛）→ 视频 | mp4，**留在服务侧 scratch，不上传** | 视频是唯一大额支出（12s 标准 480p = **5.69 算力**），单独一步才能做到「只重试这一步」 |
| `packFrameSequence` | 抠像 → 四判据 → 打包 schema7 → WebP → zip | zip（最终包 artifact） | 后半段便宜（0 算力），挂了整段重跑无所谓 |

**不拆成六步**：Rust 侧状态机要跟着长 6 倍，而中间步骤没有独立重试价值。
**不合成一步**：视频失败要重付 5.69，粒度太粗。

#### 第 4 片：串链（2026-09-13）已完成

`build_frame_sequence(video, out_dir, ...)` = 抠像 → 四判据 → 打包 WebP → zip，
**不碰任何 API、跑一次 0 算力**。`out_dir` 必须空（中间产物上百个文件，
原地重跑要批量删除会被本机守卫拦），调用方给每个 job 一个新 scratch 目录。

用已存的 `绿幕视频-135364519.mp4` 端到端复跑（`output/…/12-流水线-回归/`），结论：

| 比对项 | 结果 |
|---|---|
| 抠像帧 vs 黄金产物 | **288/288 逐字节一致**（证明 pipeline 没动算法） |
| WebP 解码 vs PNG 源帧 | **alpha 288/288 逐像素无损** |
| WebP 有损量 | 全图平均 9.4/255，**不透明区（alpha≥200）只有 2.5/255** |
| 肉眼 | 整帧 + 最差区域放大 3 倍均**分辨不出**（`_对比/` 下两张图） |
| manifest | 归一扩展名后**逐键相同**，只剩已知的 `_provenance.generator` |
| zip | **二次打包字节相同**（条目排序 + 时间戳固定成 `(1980,1,1)`） |
| zip 自洽 | 288 项 sha256 与 manifest 全对得上（Rust 安装时要校的就是这个） |

交付物：`<out_dir>/<petId>.zip` **9.7 MB**（PNG 源帧 72.6 MB / 288 帧，约 7.5 倍）。

**顺带收掉**：`MIN_FRAMING_MARGIN` 与 `MARGIN_MIN` 两份定义已合成一处 ——
常量落在**无依赖**的 `frames/__init__.py`，`first_frame.py` 与 `scripts/一键出宠.py` 都从那里 import。

⚠️ **两个 step 的边界**：`generateMotionSource`（母版+首帧+视频，5.69 算力）产出的 mp4
留服务侧 scratch，**不放进这个 zip**；`packFrameSequence` 只吃 mp4。
⚠️ **证据图不在这条链的产物里**：zip 只有运行时包（manifest + 帧），
而人工确认要看 `05-验收/` 的证据图。「证据图怎么送到客户端」是第 5 片契约扩展要定的
（一个 job 只能有一个 artifact），本片不做假设。

#### 第 5 片：契约扩展（2026-09-13）已完成

新增**第三种请求形状** `FrameStepRequest`（`route = "frame-video-v1"`），
与 `StepRequest`（legacy）/ `PixelStepRequest`（`pixel-v1`）并列，`parse_step_request` 按 route 分派。
11 个字段，其中 2 个是写实风特有的：

```
route sessionId revision providerSessionId step attempt consentVersion
sourceImages  petId displayName species
```

两个 step **共用一份字段**，差别只落在 `sourceImages` 上（`_require_exact_fields` 要求精确匹配）：

| step | sourceImages | 输入从哪来 |
|---|---|---|
| `generateMotionSource` | 照片 1..8 张 | 母版从照片生成 |
| `packFrameSequence` | **必须为空** | 上一 step 落在 `scratch/<providerSessionId>/motion-source.mp4` |

→ `packFrameSequence` 收下照片只会在实施层变成一个「悄悄忽略」的分支，**在契约层就拒**。
→ `packFrameSequence` 必须带 `providerSessionId`（没有它找不到 scratch 里的 mp4）。

**产物与媒体类型**：`FrameSequenceArtifact` 让 `job_store` 把 zip 写进 `artifacts/<id>.zip`，
`artifact_media_type()` 按扩展名回 `application/zip`（artifact 端点原先硬编码 `image/png`）。
`read_artifact` 的返回类型没动（被测试大量 `== bytes` 那样用），另开一个方法问 MIME。

**证据图不送客户端（本片定的一处契约）**：zip 里只有运行时包，`05-验收/` 的证据图留在服务侧。
理由：客户端要人工确认的是「桌宠动起来像不像」（第 6 片装进预览位），不是那五张图；
而一个 job 只能有一个 artifact。`overallPassed` / `failedCriteria` 随 `resultType: "frameSequence"`
回去，够客户端提示「检测到哪条异常」。要改的话代价是「一 job 多 artifact」，先不做。

**`generateMotionSource` 当时还没实现**（第 5b 片补上，见下）：它抛 `FramePipelineError`
（→ 客户端看到 `temporaryUnavailable`，**不是** `invalidInput` —— 请求本身没错，
是服务还没这个能力）。缺口在**提示词**：真正要发给 lk888 的两份提示词原先躺在
`output/_通用母版提示词-2026-09-12.txt` 与 `output/_通用组合循环提示词-2026-09-12.txt`
里，**而 `output/` 在 `.gitignore` 里** —— 服务根本拿不到它们；而且那是两份
「给人看的完整文档」，真正的提示词夹在「与建国版的区别」和「保存位置」之间，
靠脚本按 `【主提示词】` / `-----` 切出来。

##### 白名单：`provider_model` 不是随便记的字符串

`audit.py` 的 `_MODELS = {"gpt-4o", "gpt-image-2"}` 是**允许值白名单**，
`AuditContextV1.from_state` 会重新校验 —— 写个不在里面的名字，会在 `reserve()` 阶段
就以 `AuditContractError` 炸掉（测试先撞上的，不是生产）。已加 `seedance-2.0-guanfang`：
那条链上母版只要 0.06 算力，5.69 全花在视频上，追溯时记它才诚实。

##### artifact 不跨重启（沿用既有约束）

`job_store._load_state` 对 `status == "succeeded" and step != "renderTextureAtlas"`
会删 artifact 并标 `failed`（只有 `renderTextureAtlas` 例外，它的 wire 不需要内存里的 result）。
对写实风代价可接受且是**有意选的**：用户重试时 `packFrameSequence` 0 算力重跑，
mp4 还在 scratch 里，**不会重付视频那 5.69**。这正是「存中间 mp4 兜底」那条决策的用处。

##### `generateMotionSource` 实现

`母版（gpt-image-2）→ 首帧取景收敛（免费阶梯）→ 视频（Seedance）`，mp4 落
`scratch/<providerSessionId>/motion-source.mp4`。三条防线保证不白花那 5.69：

1. **已有 mp4 直接复用**（一次上游都不打）。后端重启会把 job 结果清掉
   （`_load_state` 对非 `renderTextureAtlas` 的成功态标 failed）→ 同 session 重试
   白捡回那支视频。要真重跑就换 `providerSessionId`（= 用户点「重新生成」）。
2. **取景收敛在免费阶梯上做完再进视频**（`SCALE_LADDER` 0.90→0.75）。全挂 = 照片的问题，
   报 `invalidInput` 并**不提交视频**（测试里断言 `submit_video` 没被调过）。
3. **上游错误码原样透出**：`contentPolicy` 这类不可重试的错误不包成
   `temporaryUnavailable`，否则上层会拿同一份提示词再撞一次审核。

另外两处顺带定死：

- **mp4 原子落地**（先写 `.part` 再 `replace`）。`packFrameSequence` 只判断
  `video.is_file()`，半支视频会被当成完整的往下跑。
- **只上报视频这一个 provider task id**。一个 job 的 `lk888_task_id` 是单选
  （上游删除要用它），报第二个不同的 id 会被 `job_store` 拒掉、整个 step 失败；
  母版那个记在 `MotionSource.master_task_id` 里回客户端。

##### wire 形状

`generateMotionSource` **没有 artifact**（mp4 一个字节都不往客户端送）：

```json
{"resultType": "motionSource", "videoBytes": 9600000, "reused": true,
 "masterTaskId": null, "videoTaskId": null, "firstFrameScale": null,
 "firstFrameLeftMargin": null, "firstFrameRightMargin": null}
```

失败码：`FramePipelineError.code` 默认 `temporaryUnavailable`，取景全挂显式给
`invalidInput`；`Lk888Error` 照旧带自己的 `code`。

##### 一处待老王拍板：毛长档位

## 五、已定决策（2026-09-13 老王确认）

1. **job 结果不跨重启 → 接受，但服务侧存中间 mp4 兜底。**
   不加 job 结果持久化（要动那套不可变审计，成本高、只省一单 5.69）。
   真正要防的是**用户中途关应用**（后端跟着死）—— 所以把 mp4 落在
   `scratch/<sessionId>/motion-source.mp4`：重试同一 session **直接复用，不重付视频**；
   用户点「重新生成」时显式要求重跑（否则会一直复用旧的）。
   白做代价从 **5.69 算力 → 0**。
2. **zip 走现有 artifact 端点**（扩 `.zip` 支持），不新加端点 ——
   新端点要把鉴权/404/tombstone/会话删除再写一遍，而现有端点只差扩展名判断 + media type。
3. **WebP 在服务侧转** —— zip 从 74MB 降到约 8MB，直接决定用户等多久。
4. **取景收敛全挂 → 让用户换照片**，但先把免费阶梯（0.90→0.75）试完；
   中途失败**不打扰用户**（自动重试静默），只在全挂时报
   「这张照片不适合，换一张正面坐姿、尾巴收拢的」。
   继续缩比换照片更糟：主体变小、与内置显示尺寸不一致。
