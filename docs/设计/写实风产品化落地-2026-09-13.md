## 一、摸清的硬约束（决定切法，别绕过）

1. **artifact 只认 PNG，且一个 job 只能有一个 artifact。**
   `job_store._decode_artifact` 硬校验路径必须以 `.png` 结尾；`app.py` 的
   `/v1/photo-avatar/artifacts/{id}` 写死 `media_type="image/png"`。
   → 最终产物（288 帧 + manifest）**必须打成 zip** 才走得通现有通道，需要扩契约。

2. **job 结果不跨后端重启。** `job_store._load_state` 对
   `step != "renderTextureAtlas"` 的 succeeded job：删 artifact + 标记 failed
   （`"job result unavailable after restart"`）。视频链路耗时 5~15 分钟，
   客户端必须在下一次后端重启前把包下载并安装完。**这条要确认能不能接受。**

3. **服务缺 scipy。** `requirements.txt` 有 numpy/pillow，**没有 scipy**；
   `poc_抠像.py` 依赖 `ndimage.label / ndimage.sum / binary_closing /
   binary_opening / gaussian_filter`。启动脚本的探测串也只探
   `fastapi, uvicorn, httpx, PIL, numpy`。
   → **加依赖**（不改算法），并同步更新探测串。重写这 5 个调用有质量回归风险。

4. **步骤名是硬编码白名单**：`contracts._STEPS` / `_PIXEL_STEPS`、
   `job_store._STEPS`。`attempt` 上限 3。

5. **`creation_photo_avatar_*` 八个命令全绑在 `PixelPhotoAvatarManager`**
   （`lib.rs:1070-1179`）→ 新路线要按 route 分派，不是加命令。

## 二、步骤切分：两个，不是六个

| step | 内容 | 产物 | 为什么这样切 |
|---|---|---|---|
| `generateMotionSource` | 母版 → 绿幕首帧（取景收敛）→ 视频 | mp4，**留在服务侧 scratch，不上传** | 视频是唯一大额支出（12s 标准 480p = **5.69 算力**），单独一步才能做到「只重试这一步」 |
| `packFrameSequence` | 抠像 → 四判据 → 打包 schema7 → WebP → zip | zip（最终包 artifact） | 后半段便宜（0 算力），挂了整段重跑无所谓 |

**不拆成六步**：Rust 侧状态机要跟着长 6 倍，而中间步骤没有独立重试价值。
**不合成一步**：视频失败要重付 5.69，粒度太粗。

#### 首帧的两处差异（第 3 片，2026-09-13）

1. **有意修的**：`analyze_master` 的 `thinStructureRatio` / `veryThinStructureRatio`
   旧实现是 `try: import cv2` —— 装了 opencv 出数字、没装出 `null`。
   **同一个脚本换台机器跑就产不同的 JSON**（实测：`D:\DevTools\Python312` 有 cv2 出数字，
   后端解释器没有出 `null`）。对一个要进服务的模块，这是不可接受的隐藏依赖。
   已固定成 scipy（本模块的既有依赖），**数值与 cv2 路径逐位相同**
   （同一母版都是 `0.0114 / 0.0224`），而 `output/` 下 8 只宠物的历史记录**全都有数字** ——
   说明 `null` 才是异常（那一次恰好跑到了没有 cv2 的解释器）。
2. **不是差异的差异**：`首帧分析.json` 里 3 个路径字段记的是**产物写在哪**，
   回归时写到了 `01-首帧-回归/` 而不是 `01-首帧/scale-90/`，所以字符串不同 —— 数值全同。
   `验收报告.json` 的 5 个 `evidence.*` 同理。

回归产物留在原地产物旁边的 `01-首帧-回归/`、`04-抠像-回归2/`、`05-验收-回归/`（`output/` 已被 gitignore）。

## 五、已定决策（2026-09-13 老王确认）

1. **job 结果不跨重启 → 接受，但服务侧存中间 mp4 兜底。**
   不加 job 结果持久化（要动那套不可变审计，成本高、只省一单 5.69）。
   真正要防的是**用户中途关应用**（后端跟着死）—— 所以把 mp4 落在
   `scratch/<sessionId>/motion-source.mp4`：重试同一 session **直接复用，不重付视频**；
   用户点「重新生成」时显式要求重跑（否则会一直复用旧的）。
   白做代价从 **5.69 算力 → 0**。
2. **zip 走现有 artifact 端点**（扩 `.zip` 支持），不新加端点 ——
   新端点要把鉴权/404/tombstone/会话删除再写一遍，而现有端点只差扩展名判断 + media type。
3. **WebP 在服务侧转** —— zip 从 74MB 降到约 8MB，直接决定用户等多久。
4. **取景收敛全挂 → 让用户换照片**，但先把免费阶梯（0.90→0.75）试完；
   中途失败**不打扰用户**（自动重试静默），只在全挂时报
   「这张照片不适合，换一张正面坐姿、尾巴收拢的」。
   继续缩比换照片更糟：主体变小、与内置显示尺寸不一致。
