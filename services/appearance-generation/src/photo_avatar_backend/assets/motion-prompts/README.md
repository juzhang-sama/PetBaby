# 写实风提示词（motion-prompts）

> 机器用的正文在 `master.txt` / `loop-idle-combo.txt` / `loop-idle-combo.negative.txt`；
> **本文件是给人读的**，不会被发给模型。改提示词改 `.txt`，别改这里来「顺手调一下」。

## 为什么拆成两份

原先这套提示词是 `output/_通用母版提示词-2026-09-12.txt` 和
`output/_通用组合循环提示词-2026-09-12.txt` 两份**给人看的完整文档**：开头写「与建国版的区别」，
结尾写「保存位置」，真正的提示词夹在中间，由脚本按 `【主提示词】` / `-----` 切出来。

两个问题：

1. **`output/` 在 `.gitignore` 里** —— 服务拿不到这两份文件，链路一离开这台机器就断。
2. **注释和提示词混在一起** —— 改一句说明文字，就可能改到发给模型的内容（注释也花钱）。

现在：机器正文进版本库（本目录），人读的说明就是你正在看的这份。

正文**不是手抄的**：是用老脚本自己的切分逻辑从原文档抽出来的，抽完逐字节比对过
（母版 4 组 species×coat、组合循环含/不含负向，全部与老链路一致）。

## 与「建国版」的区别（这段是历史，别丢）

建国版把「银渐层」的毛色**写死在提示词里**；通用版一律以照片/首帧图为准：

- **母版**：只指定「物种 + 毛长档位」两个最外层约束，其余交给模型照照片还原。
- **组合循环**：身份/毛色**一律交给首帧图**，正文里只留与宠物无关的约束
  （动作时间轴、绿幕、固定镜头、首尾一致）。

所以组合循环提示词里**一个替换位都没有** —— 同一份适配任意猫/狗。
这是「通用化」能达到的上限：身份信息在图像里，不在文字里。

### `{{COAT_LEN}}` 谁来决定

它是一句**提示**，不是真源：提示词下一段本来就要求「毛长照照片一模一样」，
毛长的真正来源是照片。所以**判不出来就不提**是安全的。

三条路径：

| 路径 | 谁决定 | 渲染结果 |
|---|---|---|
| 服务（产品） | `frame_pipeline.analyze_photo_facts` 让 **gpt-4o 看照片**判 | 判得出 → `…this exact long-haired cat.`；判不出/分析失败 → `…this exact cat.` |
| 人工出宠 | `scripts/一键出宠.py --coat short\|long` | 显式那条 |
| 都不给 | `coat=None` | `…this exact cat.` |

gpt-4o 那一步**只能降级、不能失败**：它挂了一律退到「不提」，绝不带走后面 5.02 算力的视频。

判据（4 张真照片，真值取自 `docs/验证记录/L1真实照片验收记录-2026-09-11.md` 第 3/5 节）：

```bash
python scripts/poc_照片分析验收.py     # 真打 API，4 次 ≈ 0.01 算力
```

| 源图 | 真值 | gpt-4o |
|---|---|---|
| `果冻.jpg`（短毛猫） | cat / short | cat / short ✅ |
| `长毛猫.jpeg`（长毛猫） | cat / long | cat / long ✅ |
| `短毛犬.jpg`（比格） | dog / short | dog / short ✅ |
| `金毛.webp`（长毛犬） | dog / long | dog / long ✅ |

**4/4 全对**（2026-09-13）→ 没有「永远说 long」的偏置，所以这一档可以交给模型判。
改了 `_PHOTO_FACTS_PROMPT` 就重跑这张表。

负向词按老链路的原样拼接（不是新发明的写法）：

```

Avoid the following: <负向词>
```

## 生成参数（产品固定规格，写死在 `frame_pipeline.py`）

| 项 | 值 | 说明 |
|---|---|---|
| 模式 | 图生视频 / 首尾帧（`shouweizhen`） | 1 张图 = 首帧 |
| 画幅 | 1:1 | 必须。16:9 只有 496px，分辨率砍半 |
| 时长 | 12 秒 | 与内置资产一致（289 帧 / 24fps / 42ms） |
| 分辨率 | 480p | 标准档 |
| 版本 | 标准 | ⚠️ 计费按**输出 token**（官方特惠 43.41/百万 token），单条无法预估；Mini 档更便宜但画质不行 |
| 音频 | 关闭 | 平台默认 |

母版 `gpt-image-2` 固定 2048×2048 出图（平台限制），后续首帧步骤显式缩到 1024。

## 下游管线（视频回来后照此跑）

1. 抠像：`poc_抠像.py --method chroma --fps 24 --frame-duration-ms 42`（idle 用 autocrop 到最紧正方形）
2. 验收：`poc_验收.py`（四判据；**机械指标只排雷，肉眼判定才是权威**）
3. 打包：schema 7 运行时包 → zip

服务侧这三步在 `frames/pipeline.py::build_frame_sequence`，对应 step `packFrameSequence`。

## 验收

- **母版**：整体毛色与照片一致（亮度中位误差 ≤ ±15），花纹/斑点布局不变，眼睛颜色与原图一致。
- **首帧**：`tailSwingFit` 两个余量都要 ≥5%（`MIN_FRAMING_MARGIN`）—— 不达标**不许进视频**
  （长毛猫当初没看这行警告直接进视频，白花 4.67 算力）。
- **视频**：`skill petbaby-video-intake-diagnosis` + `petbaby-greenscreen-matting` 的四项判据。

## 一次性/交互动作的提示词（2026-09-14 搬进来了）

`action-skeleton.txt` + `actions/{yawn,lick,grab-release}.json`。原先在
`scripts/_提示词模板/`，现已搬到这里当**唯一真源**，两条路都从这里读：

| 谁 | 取哪部分 | 产出 |
|---|---|---|
| 服务 `frames/action_prompts.py` | 骨架的**【一】【二】两节** | **发给 Seedance 的**提示词 |
| 脚本 `scripts/poc_生成动作提示词.py` | 整份骨架 | 给老王看的**操作文档**（含取景约束、下游管线命令、复查清单） |

骨架是**给人看的五节文档**（【一】主提示词 /【二】负向词 /【三】取景约束 /
【四】生成参数 /【五】复查清单）。服务只切【一】【二】—— 剩下的都是人工步骤，
服务不需要。切分逻辑与 `scripts/poc_生成绿幕视频.py::section` **逐字一致**。

### 服务侧只有 4 个宠物字段

骨架里因猫而异的只有 `identity` / `coat` / `coatGuard` / `coatNegative` ——
原先写在 `output/宠物档案/<petId>.json`（**`output/` 被 gitignore，服务拿不到**，
而且只有 04/05/06 三份）。服务路径改由 `analyze_photo_facts`（gpt-4o 看首帧图）
自动判定。crop / 余量 / 锚点帧 / 路径只出现在人读的三节里。

### ⚠️ `lick` 的正文是**审核规避写法**，别「修正」成「舔」

`actionId` 叫 `lick`，但 `lick.json` 的正文写的是「**理毛 / 清理 / 口部动作**」，
**通篇没有「舔」「舌」「咬」**。这是有意的：内容审核对「舌/舔/咬 + 身体部位」的
组合直接拒（失败态只给一句中文 `error`、**没有英文 code**、`refunded=true`、
不可重试）。而**负向词里可以出现** `continuous licking` 之类（那是禁止项）。
改这份 json 前先读 `参考-资产生产与取景契约.md` 与审核那一节。
